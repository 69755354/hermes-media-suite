# 架构说明

## 一、部署拓扑

```
 ┌──────────────┐        ┌────────────────────────────┐        ┌──────────────────┐
 │ 飞书（群/私聊）│  ⇄    │ 控制面 server.py            │  ⇄    │ 客户机 agent      │
 │              │        │ 127.0.0.1:18977 + SQLite    │ 轮询   │ winport + Chrome │
 └──────────────┘        └────────────────────────────┘        └──────────────────┘
        ⇅                              ⇅
 ┌──────────────┐              ┌──────────────────┐
 │ 飞书机器人 bot │              │ 运维 CLI / 脚本   │
 └──────────────┘              └──────────────────┘
```

- 控制面只监听回环地址，外网不可直连；管理接口要求 admin bearer，入站接口要求 inbound token。
- 客户机主动轮询命令队列，不需要公网入口，也不开放入站端口。
- 机器人、控制面、客户机三者用 `command_id` 串起同一笔任务，重复投递只生效一次。

## 二、命令生命周期

```
queued → claimed → done / failed
```

- `claimed` 由控制面在一次事务内原子领取，同一命令不会发给两台机器。
- 终态写入后不接受覆盖；重试必须换新的 `command_id`。
- 客户机执行长任务时用分离进程，控制面按日志与回执判断结果，避免「连接断开被误判失败」。

## 三、发布状态机（客户端）

```
计划(plan)
  │  dry-run 校验：时间窗、素材指纹、账号、授权
  ▼
fill（上传 + 填表，不提交）
  │  证据：截图 / DOM / 请求记录
  ▼
approved_publish（校验签名回执）
  │  二次校验表单
  ▼
--allow-submit（显式开关）
  │
  ▼
结果判定
  ├─ 有平台作品号 / 页面成功证据 → CONSUMED
  ├─ 无证据 → UNKNOWN → 冻结通道，人工核实
  └─ 明确失败 → 回退并保留证据
```

### 幂等键

`账号 + 素材指纹 + 时间窗` 三元组。账本状态：

| 状态 | 含义 | 能否重发 |
|---|---|---|
| RESERVED | 已预留，尚未提交 | 仅在确认无在途时可人工回收 |
| SUBMIT_INTENT | 已点击提交 | 不能重发，只能人工核对平台结果 |
| CONSUMED | 已确认发布成功 | 不能重发（需显式复投凭据） |
| UNKNOWN | 结果不明 | 不能重发，先人工核实 |

### 冻结（hold）

任一通道出现验证码、风控、登录失效、网络异常、结果未知，就写入该通道的冻结记录。
冻结是「停止线」：新任务在入口被拒，必须人工核实后带原因解除，解除动作会留审计记录。

## 四、证据与完整性

- 每一步落截图 + HTML + 关键请求，保留期可配置（默认 14 天）。
- 启动时校验 `MANIFEST.json`：逐文件比对字节数与哈希，任何不一致直接拒绝执行。
- 修改客户端代码必须同步更新清单，否则下次启动即完整性失败。

## 五、数据边界

| 数据 | 位置 | 是否入库 |
|---|---|---|
| 客户注册、命令、回执 | 控制面 SQLite | 否（运行时生成） |
| 素材与成片 | 客户机本地目录 | 否 |
| 冻结记录、幂等账本 | 客户机 `run/` | 否 |
| 密钥与令牌 | 环境变量 / `.env` | 否（已排除） |

## 六、扩展点

- 新平台：在客户端 `winport/platforms` 侧扩展通道定义与发布驱动。
- 新客户：控制面注册客户 + 客户机导入授权，命令按 token 路由。
- 新阶段：`video-team` 的 `pipeline.json` 定义阶段与产出物，引擎按配置推进。
