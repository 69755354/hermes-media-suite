# 案例：记忆文件残留旧规则 → 节点4 出分镜表格（2026-08-07）

## 现象

小鹿跑红果漫剧剧情项目，节点0-4 完成，交付「古龙风剧情广告文案」——**表格是分镜脚本**。
刚修完 huoshan 节点4 规则（只出台词本、禁止镜号/时段/画面/景别），物理卡点、guard、SPEC 全对齐了，
小鹿还是出分镜表。表面看是「修复没生效」或「小鹿违纪」。

## 排查路径（对比 physical-gate-debugging 三步）

1. ✅ guard 四件套含 huoshan（新版）
2. ✅ 节点4 模板已去镜号列（新版）
3. ✅ customer huoshan md5 = 新版（410fabb...）
4. ❌ **三步全过仍出错 → 查第四层：记忆文件**
   - `grep -rn "出片前" ~/.hermes/profiles/customer/memories/` → 命中 `USER.md`:
     「出片前必须输出分镜脚本(storyboard)审核。跳过审核直接出片=违纪，用户必叫停」
   - 这条注入 system_prompt（`SELECT prompt FROM system_prompts` 验证：缓存含「分镜脚本」、不含「禁止写镜号」）

## 根因

**USER.md 记忆残留旧规则，跟新 huoshan 节点分工打架。**
小鹿遵守了记忆里的旧规则（出片前给分镜）——不是违纪，是「规则打架」时它选了更旧的。

## 修复

1. USER.md 条目改为新规则：
   「节点4 只出台词本(故事/对白)，禁止写镜号/时段/画面/景别——那是节点5分镜的活。
    分镜脚本由节点5输出，节点5完成并过审核才能出片。跳过审核直接出片=违纪，用户必叫停」
   （保留原意图的安全阀，只改分工）
2. 清缓存（`DELETE FROM system_prompts` + `DELETE FROM messages/sessions` + feishu 路由）
3. 重启 customer gateway → 飞书重连
4. 小鹿重跑节点4 → **纯台词本**（段落/说话人/台词/语气/情绪五列，零镜号）✅

## 连带发现：三版盲评流程可漏跑，但物理卡点兜底

- 小鹿节点4 重跑后只有 1 版定稿（`节点4_剧本定稿.md`），**没有 v1/v2/v3、没有评审报告**——三版盲评漏跑
- 但 review_gate node4_review 检查 `节点4_评审报告.md` 存在+≥60，进节点5 前必拦 → 物理卡点有效
- 补跑工具：`~/.hermes/scripts/node4_review_scorer.py`（四维盲评 Judge 打分，
  单文件模式 / `--multi` 三版盲评模式，输出格式兼容 review_gate.read_score）

## 经验

1. **三步排查全绿 ≠ 行为正常**——记忆文件是第四层，注入 system_prompt 优先级高
2. bot 出「旧行为」时先分清：乱来 vs 遵守另一条更老的规则（后者不是违纪）
3. 改记忆后必须清 system_prompts 缓存+删会话路由+重启，**记忆不在 skills 同步清单、不在哈希守卫监控里**，无自动兜底
4. 引用外部结论（教程/文档「已测通」）≠ 自己环境实测——剪映 11.1 是教程的，我们 Mac 是 10.8
