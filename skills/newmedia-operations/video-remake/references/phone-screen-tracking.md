# 手机屏贴图自动跟踪（YOLO/光流 v3 锚点帧方案）

2026-08-18 火龙漫剧复刻实测。动态镜头（人物举手机/站起）下手机屏位置变化，固定坐标 overlay 会漂，需要自动跟踪。

## 结论速览

| 版本 | 丢帧率 | 结果 |
|:--|:--|:--|
| v1 原版（YOLO 第一帧+光流） | 100% | 不可用：YOLO 第一帧框错位置（黑屏手机低置信被椅子抢框），动作段 LK 追不上 |
| v2 黑屏矩形检测 | 99% | 更糟：Seedance 手机屏**不是纯黑**（均值124，<35像素仅0.1%），阈值<35失效还误检左下角暗区 |
| v3 锚点帧+双向跟踪 | 0%（除故意不贴前段） | 可用：锚点帧完美框住手机屏，跟踪全绿，贴图完美贴合 |

## v3 核心三步

1. **锚点帧初始化**：不检测第一帧（手机又小又低位）。扫描 5-9s 找「手机屏最大最清晰的帧」——numpy 连通域找最大暗块（`gray<100`，区域限画面中上部 y300-800 x400-720），实测帧179≈7.5s。该帧黑屏检测 100% 框对。
2. **双向跟踪**：从锚点向后到结尾 + 向前到贴图起点。LK `maxLevel=4`（金字塔升到4级适配举手机大位移）、`MAX_DELTA=110`（放宽大位移容忍）。
3. **丢帧插值**：overlay 阶段丢帧用前后有效帧线性插值（`before*(1-t)+after*t`），不用 last_valid 旧位置硬撑（旧位置在动作段错位会穿帮）。

**业务先验**：贴图起点定在手机举起稳定后（3.5s 帧84），之前故意标 -1 不贴——原片 3s 前手机屏本来就是暗的，不贴不影响还原，避开动作过渡段（帧62-82）跟踪不稳。

## 关键坑

- **Seedance 手机屏不是纯黑**：黑屏检测 `threshold(gray, 35)` 失效。手机屏均值 124、<35 像素仅 0.1%；左下角暗区（阴影/桌子）反而满足阈值被误检（hull 3点面积3160）。
- **YOLO 手机检测在 Seedance 画面不可靠**：检出但框错（conf=0.65 框到椅子 x220-302 y754-818，实际手机屏 x522-620 y546-728）。仅作黑屏检测失败后的兜底。
- **cv2.VideoWriter 只写视频丢音频**：overlay 后必须 `ffmpeg -i noaudio.mp4 -i src.mp4 -c:v copy -c:a copy -map 0:v:0 -map 1:a:0?` 补音轨。
- **`is_valid_quad` 要求 `len(hull)==4` 太苛刻**：approxPolyDP 圆角手机屏常出 5-8 边形，直接判失败。放宽：面积够大 + hull 顶点 4-8 就接受。
- **2核4G 跑 YOLO CPU 推理**：单帧 100-200ms，20s@30fps 约 1-2 分钟，串行可接受。
- **⚠️ 从原片裁剪的动态界面素材（bfv）尾部会混入原片人物（2026-08-18 镜3 实测，血泪）**：用 `crop` 从原片裁手机屏区域做贴图视频时，**素材尾部会在原片人物切换点后混入人物画面**——火龙漫剧播放页素材原裁 3.5s（原片 32-35s），实测 **2.6s 处就切到黑衬衫男**（原片人物进画面），2.5s 处还是纯孙悟空。不逐秒验证尾部就整段贴 = 贴图播放到尾部穿帮（成片 30s/镜3 11s 反复出现「黑衬衫男」）。修法：抽帧逐秒查素材尾部（`ffmpeg -ss <t> -i bfv.mp4 -frames:v 1` + vision，尤其 0.1s 粒度查切换点）→ 裁掉含人物的尾部（本次 `-t 2.5` 重裁）→ 再验证最后 0.2s 仍干净。**贴图视频的 enable 窗口上界 = 素材实际干净长度，不是整数秒**（本次 enable between(t,9,11.5) 配 2.5s 素材 + `setpts=PTS+9/TB` 延迟到窗口起点，避免播完冻结在最后一帧）。判断标准：任何「从原片裁的动态素材」，先 vision 查尾部是否混入人物，混入就裁短，宁短勿穿帮。

## 贴图严丝合缝：屏幕质感三件套（2026-08-18 用户「他的那个手机贴图是做的严丝合缝的」后固化）

光流跟踪解决「贴对位置」，屏幕质感解决「看不出是贴的」。对照原片 8s 手机屏抽帧，原片贴图三要素：

1. **圆角过渡**：内容四角跟屏幕圆角匹配（`make_screen_mask(w, h, radius_ratio=0.08)`——圆角半径占屏宽 8%）
2. **顶部刘海留白**：内容不延伸到屏幕顶部（`notch_height_ratio=0.05` 顶部 5% 高度黑条，模拟灵动岛/听筒区）
3. **玻璃反光**：屏幕上部 20% 高度轻微提亮渐变（`glass[yy,:,:] *= 1.0+0.06*(1-yy/(h*0.2))`），模拟屏幕玻璃反射环境光

实现：cv2 画圆角矩形 mask（4 个 circle + 2 个 rectangle）→ GaussianBlur 羽化 2px → 透视变换贴图后 `bitwise_and` 合成。代码：`overlay_screen_look.py`（make_screen_mask + apply_screen_look + run_overlay，可并入 pipeline 的 run_overlay）。

**验证**：修复前 vision 判定「明显贴纸感/浮在表面」，修复后「almost indistinguishable from actual content displayed on the phone's screen」（圆角匹配+玻璃质感+移动跟踪三合一）。**移动镜头必须配光流跟踪**——手机动贴图不动 = 一眼穿帮，固定坐标 + 屏幕质感也救不回来。

## 验证流程

1. 先跑 `detect_black_screen_rect` + `is_valid_quad` 在锚点帧上，绿框画出来 vision 确认框住手机屏（本会话锚点帧179 通过）
2. 全片跑完抽帧（3.5/5/7.5/10s）vision 确认贴图贴合
3. 锚点帧验证通过才可信，vision 说「进去了」不可靠，要像素级确认
