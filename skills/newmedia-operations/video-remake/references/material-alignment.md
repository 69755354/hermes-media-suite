# 素材对齐方案 + 字幕样式核验（2026-08-18 火龙漫剧实战）

复刻任务素材到位后，用户要求「对齐参考视频」时的标准做法。触发：用户说「剩下的素材对齐一下参考视频」「素材放的位置/什么时候放图片/什么时候放视频」「logo 放手机屏哪里」「字幕的颜色大小位置字体」——这是 A_MATERIAL_ALIGNMENT 分析任务（智力活，派 codex 出方案，Hermes 只做抽帧证据+打包+质检）。

## 一、素材对齐方案流程

1. **抽原片关键帧做证据**（fps 抽 3s/10s/16s/19s/26s/34s/41s 等代表时点），vision 逐张确认：人物位置/手机位置/手机屏内容/页面叠加位置与占比/logo 位置/尾卡结构。
2. **整理素材全景清单**（三个来源分列）：
   - 用户提供（`assets/materials/`，优先用）：logo / 闪屏页 / 品牌页手机屏贴图
   - 原片提取无水印大图（`复刻素材_重做/`）：福利中心_无水印 / 播放页_无水印
   - 动态视频素材（`复刻素材_v2/视频/`，贴视频不贴图）：福利中心叠加 / 解锁弹窗 / 录屏 / 尾卡
3. **写任务书**（`tasks/material_alignment_task.md`）：背景+原片画面结构表（含证据时码）+可用素材清单（绝对路径）+要解决的问题（放的位置/图片vs视频时机/logo手机屏位置）+输出要求（按分镜组织：贴图内容/文件/位置/时机/类型/备注，标注原片证据）+执行方法（先读对照表/A_PROMPT_PACKAGE/素材位置记录）。
4. **派 codex**（走统一入口壳，禁裸调），产出 `artifacts/media_prep/A_MATERIAL_ALIGNMENT.md`。
5. **约束**：复刻=照抄原片，禁止新增素材/特效；用户提供的素材优先，原片静态图只在视频素材缺失时兜底；不生成新素材。

### 任务书标记格式坑（2026-08-18 实测 BLOCK）

`task_brief_gate.py` 的 `parse_markers` 只认**行首裸 `KEY=VALUE` 行**（无 `>` 无 markdown 前缀无缩进）。写成 `> 任务类型：TASK_TYPE=MATERIAL_ALIGNMENT` 或 `> TASK_TYPE=分析` 都解析不到 → BLOCK「缺少有效 TASK_TYPE」。正确写法（顶格独立行）：
```
TASK_TYPE=分析
DATA_SOURCE=原片 <视频路径> + 原片画面结构对照表 + 素材位置记录.md
```
素材对齐方案归「分析」类（不是自创的 MATERIAL_ALIGNMENT 类型，gate 只认 复刻/分镜/生图/出片/文案/分析 六类）；分析类强制标记含 DATA_SOURCE=，约束词「数据来源」。gate 返回 WARN（如 PRELOAD_NODES 未覆盖）时 mode=WARN 不阻断，可继续派活。

### codex 额度用尽 → DS 直调降级（2026-08-18 实测）

codex 报 `You've hit your usage limit`（额度用尽，错误自带恢复时间）时，素材对齐方案等分析任务降级走：
```bash
python3 /home/ubuntu/workflow/hermes_task_dispatch.py \
    --brief tasks/material_alignment_task.md --project huolong-guide \
    --target ds_native -- <任务书> <输出路径>
```
统一入口自动过 gate + 签发 TASK_GATE_TOKEN，ds_native_invoke.py 内置 token 硬校验（防裸调绕过）。**不要**为省事把 DS 接进 codex 壳跑——token 成本差 5-10 倍（codex 壳注入全套上下文，回几个字就烧 21 万 token），单步分析任务 DS 直调完胜（详见 codex-cli-ops「DS 接进 codex 壳」节）。

## 二、动态素材 vs 静态图清理规则

- 原片 App 界面是**动态素材**（贴视频不贴图）——用户原话「有些是视频素材，你要把整个视频素材给截下来，到时候你贴的时候要贴视频上去」。
- 用户确认：「你看一下原视频里哪些是动态素材，如果你已经有了动态素材，你就把那些静态的图片删掉就行了」——**已有动态视频覆盖的时段，对应静态界面截图直接删**（如界面_19s/23s/25s/27s/29s/31s/33s/35s 全删，因有福利中心叠加/解锁弹窗/录屏视频覆盖）；**无视频覆盖的静态图保留**（如 11s 提现页，原片手机屏不对镜头、无对应视频）。
- 删除前先 `search_files` 查引用（A_PROMPT_PACKAGE/素材位置记录），更新素材位置记录.md 留痕。

### ⚠️ 原片截的整段视频素材全部含原片人物，不能当贴图（2026-08-18 成片被打回血泪）

从原片按时段截的「片段_XX.mp4」（录屏 24-35.8s / 解锁弹窗 22-24s / 福利中心叠加 14-22s / App真实录屏 24.1-35.8）**全部是「原片人物+界面」的合成画面**（边缘露脸/人物持机），不是纯界面素材——整段 overlay 到复刻版人物上 = 原片人物穿帮（本次 5 镜合成全翻车，用户：「你把原视频的人都放进去了」）。「贴视频不贴图」指贴**干净的动态界面**，不是贴整段含人视频。**合成贴图前先 vision 验证每个素材文件是否含人物**（看边缘/持机人），含 → 换用户提供的干净素材（品牌页/logo/无水印静态图）或从原片抠页面区域，先问用户。用户拍板「镜2 用静态图福利中心_无水印.png」= 页面为画面主体时静态图可接受，动态弹窗缺失是取舍。

### ⚠️ 贴图位置/透明度照原片实测，不能全屏盖死（2026-08-18 用户「第二个人物完全没露过脸」血泪）

A_MATERIAL_ALIGNMENT 方案（DS 出）可能照抄任务书假设没核原片，**不能当免检**。合成前逐段抽原片帧核验素材真实摆放：火龙漫剧实测——① 3s/10s 手机屏亮，10s 屏内品牌 logo 占屏高约1/3（中上部）；② 15s 福利中心页**半透明叠加画面中间（宽约2/3、上部到近底部），人物露额头/脸颊/肩/手**——不是全屏盖死（本次 432x780 全屏盖死、小芸完全没露脸被打回）；③ 23s 弹窗屏占画面高约2/3、26s 剧库屏占约65%、34s 播放屏占高70%宽35%（手机屏放大展示、人物被遮挡是原片本身设计）。贴图坐标：vision 像素不可靠 + 手机是动态镜头（人物站起/举手机位置变），固定 overlay 坐标跟不上——按动作分段给坐标或用 numpy 暗区检测（`arr.mean(axis=2)<60` 找屏幕跨度），贴完抽帧发用户确认。

## 三、字幕样式核验（颜色/大小/位置/字体）

用户要求字幕对齐原片时，抽 13 个时点（2/4/7/10/13/16/19/22/26/30/34/38/41s）底部字幕区（crop 底部 45%）拼 2 行 grid → vision 逐格问样式（位置/颜色/字体粗细/背景条/占比/有无特殊帧）。

火龙漫剧实测结果（可直接复用）：
- 全片统一：**底部居中、纯白粗体、黑色半透明背景条、宽约画面75%、高约5%**
- 特殊帧：4s 品牌词「火龙漫剧」黄色高亮；30s 无底部字幕；41s 尾卡无台词字幕
- 合成烧录：Noto Sans CJK Bold / index=2 SC / 底部居中 / 白字 / 黑半透明背景条；品牌词黄色高亮；无字幕时段照原片不烧

核验记录落盘：`字幕样式核验记录.md`（项目根），任务书注明「字幕走合成阶段脚本，方案文档不需包含」。

**⚠️ 合成前检查旧 ASS 字幕文件是否繁体+错字（2026-08-18 实测）**：项目里遗留的 `字幕_逐字保留.ass` 可能是从 ASR 转写直接生成的——**繁体**（現在/劇/獎勵）且**错字**（「懸煥」应为「玄幻」、「雙烈流」应为「双列浏」、「數評」应为「竖屏」）。合成前必须重做简体 ASS：抽原片字幕区帧（crop 底部区）逐字核验画面字幕（简体）→ 重写 Dialogue 文本 → 落盘 `字幕_简体核验.ass`。样式：底部居中/白字粗体/黑半透明背景条（`&H8C000000`）/Noto Sans CJK SC/字号44/MarginV 160/宽约75%。合成脚本引用新简体 ASS，别拿旧繁体文件烧录。

## 四、交付节奏

- 素材逐张确认时：**一次只发一张**，等反馈再发下一张（「我说的是一次发一张」）；用户说「重新发」= 重发刚才那批；说「等我确定完再发下一张」= 严格等。
- 用户对单张素材：「删」= 立即删文件报剩余数量；「留着」= 保留；「修一下」= 修完发回来确认再定稿（备份 .bak 留到确认后删）。
- 用户要「发出来看看」已保留的素材时：**所有保留素材都要逐张发完**，不能只发待确认的跳过已留的（「保留的没给我看的发出来看看」）。

## 五、素材归属以用户最新指认为准（2026-08-18 火龙漫剧 logo 混淆教训）

**用户发图后，素材「是什么、干什么用」以用户明确指认为准，不凭文件名/之前落盘假设背书。** 实例：用户先发霓虹手势 logo（落盘为 `火龙漫剧_logo_用户提供.jpg`），后又发闪屏页说「这个才是我发的」——当时先误判「logo 是闪屏页里的卡通龙、霓虹手势作废」，实际用户重发霓虹手势图后确认：**小图（霓虹手势 512x512）= logo；长图（品牌页，顶部「火龙漫剧」文字+卡通龙）= 手机屏贴图；闪屏页（带状态栏）= 闪屏页素材**。处理：
1. 用户发新图时先 `vision_analyze` 看内容 + 与已落盘素材做内容哈希对比（`hashlib.md5(img.tobytes())`）判断是否重复
2. 用户说「这个才是我发的」= 之前落盘的归属假设可能错，**当场重新确认每张素材的用途**——但别急着下结论说「某张作废」，用户可能只是纠正归属、还要重发图确认；等用户把「哪个是 logo / 哪个贴手机屏 / 哪个是页面素材」说完整再定
3. 素材用途变更后同步更新「素材位置记录.md」+ 素材对齐方案，不等到合成阶段才发现贴错图
