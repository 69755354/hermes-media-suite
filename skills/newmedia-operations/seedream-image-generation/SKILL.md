## 提示词体系：五层标准结构

### 结构规则
权重从前到后逐级降低，每层功能独立无交叉。用户自定义描述插入层级3位置。

| 层级 | 名称 | 作用 | 权重 |
|:----|:-----|:-----|:----:|
| L1 | 主体基础层 | 锁定人物长相、年龄、五官、发型、基础气质 | 最高 |
| L2 | 肤质妆容层 | 单独管控皮肤质感，只写正向生理细节 | 高 |
| L3 | 体态情绪穿搭层 | 微表情、情绪、肢体、服装（用户描述插这里） | 中 |
| L4 | 镜头光影构图层 | 焦段光圈、景深、光源方向、明暗逻辑 | 低 |
| L5 | 场景氛围画质层 | 环境、色调、质感风格兜底约束 | 最低 |
| NEG | 负面提示词（独立模块） | 统一收纳所有禁止元素，正向文案不出现否定语句 | 独立 |

### 写作格式铁律（天行者2026-07-21定稿）
- **自然段落式**：用句号和分号组织逻辑，不要用逗号堆砌关键词
- **具体可执行**：只写AI能执行的描述，**不写抽象词**（❌邻家感/真实感/温柔/优美 → ✅校园非网红/腰臀比自然/肩颈线条舒展）
- **负向用「无」字句**：统一用「无XX」格式，例如「无俯拍，无仰拍，无斜拍」
- **正负向成套使用**：用户给的prompt如果包含正向+负向，**必须整套复制**，不能只取正向。图生图没有内置负向词。
- **唇色写法**：统一用「接近肤色的自然淡裸粉，仅带轻微血色，不偏玫红不偏荧光」。**禁止写「玫瑰粉」**——Seedream看到「玫瑰」就往亮粉色跑。用户明确纠正过。
- **完整存档**：wiki/concepts/xiaolu-final-prompt.md

### 自检校验（每次写/改prompt后必须做）
1. **层间无矛盾** — L1的唇色描述不应与L2的妆面描述冲突
2. **数据不自相矛盾** — 不要同时写8K和720p，不要同时写手机前置和单反浅景深
3. **层级3填充** — 用户描述只替换L3，不污染其他层
4. **格式检查** — 是否用了自然段落式（✅）还是逗号堆砌关键词（❌）

### 🔄 全身/半身切换协议

当用户从全身像改为半身像（说「脸太小了」），**三处必须同步修改**，只改一处会导致描述冲突：

```
LAYER1: 删除「身高约Xcm」——半身照不需要身高描述
LAYER3: 只保留上半身穿搭，删除下半身（裙子/鞋子）描述——半身照看不见
LAYER4: 「人物全身自然站立」→「胸部以上半身构图」
```

**不改全就会出bug：** 半身图还在写裙子/凉鞋，各层自相矛盾。用户明确纠正过这个问题。

## 两个已知模型坑点（文字拉不动，需策略性处理）

### 坑点1：Seedream 4.5 默认唇色偏亮粉
- **无论怎么写唇色描述**（写未涂口红、自然裸粉色、素唇），Seedream 4.5 仍会出亮粉色/玫粉色口红
- 这是模型训练数据偏好的硬伤，文字描述几乎拉不动
- **最佳方案**：把素唇照作为垫图，经 hermes_task_dispatch.py 提交图生图任务，垫图参数用 `image`（file-xxx），不需要公网URL；不直接调用 seedream_gen.sh
- **次选方案**：正向写「嘴唇呈现接近肤色的自然淡裸粉，仅带轻微血色，不偏玫红不偏荧光，阴影区域不偏紫、不发灰」，负向加「无唇色过艳」「无荧光唇色」

### 坑点2：全身像默认俯拍
- Seedream 4.5 默认视角：半身像→平视 ✅  全身像→俯拍 ❌
- 需要用**双向约束**同时拉：
  - **正向（权重最高层L1）**：写相机高度与人眼齐平、正面水平拍摄、镜头无俯角无仰角
  - **镜头层L4**：写严格正面平视机位，镜头中心与人物眼睛处于同一高度
  - **负向**：写无俯拍，无仰拍，无斜拍，无高机位拍摄，无低机位拍摄
- 写过弱、只在某一层出现 → 无效，Seedream 仍会出俯拍

### 坑点3：全身像容易裁脚/不完整入镜（2026-08-08 实测）
- **现象：** 图生图全身像第一版只到小腿，脚没入镜——Seedream 默认构图倾向「小腿以上」，写「全身自然站立」不够。
- **修复（实测有效，正向+负向双管齐下）：**
  - **正向**：写「完整全身照，从头顶到脚底完整入镜，脚部完整可见」「双脚着地完整入镜」「头部上方与脚底均留白」
  - **负向**：加「无裁剪，无截断，无只露半身，无只到小腿」
- **配套坑：** 参考图只有半身/头像时，AI 会脑补下半身——鞋子/袜子大概率乱编（实测出过「光脚」）。客户要求穿鞋 → 必须在正向显式写「黑色皮鞋」等具体鞋款，否则默认光脚/乱配。
- **验证：** 生成后必须 vision_analyze 自查「是否完整全身入镜（头顶到脚底）」，裁脚是常见第一版失败，别直接交付。

## 场景图生成（非人像：空间/城市/产品环境）

适用：PPT配图、门店环境图、城市天际线、室内空间——不需要锁人物的场景。

视频线场景图：垫图只传 1 张——复刻片垫参考片的场景帧，原创片垫本条的角色三视图。

要点：
- 模型：默认 Seedream 5.0（doubao-seedream-5-0-260128），全部场景统一用 5.0
- 尺寸：跟当次成片画幅一致——横版出 2560x1440（16:9），竖版出 1440x2560（9:16）
- 负向词必传，场景图版建议：无文字，无水印，无logo，无标牌文字，无人物面部特写，无卡通，无CG感，无过度锐化，无模糊，无畸变，无多余杂物
- 生成后必须 vision_analyze 自查：元素齐全度（对照描述逐项）、无文字/水印/畸形
- 合规价值：客户PPT里扒的图库图有版权风险（授权只覆盖原deck），AI生成原创图是替代正解——用户确认「方案2」后执行

### ⚠️ ARK API 限制（与豆包App的差异）

| 能力 | Seedream API（ARK） | 豆包App/即梦 |
|:----|:-------------------|:------------|
| reference_strength | ❌ 不支持 | ✅ 支持（推荐0.28-0.32） |
| cfg_scale | ❌ 不支持 | ✅ 支持（推荐7.5） |
| 面部相似度 | ❌ 不支持 | ✅ 支持 |
| 面部保护/创意增强 | ❌ 不支持 | ✅ 可关闭 |
| 采样步数控制 | ❌ 不支持 | ✅ 支持 |
| 构图标定能力 | ⚠️ 弱（需写进prompt最前端） | ✅ 强 |
| 锁人物特征能力 | ⚠️ 弱（图生图锁不住穿搭/发型/脸） | ✅ 强（内置面部保护） |

**结论：** 图生图/三视图/角色设定稿等需要锁人物特征的任务，也**一律经 `hermes_task_dispatch.py` 提交**；豆包App只在用户点名时才用。API 锁特征能力较弱，要靠 prompt 前置构图约束和素人垫图来补。

### 合法参数白名单
model, prompt, negative_prompt, image, size, n, watermark

### 尺寸规则
- 视频线场景图跟当次成片画幅走：用户说横版出 2560x1440（16:9），说竖版出 1440x2560（9:16）；用户没说画幅时，含双人段出横版 2560x1440，纯单人片出竖版 1440x2560（二轮裁定第 2 条）
- 非视频用途才默认 1440x2560（9:16 竖屏，满足最低 368.64 万像素）
- 横版推荐 2560x1440（16:9）
- **格式必须用 `WIDTHxHEIGHT`（乘号），不能用 `WIDTH:HEIGHT`（冒号）**。ARK API 只认乘号格式，冒号会返回 `InvalidParameter`。用户给 `1704:960` 时须转成 `2560x1440`。

## 写实人像真实感优化

### 核心逻辑
AI假不是因为细节不够，而是**太完美**。真实感靠光线方向、手机自拍质感、构图不完美来补，不靠在脸上堆瑕疵。

### 五维优化
| 维度 | 做法 | 关键词 |
|:----|:-----|:-------|
| 皮肤 | 只保留自然毛孔和肤质光泽，不加痘印/斑点/瑕疵 | subsurface scattering, visible pores, natural skin sheen |
| 光线 | 有方向、不均匀 | 45度侧光、窗边光、轮廓光、发丝光 |
| 构图 | 前景遮挡、不完美裁切 | 玻璃反光、树叶、窗框虚化 |
| 画质 | 两种画质二选一，不得混写：手机前置质感，或默认 prompt 的 85mm 定焦浅景深；默认小鹿 prompt 保持 85mm 时，不再加 iPhone前置 一类的词 | 选手机前置时：iPhone前置、原生相机、轻微抖动、噪点；选单反时：85mm定焦、浅景深、胶片颗粒 |
| 妆容 | 裸色 > 浓妆，皮肤干净自然 | 自然裸色唇、不磨皮 |

### 光线规则（多源交叉验证）
- ❌ soft lighting, diffused light → 越柔越假
- ✅ harsh side lighting, directional light, window light → 有方向的光=真实
- **最推荐：** 45度侧光 + 窗边自然光 + 轻微轮廓光

### 垫图选择规则
| 参考图类型 | 效果 |
|:----------|:-----|
| **素人生活自拍（无修）** | ⭐⭐⭐⭐⭐ 最佳 |
| 网红精修自拍 | ⭐ 最差 |
| 手机前置原相机 | ⭐⭐⭐⭐ |

## 已知坑点

### 图生图参考图锁定不足 + 禁止擅自换图
- Seedream 4.5 图生图 **无法可靠锁定**参考图的穿搭、发型、五官细节。即使 prompt 中明确指定了穿搭/发型/发色，输出仍可能跑偏（卷发变直发、深棕变黑色、吊带变其他款式）。
- 这不是prompt问题，是模型的训练数据偏好导致——图生图只能锁个大概（性别、人种、基本体态），精细特征靠垫图质量、prompt 前置约束或后期修图来补，仍经 hermes_task_dispatch.py 提交；豆包App/即梦只在用户点名时才用。

### 内容安全审核：常见触发场景及绕过

Seedream API 有输出内容安全审核，以下prompt类型容易触发拦截：

| 触发场景 | 典型敏感描述 | 解决方案 |
|:---------|:------------|:---------|
| 温泉/泳池/浴室 | 「水面齐胸」「身体泡在水中」「头发湿贴脸颊」 | 改成「坐在温泉池边，身穿上衣」「水汽氤氲」「脸颊微红」。如果加上「东亚女生」「非混血」等种族约束更容易触发审核 |
| 湿身/水汽类 | 「头发微湿」「水汽蒸腾」叠加人物场景 | 弱化「身体入水」描述，改为岸边/池边姿态 |
| 温泉/自拍 | 「身体泡在水中」「湿身」类描述 | 弱化入水描述后经 `hermes_task_dispatch.py` 提交；豆包App只在用户点名时用 |
| 5.0 Pro 比 4.5 审核更严 | 同样prompt在4.5能过，5.0可能被拦截 | 先改写敏感描述，再用 5.0 重试；不得自行切到 4.5 |

**处理流程：**
1. 收到 400 `OutputImageSensitiveContentDetected`
2. 删除所有涉及「身体泡在水中」「水面齐胸」「湿身」类描述
3. 改为人坐在岸边/池边/穿着衣服的姿态
4. 加「身穿XX上衣」明确衣着的描述
5. 重试

## AI真人视频三步法（图生视频人物稳定）

适用场景：图生视频默认只走快乐马 happyhorse-1.1-r2v（引用语法按快乐马规则，不等同 wan3.0）；Seedance 等其他通道仅用户明确点名时才用。保证人物形象稳定+情绪连贯

### Step 1：人物设定解析
将参考视频交给AI，提取人物的**年龄、脸型、发型、气质、穿着、镜头风格、光线环境、整体氛围**等完整设定，再用这些描述词生成一张高度真实的人物参考图。生成的人物参考图一律是年轻形象：参考视频里的人是 40 岁及以上（含 40 岁整）时，年龄改成年轻，不照抄。

### Step 2：情绪细节解析
让AI分析视频中人物的情绪变化，重点关注**微表情细节**：
- 眼神是否躲闪、眼眶是否泛红
- 眉头是否收紧、嘴唇是否微颤、呼吸是否急促
- 情绪的递进逻辑（如从委屈到克制、压抑到爆发）

**禁止**仅用「开心、难过、愤怒」这类笼统词汇。

### Step 3：视频生成
用 Step 1 的人物参考图，加上在快乐马 r2v 提示词里复写的人物外貌（脸型、发型、穿着等），再加 Step 2 的情绪细节描述词，生成视频

## 设计标准：reference_image 应包含的信息

### 面部核心（优先锁定，防止跨帧换脸）
- 五官基础：眉眼形状、眼距、瞳孔颜色、鼻型鼻翼宽度、唇形唇厚、颧骨高低、下颌线条、脸型
- 皮肤细节：原生肤色、毛孔粗细、鼻翼油光、皮肤明暗肌理（不加痘印、斑点、瑕疵）
- 妆容特征：淡/浓妆、口红色调、眼影深浅、眉形、遮瑕程度
- 毛发特征：发色、刘海样式、发丝粗细、碎发位置、发际线

### 形体穿搭
- 头肩比、脸部镜头占比
- 上衣款式、颜色、面料纹理、褶皱走向
- 肩颈线条、手部特征（若入镜）

### 画面拍摄特征
- 镜头属性：手机前置/单反、焦段、构图
- 光影类型：光源方向、高光分布、阴影深浅
- 画质属性：噪点、抖动、磨皮程度、景深

### 关键规则
1. 参考图清晰度越高，提取特征越完整
2. prompt强制约束保留/去除特征（如保留毛孔）
3. ARK 接口不支持 style_strength/reference_strength，贴合度靠垫图质量和 prompt 约束
4. 视频模型只能静态复刻，动态为AI生成，动作越多五官越易漂移
