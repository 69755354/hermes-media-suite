# 火龙素材台账三处同步

火龙（漫剧成片）换版本时，一个版本散落在三个地方，**只改一处 = 客户仍看到旧片**。

| 位置 | 是什么 | 谁看 |
|:--|:--|:--|
| 在线编号表 | 飞书 sheet `Xbj8seoXKhPI6ctZGFbcQtIXnv7` / sheet_id `1f6a33`（编号/名称/类型/模板/时长/交付日期/成片链接） | 素材群对外 |
| 多维表 | 飞书 base `D2nbbBWF4aJdBEs11j5cujA2njc` / table `tblDfvUIpa9oDWTB`，字段含 编号/成片编号/时长/交付日期/**视频(附件)**/标题/话题 | 后台投手上传用；打包交付的源 |
| 本地 | `huolong-asset-index/index.json`、`素材编号台账.md`、`火龙漫剧·素材编号表_*.xlsx` | 本机内部 |

## 编号纪律（2026-10-02 用户纠正，硬规矩）

**已交付的编号不得覆盖。** 表里已经有「免费-11」= 那就是已交付的资产；重新出片/换版只能**递增新编号**（往表内最大号后面接），绝不能把现成编号的附件换掉。

- 错法：把新片上传后直接 PUT 到 `免费-11` 那行 → 旧资产记录被毁（已回滚过一次，旧 file_token 从改前 JSON 恢复）。
- 对法：旧行原封不动；新片建新记录，`编号`/`成片编号` 取下一个可用号（免费-14 这类），附件名**必须同编号**（`免费-14.mp4`，不能沿用旧编号名）。
- 改任何行前先把改前的整条记录存 JSON（含附件 file_token/size），否则回滚不了。

## 打包范围＝只打 10 月（2026-10-06 用户定）

用户原话：「9月份的我已经都全部上传上去了，你后面打包，你就打包10月份的」。

- **默认只打包多维表里「交付日期」为 `10-xx` 的行**；`09-xx` 一律跳过（9 月批次用户自己已全部上传），除非显式 `--month 9`。
- 工具：`check_delivery.py --packable [--month 10]` 列范围；`--files <目录|zip>` 里 9 月片子会标「9月·不打包」。
- 范围与查重是两码事：范围管「打哪些月」，查重管「这条是不是已经发过了」；两个都要过。

## 交付查重（打包/上传前必跑，2026-10-06 用户要求）

用户原话：「你要记得哪些是已经上传过的，你打包下载的时候不要重复了」。

**工具**：`/home/ubuntu/workflow/projects/huolong-guide/ledger/check_delivery.py`
- `--refresh` 从多维表重建 `已交付清单.csv`（82 行快照：编号/名称/类型/时长/交付日期/视频文件名/大小/file_token/record_id）
- `--files <目录或zip>` 判每个视频：已交付(✗ 别重复发) / 未交付(✓ 可发) / 不在表里(?)。**有重复时 exit 1**
- `--undelivered` 列未标交付日期的行

**判重键**：编号（前缀 `免费|激励|种草|APP种草-\d+`）+ 文件大小 + 附件名里的 sha 前缀（表内附件名为 `<编号>_<sha前8>.mp4`）。三样都对上才算同一条。

**规矩**：
1. 打包前先 `--refresh` 再 `--files`，`有重复` 就必须剔除后才打包；不靠脑子记。
2. 交付完成后**必写**多维表「交付日期」（那是查重的唯一依据）；只发链接、不写表 = 下次会重发。
3. 表里编号为空的行（当时 2 行：`recvw6BREqtKYo`/`recvwBCexg6FZe`）查重会漏，遇到先补编号。

## 入库即填全字段（2026-10-06 用户定，硬规矩）

用户原话：「**下次入库的时候直接填写好**」。往多维表写新成品记录时，**一次性写全**：编号 / 成片编号 / 名称 / 类型 / **模板/脚本** / 时长 / 交付日期 / 标题 / 作品描述 / 打包状态，不留空列、不事后补。

> ⚠️ **字段名以实查为准（2026-10-07 实查，表里只有 11 个字段）**：成片编号 / 编号 / 名称 / 类型 / **模板/脚本**（不是「模板脚本」）/ 时长 / 交付日期 / 作品描述 / 标题 / 打包状态（单选）/ 重复标注（单选）。
> **没有「话题」「作品简介」两列**——旧写法写进去直接报 `1254045 FieldNameNotFound`；字段名写错同样报这个错。拿不准先拉 `<base>/tables/<tbl>/fields?page_size=100` 对一遍再写。
> 写表开关：`be.allow_write = True`（默认关，不开报 `WriteDisabled: 真写未开启（默认关）`）；整表条数 `len(be.list_records())`。
> 无成片时的登记：先建条、时长填定稿值（如 `26.8s`），成片出来再用实测值校正；**编号照旧接表内最大号，不覆盖已有行**。

固定字段（逐字照抄，不得改写）：
- 话题 = `#火龙漫剧 #漫剧 #腾讯漫剧`
- 作品简介 = `火龙漫剧｜漫剧App。海量漫剧内容免费开放观看，竖屏沉浸式刷剧、双列流快速选剧，覆盖玄幻、科幻、都市、悬疑等热门题材，打开就能看。`

可变字段口径：
- 标题：一句话口语化钩子，7–15 字（既有样例中位 11 字），同批不重复。
- 作品描述：一句话，写这条讲了什么/给什么利益，与素材内容相符。
- **必须来自素材本身**：先读该条的文案源文件；没有文案源就转写素材（`/home/ubuntu/workflow/tools/asr/asr_run.py <音视频> [前缀]`，可先 `ffmpeg -t 12` 截前 12 秒省时间，脚本自带重活锁串行）。**禁止按表内名称/角色名推断**——2026-10-06 那批 30 条照名字推的判为不合格，全部重写。
- 合规：不得出现收益承诺（日赚/躺赚/百分百/保证提现）、不得出现「无广告」同义表述；绝对化按口径 ㊸ 放开。
- 补写既有空行时同样按此口径，不区分批次。

## 作品描述字段口径（2026-10-12 用户定）
**字段名就叫「作品描述」**（多维表列名，写错写「描述」直接报 `BitableError code=1254045 FieldNameNotFound`；表内 12 列：成片编号/编号/名称/类型/模板·脚本/时长/交付日期/**作品描述**/标题/打包状态/重复标注/视频）。

多维表「作品描述」列 = **利益点（≤30 字）+ 三个话题标签**，一条文本：
`<利益点≤30字> #火龙漫剧 #漫剧 #腾讯漫剧`
- 标签一字不差、顺序不变；利益点必须卡在 30 字以内（含标点）。
- 利益点按类型取值：免费＝不花钱/不用会员/不绑卡看全集；激励＝看剧攒火龙币能提现；种草＝剧好看/资源多/不卡点。
- 写作人＝codex（先读内容红线库 + huolong-manju-standard），写完按 `record_id` 回写表；旧记录描述同样补齐，不要只写新批。

## 写入表的技术细节（2026-10-12 实测）
- 写字段用 **PUT**：`PUT /bitable/v1/apps/{app}/tables/{tbl}/records/{record_id}`，body `{"fields": {...}}`（`feishu_client.FeishuBackend._call("PUT", url, body)`）。
- `GET /fields` 偶发返回空 items（限流/重试即好）——写之前先解析出真实 field_name 再写，别硬写猜的名字。
- 批量写 100+ 条：每条 `time.sleep(0.2)`，失败重试 1 次（sleep 1s）即稳（122 条实测 0 失败）。
- 多维表**接口不支持改行顺序**（PATCH `/views/{id}` 带 sort_info 返回 property=null 不生效）→ 「按类型成块」靠写入时按类型顺序写 + 表内「按类型分组」视图；别对用户承诺能重排行。

## 编号与分包规则（2026-10-12 实测确立）
- 新片入库编号＝**按类型各自续号**（免费/激励/种草），同类内连续、写入顺序连续，不覆盖老号、不跳号（读 `huolong-guide/ledger/已交付清单.csv` 取各类型最大值）。
- **两账号分包＝编号奇偶**：**偶数编号 → 账号A，奇数编号 → 账号B**（10-08 批实测：免费-14/16/18/20/22/24→A，15/17/19/21/23→B；激励-08/10/12/14/16→A，07/09/11/13/15/17→B）。别用「按位置轮转」——两种算法结果会错位一条。
- 包内文件用**编号命名**（`免费-45.mp4`）＋一份 `清单.txt`；投递走 `/home/ubuntu/public/` 下 Caddy：`http://<公网IP>/<dir>/<ascii-name>.zip`（中文名另存一份 ASCII 拷贝，源包保留中文名）。
- 字段要一次写全（编号/成片编号/名称/类型/模板-脚本/时长/交付日期/标题/作品描述/打包状态/视频附件）；`FeishuBackend` **没有 update 方法**，改已有记录用 `b._call("PUT", f"{b._base()}/records/{rid}", {"fields":{...}})`。
- 标题/作品描述必须**逐条从该条台词生成**（禁套模板）。

## 打包交付命名


包内的成片文件名**只用编号**：`免费-12.mp4` / `激励-06.mp4` / `种草-07.mp4`——不要加「免费-12 大排档双料密集版.mp4」这种后缀（用户：「记得文件改成免费多少这种名字」）。

**例外（2026-10-06）**：用户要求「视频名字要对应表格里的」时，用 `编号_名称`（按多维表逐行取值），例如 `免费-25_免费-21文案×免费-21角色.mp4`；多维表附件自身命名是 `<编号>_<sha前8>.mp4`，别混用。表格类附件可以用中文名（如 `素材编号表.xlsx`）。

## 客户说「把群里那个 Excel 表发我」= 指哪张

**默认是多维表**（base `D2nbbBWF4aJdBEs11j5cujA2njc` / table `tblDfvUIpa9oDWTB`），不是在线编号表。用户原话：「群里那个 EXCEL 表 免费0几的那个表」→ 导出时要带全字段（编号/名称/类型/模板脚本/时长/交付日期/标题/作品描述/话题/**成片附件名**），记录拉全（`page_size=100` + 翻页，别只取第一页）。发过在线编号表导出被纠正过一次：两张表结构不同，编号表只有 7 列、没有标题/描述/附件，用户一眼就看出来不对。

## 客户说「表里的 XX 还是之前的」怎么查

1. 先读在线编号表对应行（`GET /sheets/v2/spreadsheets/<tok>/values/<sid>!A1:H40`）——确认对外表到底改没改。
2. 再读多维表（`POST /bitable/v1/apps/<app>/tables/<tbl>/records/search`），比 **时长 + 附件 size** 与交付件是否一致。**附件挂在多维表上，最常漏的就是这里**。
3. 附件 size 对不上 = 就是旧片；别只看时长（时长可能已被人工改过）。

## 改多维表附件（换片）

```python
# 1) 上传（file_token 只有上传后才知道，无法复用云盘 token）
POST /open-apis/drive/v1/medias/upload_all
  multipart: file_name / parent_type=bitable_file / parent_node=<app_token> / size / file
# 2) 写记录
PUT /open-apis/bitable/v1/apps/<app>/tables/<tbl>/records/<rec_id>
  {"fields": {"视频": [{"file_token": FT}], "时长": "30.8s", "交付日期": "09-24"}}
# 3) 回读 + 下载附件算 md5 与本地交付件比对
```

**坑：文本字段写纯字符串，不要写读回格式。** 读回来是 `[{"text":"30.8s","type":"text"}]`，把这个数组原样 PUT 回去报 `1254060 TextFieldConvFail`，整条更新失败（附件也不会生效）。关联/附件字段才用数组。
