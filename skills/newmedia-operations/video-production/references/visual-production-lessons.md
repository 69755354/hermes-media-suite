# 视频生产视觉教训库（2026-08-10 茗希项目沉淀）

## When to Use

- 探店/剧情视频生产：节点7-10（素材/生图/提示词/出片）涉及实景图、体验镜、服务过程时
- 用户提到「实景图有几张」「体验镜没有服务过程」「按摩放松应该在实景图里」
- Seedance 出片出现「下载失败 0B」或视频拿不到

> 本 skill 承载 huoshan / codex-bridge / seedream-image-generation 等 user-owned skill 无法自动 patch 时的可复用视觉生产教训。相关 skill 被 `hermes curator adopt` 后应合并进 huoshan。

## 铁律（用户三次纠正，每一条都是踩过的坑）

### 1. 客户实景照一张不漏
- 客户给了几张实景照就优化几张，一张不漏
- 茗希案例：客户给 3 张（理疗室/服务区/美容室），只优化 2 张被纠正「实景图有3张吧」
- 做法：建档时先盘点 `assets/` 全部实景文件数，优化清单与客户素材一一对应

### 2. 体验镜必须有服务过程
- 探店视频核心是「带你进去看别人怎么服务」——体验镜不能是空洞的「坐着放松」
- 茗希案例：镜5 初版「甜妹坐着放松」被用户纠正「你没有服务过程谁知道你干嘛的」
- 正确：甜妹俯卧+理疗师手部肩颈按摩，服务过程可见

### 3. 按摩/服务场景必须垫实景参考图
- 服务场景的背景必须是**真实门店环境**（客户到店能对上），不是 AI 编的环境
- 茗希案例：初版垫角色参考图生成 AI 背景，被纠正「你按摩放松应该在实景图里面吧」
- 正确：垫「高端实景升级图」做背景 + 角色参考图锁脸 = 双参考图生成

### 4. 实景高端化升级原则
- 保留场景结构 100%（布局/物件/位置不变），只升级光影/质感/氛围
- 升级点：暖色自然光层次、地板光泽、织物精致度、电影级摄影感
- 客户到店要对得上——这是探店真实性的底线

### 5. 服务过程合规边界
- 只拍保健按摩过程（手部推揉），不出现针/艾灸/仪器等医疗器材
- 字幕无疗效词、无绝对化承诺
- 理疗师不露脸只露手（AI 生成手部动作比人脸简单、不易崩）

### 6. Seedance 出片下载走 relay
- Seedance 视频 TOS URL 新加坡机直连不通
- download_file 必须走 8899 relay GET（execute_api.py 已修：`http://127.0.0.1:8899/upload?url=<编码>`）
- 症状：出片 0/6「下载失败 0B」——提交成功但下载断

## 流程要点（节点7-10 相关）

- 节点7 素材清单：实景（全部）+ 角色参考图 + AI 出镜图，逐镜映射
- 节点8 生图：镜图垫角色参考图锁脸；服务镜双参考图（实景+角色）
- 节点10 提示词：参考图映射用实际文件绝对路径；专属负面列每镜特定崩法
- 出片：2 并发经 relay，先小规模验证下载通道再全量

## STATE.json 自拦（2026-08-10 茗希两次踩坑）

codex 执行 AGENTS.md 会主动检查项目 STATE.json——上游节点没标 DONE 时，即使评审门已过，codex 也自拦 `BLOCKED: 节点X候选门已通过，但 STATE.json 未将 NODE_Y 标记为 DONE`。这不是 bug 是物理卡点在工作。修复：`python3 /home/ubuntu/.hermes/scripts/update_state.py write <项目目录> NODE_XX PASS` 补签已完成节点，再重跑 codex。顺序：评审门 ALLOWED 之后才补签，别提前签。

## 后期合成（字幕/BGM）要点

- **字幕渲染用 drawtext 不用 ASS**：ASS 被 sed 改坏会静默失效（ffmpeg 不报错但字幕不渲染）；ASS MarginV 定位不可靠（Alignment=5 时 320→480 几乎不移动）。drawtext 精确可控：`y=h-190`（720x1280 下约 90% 高度），`enable='between(t,起,止)'`
- **字幕位置必须抽帧验证，不能凭感觉**（用户「你自己👀」纠正）：改完位置用 `ffmpeg -ss <秒> -t 1 -vf "fps=1,scale=540:960" 抽帧` + vision_analyze 问「字幕在画面高度百分比/是否贴底/是否出屏」，得到客观数值再交付。常见误判：视觉模型可能把「白字黑描边」读成「黑字白描边」，抽帧时机要对准字幕显示段（如 8.5s 抽镜2 中间）
- **ASS sed 修改有静默失效风险**：sed 改 `\N` 换行/字体行可能把 ASS 改坏，ffmpeg 不报错但字幕消失——遇到「改了参数字幕反而没了」先重写干净 ASS 或换 drawtext
- **字幕用户偏好**：距底约 10%（不要贴死底边，y=h-100 被嫌太低；也不要中间挡脸）；每行 ≤12-14 字防出屏；**核心卖点必上字幕**（价格/赠品/店名/地址——漏了 299元 被纠正）；价格/店名/地址用浅粉色 `0xE87FB8`
- **BGM 兜底**：无免版权音乐库时用 python wave 合成木吉他琶音（C-G-Am-F 进行+拨弦衰减包络），混音音量 0.35 不压人声，淡入淡出 2s
- 详细命令见 `video-production` skill（user-owned，如需修改请 `hermes curator adopt`）

## 运营边界（2026-08-10 用户两次纠正，与视觉无关但同属客户项目执行）

- **不评估客户产品是否盈利**：客户可能故意亏钱做引流（如 299 元礼包当获客成本），那是客户的经营策略，不是内容团队该纠正的。产品结构照客户原始定义走。
- **不分析客户推广方案本身**：客户给了什么产品/方案，就围绕它做内容运营——内容怎么带流量、合规怎么过关、转化路径怎么通、素材怎么做。不做盈利重构、不劝涨价、不评产品合不合理。
- 边界 = 内容运营角度，不是经营咨询角度。

## 抖音生活服务 AIGC 合规硬规定（2026-08-10 DELIVERY_PACKAGE 终检发现，发布级风险）

探店/团购带货视频在**抖音生活服务**语境下，以下行为按平台规范不得发布（参考：抖音用户服务协议 / 抖音AI内容标识公告 / 抖音生活服务AIGC创作规范）：

1. **AI 生成/过度美化门店环境**：丽人、洗浴按摩类团购营销不得用 AI 生成或过度美化的环境替代真实场景。→ 门店环境镜必须用客户原始实拍，只做常规裁切/亮度/色彩校正，不改变空间/设施/陈设。
2. **AI 虚构服务过程**：团购带货视频的商品、场景、服务过程与效果不得由 AI 虚构。→ 服务过程镜要真实服务实拍；无法补拍则删除该镜改用真实用品准备或空镜。
3. **AI 甜妹等虚拟讲解人**：可以作为虚拟讲解人，但拟真背景不能被理解为真实门店场景（用中性背景），发布页主动声明 AI 内容。
4. **AIGC 标识**：AI 生成/合成内容必须主动添加显著标识。
5. **BGM 版权**：商用发布音乐权属需留证；无法留证时改用抖音可商用音乐。

**终检门槛**：四维终审加权 ≥68 才放行；DY01 茗希案例 61.7 分因上述问题 FAIL。产品名不统一、双 CTA、容貌焦虑/身体结果暗示也是常见终检扣分项。

**用户放行决策模式（2026-08-10）**：终检 FAIL 时先报风险，用户可能选择「先放行」（DY01/DY07，风险客户自担）或「后面的改」（DY02-06/DY08 严格按修订要求：真实素材/合规名/单CTA/BGM留证/AI声明）。放行决定必须写进产物文件（放行记录段）+ workflow_state.json 风险标注，不静默放行。

**放行≠不改的逐项决策（2026-08-10 用户「1 2 7」定案）**：终检 P0 问题按编号逐项让用户拍板，不是整片放行/整片改。茗希案例：用户说「1 2 7」= AI 相关 3 项（美化环境/虚构服务/甜妹拟真）放行不改（AI 代运营定位，接受平台审核风险），其余 4 项（产品名/双CTA/容貌焦虑文案/BGM版权）必须改。逐项决策写进产物文件表格，标注「放行不改」或「要改」。

**字幕改了口播没改的决策（2026-08-10）**：只重烧字幕不改口播=字幕合规但音频还是旧文案。用户选「就这版交付」（发布时以字幕为准）。改口播需重新出片配音（花 Seedance 费用），先问用户要不要，不要就标注「口播保留旧文案，以字幕为准」交付。

**文案设计逻辑（DY01 用户问「这么写的原因是」）**：首句反直觉钩子（「先不讲效果」→规避疗效承诺+制造好奇）→地域点名筛人（「双峰姐妹」）→场景共情不放大焦虑（「累想放松」替代「脸色蜡黄」）→信任定位（「先看环境听流程」）→合规改名（九类日常养护权益）→自我合理化（「对自己好比买衣服值」）→单一CTA（点定位→预约）。每步都服务北极星路径。

## 北极星指标按客户类型动态定（2026-08-10 用户纠正）

「有效到店」只是实体店客户的北极星，不是通用的。按客户类型定：
- 实体店/本地生活 → 每周可归因有效到店（或核销/预约）
- 自媒体/达人 → 可商业化精准粉/私域沉淀（非泛粉）
- 知识付费 → 付费学员转化
- 带货电商 → GMV/复购率
- B端品牌 → 有效询盘线索

写打法策略（GROWTH_STRATEGY）前必须先判定客户类型→变现方式→北极星，禁止一刀切。
