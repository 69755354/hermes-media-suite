# 口播发音含糊的根因与生成纪律（2026-08-06 血泪教训）

> 参数状态：故障案例。生产裁决为实际试读拆段、口播单段不超过10秒；下文其他秒数和字数只用于复盘。

## 事件
星广-红果漫剧小鹿口播（Seedance 2.0 Mini）：30s 口播生成后 whisper 转写发现
2 处发音含糊（「多样故事持续上新」「画质清晰无卡顿」）。用户指出「以前生成的视频
也没出现口播说话含糊啊」——排查后确认**不是模型能力退化，是本次参数违背已知纪律**。

## 根因（两个叠加错误）
1. **15s 长段塞 55 字**：Seedance 2.0 Mini 单镜上限 15s，但 skill 原有底线是
   **4-12s/镜**（每镜台词少、发音从容）。15s/55 字 = 3.7字/秒，语速本来就赶。
2. **提示词写了「语速略快，吐槽感」**：火上浇油——Seedance 理解成快点念，直接糊。

## 正确纪律（生成侧）
- **分段 4-12s/镜**，每镜台词 ≤36 字
- 提示词写「**语速适中、吐字清晰、咬字准确、每句断句清楚**」
- **禁止**写「语速略快 / 快点念 / 语速快」
- 30s 口播成本参考：2×15s ≈ 15元（Mini ¥0.5/s）；3×10s 更稳但略贵
- 生成后必须 whisper 转写对比文案：
  - ≤2 处含糊 → 剪辑盖住（卖点卡穿插，见主 SKILL.md）
  - >3 处大面积糊 → 直接判定生成失败，改参数重跑

## 用户信号识别
用户说「以前生成的视频没这问题」= 强信号：**检查是否违背已知纪律**（分段/提示词参数），
而不是甩锅给"模型能力上限"。之前成功案例用的是短段 + 语速适中提示词。
