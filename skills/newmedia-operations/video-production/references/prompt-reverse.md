# 拆视频 — 短视频分析+提示词反推

## 核心纪律

**🚨 「只提取不编造」是最高铁律。**

- ✅ 基于实际数据源（视频帧截图/豆包Vision视觉分析/页面HTML/文案）反推
- ❌ 禁止仅凭标题、标签、常识拼凑「提示词」然后谎称是反推的
- 拿不到实际画面 → 诚实告知

## 🚨 「分析视频内容」语义澄清（2026-07-10 用户纠正）

当用户说 **"分析视频内容"** 时，优先理解为 **画面视觉内容（视频帧里有什么）**，不是结构元数据（标题/标签/作者/章节）。

| 用户说的 | 正确理解 | 错误理解 |
|:---------|:---------|:---------|
| 分析视频内容 | 画面主体/场景/光影/运镜/风格/角色外貌/表情动作 | 标题/标签/发布时间/作者/点赞数 |
| 分析这个视频 | 同上 | 同上 |

**执行顺序：**
1. ✅ 先确认能否获取视频帧（截图/下载/视频流捕获）
2. ✅ 能获取 → 提取关键帧 → 走Vision分析 → 输出7要素
3. ❌ 不能获取（未登录/验证码/模型无视觉能力）→ **诚实告知无法分析画面内容**，不是退而求其次给结构分析
4. ❌ **禁止**在拿不到画面时，仅凭标题/标签/章节描述拼凑「画面分析」冒充内容分析

**当前模型无视觉能力时的标准回复：**
> "我的模型不支持看图分析。你描述一下画面内容给我，或者换个有视觉能力的模型来看。"

## ✅ 能拆的 / ❌ 不能拆的

| 维度 | 怎么拆 | 依赖 |
|:----|:------|:----|
| **脚本结构** | 钩子类型、3秒留人、痛点段、信任段、CTA收尾 — 有文案就能拆 | 文案/字幕就行 |
| **标题/描述/标签** | 关键词密度、情绪词、行动指令 | 页面HTML就够 |
| **画面构图/光影/色调** | 豆包Vision看图分析 | 截图/视频帧 → 调ARK端点 |
| **画面提示词反推** | 按7要素输出提示词 | 需实际截图或视频帧 |
| **文案话术库** | 同城引流钩子句式+CTA句式提炼 | 批量搜爆款文案 |
| **——** | **——** | **——** |
| **原版prompt** | ❌ 看不到创作者的实际prompt | 无法获取 |
| **负面提示词** | ❌ 只能猜「常见通用负面词」 | 无法获取原版 |
| **参考图** | ❌ 图生视频的原参考图看不到 | 无法获取 |
| **Omni时间戳** | ❌ 台词口型同步的时间戳分段看不到 | 无法获取 |

## 画面提示词反推（7要素输出格式）

有截图/视频帧时才执行，否则直接告知「无画面数据」。

```
①【主体】
性别/年龄/外貌/穿搭/体型（基于实际画面描述，不虚构）
数量：几人
位置关系：画面中心/偏左/前景/后景

②【动作】
动态描述：
幅度：大/中/小
速度：快/中/慢

③【场景】
环境：室内/室外、具体空间
时间设定：白天/夜晚/黄昏
氛围：专业/温馨/冷淡/热闹

④【光影】
光源类型：自然光/顶灯/侧窗光/补光灯
光源方向：正面光/侧光/逆光/顶光
强度：明亮/柔和/昏暗

⑤【运镜】
镜头类型：固定/推/拉/摇/移/跟/俯拍/仰拍
画面稳定性：稳定/手持微晃
景别：特写/近景/中景/全景/远景

⑥【风格】
视觉风格：写实/电影感/纪实/清新/复古/高对比
色调：暖调/冷调/中性/高饱和/低饱和
质感：胶片颗粒/磨皮平滑/原画自然

⑦【画质】
分辨率推断：高清/标清/模糊
帧率推断：顺滑/正常/卡顿
特效/滤镜：如有说明
```

【完整提示词】按「主体+动作+场景+光影+运镜+风格+画质」语序组装

⚠️ 声明：本提示词是基于画面【反推】的结果，并非原视频创作者使用的实际提示词。

## 执行流程

### ① 判断数据源
- 有截图/视频帧 → ffmpeg取关键帧 → 调豆包Vision分析 → 输出7要素提示词+声明
- 只有文案/字幕 → 做文案结构拆解，标「置信度：低」
- 只有标题 → 诚实告知无法反推

### ② 获取视频源文件

**场景A：抖音网页版播放页 — 通过CDP获取视频源地址**

当页面上有 `<video>` 标签时，用 browser_console 提取 `currentSrc`：
```javascript
// 在browser_console的expression参数中执行
document.querySelector('video') ? document.querySelector('video').currentSrc : 'no video'
```
拿到URL后用curl下载：
```bash
curl -sL -o /tmp/yuan_video.mp4 "$VIDEO_URL"
```

**场景B：用户已发文件或已有本地文件** — 直接使用。

### ③ 帧提取（视频才有这一步）

**采样密度由视频时长决定：**

| 视频时长 | 建议fps | 总帧数 | 用途 |
|:--------|:-------|:------|:-----|
| ≤10秒（短视频） | fps=2~30 | 20~315帧 | 精细分析动作节奏（张闭嘴/表情切换timing） |
| 10-30秒 | fps=1~2 | 15~60帧 | 覆盖动作变化即可 |
| 30-60秒 | fps=1/2~1 | 15~30帧 | 看场景/运镜变化 |
| >60秒 | fps=1/6 | ~10帧 | 看整体结构 |

**短卡点视频（如#跟着猫咪一起摇头晃脑类）必须高密度采样** — 这类视频的精髓是0.3-0.5秒的表情切换卡BGM，低采样会漏掉关键变化。

```bash
# 高密度采样（短卡点视频：fps=30，逐帧分析）
mkdir -p /tmp/yuan_315
ffmpeg -y -i input.mp4 -vf "fps=30" -q:v 2 /tmp/yuan_315/frame_%05d.jpg

# 中密度采样（一般视频：fps=2）
mkdir -p /tmp/yuan_frames_hd
ffmpeg -y -i input.mp4 -vf "fps=2" -q:v 2 /tmp/yuan_frames_hd/frame_%02d.jpg

# 低密度采样（长视频：fps=1/6）
ffmpeg -i input.mp4 -vf "fps=1/6" -frames:v 10 -q:v 2 /tmp/frames/frame_%02d.jpg
```

**⚠️ 铁律：抽帧密度不够 = 分析不准。** 用户纠错过一次「你只有11帧」因为用了fps=1抽10秒视频。短卡点视频抽帧不要太稀疏。

### ④ 豆包Vision逐帧分析

**单批分析（≤5帧，token友好）：**
```bash
# 把截图base64后传ARK看图端点分析
IMG_B64=$(base64 -w0 /tmp/frames/frame_01.jpg)
curl -s -X POST "https://ark.cn-beijing.volces.com/api/v3/chat/completions" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seed-2-0-mini-260215",
    "messages": [
      {
        "role": "user",
        "content": [
          {"type": "text", "text": "分析这些视频帧，按以下维度逐帧分析：1)画面主体 2)动作 3)场景 4)光影 5)运镜 6)风格色调 7)画质"},
          {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,'$IMG_B64'"}}
        ]
      }
    ],
    "max_tokens": 500
  }'
```

**批量分析（15帧/批，适合高密度抽帧逐帧分析动作节奏）：**
```python
BATCH_SIZE = 15  # 每批15帧，token约2.2万，在32K上下文内
for batch_start in range(1, TOTAL_FRAMES + 1, BATCH_SIZE):
    batch_end = min(batch_start + BATCH_SIZE - 1, TOTAL_FRAMES)
    frames_info = {}
    for i in range(batch_start, batch_end + 1):
        with open(f"{FRAME_DIR}/frame_{i:05d}.jpg", "rb") as f:
            frames_info[i] = base64.b64encode(f.read()).decode()
    
    payload = {
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": f"逐帧输出：帧[编号]: 嘴[张/闭], 眼[睁/闭], 头[位置], 表情[描述]"},
        ] + [{"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}} for b64 in frames_info.values()]}
    }
```

**分析prompt的关键（短卡点视频专用）：**
- 必须问清楚 **嘴张/闭、眼睁/闭、头位置** 三个核心维度
- 不加额外解释要求，用固定格式输出方便后续归纳
- 单帧分析约1700 tokens（含图片），15帧约2.2万 tokens

**实测token参考：**
| 帧数 | prompt_tokens | total_tokens | 耗时 |
|:----|:-------------|:-------------|:----|
| 1帧 | 1353 | 1694 | ~3秒 |
| 15帧 | ~18000 | ~22000 | ~8秒 |
| 315帧全分21批 | ~28万 | ~37万 | ~2-3分钟 |

## 🚨 关键区别：Seedance vs 人脸关键点驱动工具

**这个区别决定了视频能做成什么样，必须在反推分析时就心里有数。**

| | Seedance 2.0 Mini | 人脸驱动工具（即梦特效模板/FOMM/Wav2Lip） |
|:--|:-----------------|:---------------------------------------|
| 原理 | 文生视频，逐帧猜画面 | 检测人脸关键点→按时间轴驱动变形 |
| 表情精度 | 写「张嘴惊喜」可能生成，但timing随缘 | 精确到帧控制张闭嘴/眨眼/摆头 |
| 动作频率 | 写「快速摇头」可能不动可能慢摇 | 预制动画曲线，固定频率 |
| 表情切换速度 | 0.3-0.5秒切表情→模型跟不上 | 帧级切换，0.033秒一帧都能控 |
| 多画面同步 | 单次只生成一个画面 | 可同时驱动主画面+画中画 |
| 适合什么 | 探店口播、叙事、场景展示 | 卡点特效、模板化表情变装、对嘴型 |

**反推后的方案决策：**
- 如果分析发现原视频是**真人实拍+猫咪贴纸**（不是AI生成），并且依赖**精确到0.3秒的表情切换卡BGM** → ✅ 建议用即梦/人脸驱动工具，不是Seedance硬怼
- 如果原视频是**AI生成**或**不要求精确timing** → Seedance就够
- **不要用Seedance硬做它不擅长的事** — 写prompt说「0.3秒切换表情」「头部快速小幅度摆动」等于让它碰运气

## 🚨 节奏分析方法论（短卡点视频专用）

**#跟着猫咪一起摇头晃脑 类视频的逐帧分析流程：**

1. **下载原视频** → CDP拿video src → curl下载
2. **高密度抽帧** → fps=30，10秒视频=315帧
3. **分批Vision分析** → 每批15帧，问三个核心维度：嘴张/闭、眼睁/闭、头位置
4. **归纳节奏规律** → 找出表情切换的节拍模式，比如：
   ```
   闭眼微笑(0.5s) ↔ 张嘴惊喜(0.5s) ↔ 闭眼微笑(0.5s) ↔ 张口大笑(1s) ↔ 闭眼嘟嘴(1.5s)
   ```
5. **判断工具选型** → 根据精度需求决定用Seedance还是人脸驱动工具

**⚠️ 常见错误：**
- ❌ 凭想象写「摇头晃脑」——实际是张闭嘴+轻微头动，不是真摇
- ❌ 以为AI生成——实际上抖音标的「疑似AI生成」可能只是贴纸+滤镜
- ❌ 低密度抽帧分析短卡点视频——漏掉0.3-0.5秒的表情切换关键帧

### ④ 输出
按7要素填完 + 组装完整提示词 + 声明
