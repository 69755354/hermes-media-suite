# 抖音真号实测（2026-10-17，广州 gz-customer-01，账号「天行者」）

目的：验证「驱动真实 Chrome 走完创作者中心发布」是否可行，为 Windows 客户端发布驱动定契约。

## 结论
可行。15 秒测试片完成 上传→填标题→发布→后台出现作品，真实作品 ID `7697584059211402536`，随后已删除。

## 登录链路（客户首次安装必踩）
1. 扫码登录：CDP 接管的 Chromium 里二维码常被判无效，手机「相册」扫登录码会被拒（安全策略），**不要押扫码**。
2. 短信登录：手机号 + 短信验证码可用。按钮点击必须真的落到元素上。
3. **新设备首次登录会弹「身份验证」**：手机刷脸 / 原设备扫码，二选一，必须账号本人完成，自动化无法绕过。→ 产品首次安装必须保留「人工完成一次身份验证」这一步，之后 profile 复用。

## 会挡住自动化的浏览器/页面弹层（实测逐个踩过）
- **Chrome 原生 `Open xdg-open?` 协议弹窗**：页面一加载就弹，`page.screenshot()` 看不到（只截页面），但会把所有点击/输入吃掉 → 表现为「点了没反应、JS 正常」。必须在 OS 层（XTEST/xdotool）点掉，或启动参数禁用外部协议弹窗。
- **「发文助手」新手引导浮层**：盖住短信验证弹窗，`get_by_text('获取验证码').click()` 报 retrying/超时 → 先点「完成」关引导。
- **视频预览说明弹层**：需点「我知道了」。

## 发布流程真实契约
- 上传页：`/creator-micro/content/upload`，唯一 `input[type=file]`，`set_input_files()` 可用；上传后自动跳到 `/content/post/video`。
- 标题：`input[placeholder*="作品标题"]`（`fill()` 可用）。
- 描述：contenteditable div（无 textarea）。
- 封面：`智能推荐封面` 可留空，**不选封面也能发**；发文助手会提示横/竖封面缺失（只是提示）。
- 自主声明：未选也会弹「请选择自主声明」，但实测未阻塞发布。
- **点发布后二次本人验证**：弹「为确保是本人操作」，需短信验证码（手机号脱敏显示）。「获取验证码」是 `<p>`，坐标点击可用，成功后按钮变倒计时。
- 发布成功判定：跳 `/content/manage`，列表出现该作品（审核中）。
- **作品 ID 取法**：列表点「编辑作品」→ URL 的 `mid=` 参数即作品 ID（HTML 里搜不到 19 位数字）。
- 删除：列表「删除作品」→ 弹「确定要移除此作品吗」→ 点「确定」→ 列表变「没有更多作品」。

## 对发布驱动的硬要求
1. 必须处理浏览器原生弹窗（OS 级）与页面引导浮层，否则一切点击静默失效。
2. 必须支持发布时的短信二次验证（人工介入点），不能假装全自动。
3. 成功判定只认 `mid=` 作品 ID，不认 toast。
4. 首次安装=人工登录+身份验证；后续 profile 复用。
