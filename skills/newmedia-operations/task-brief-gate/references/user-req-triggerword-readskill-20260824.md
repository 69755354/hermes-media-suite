# USER_REQ 原话引文含触发词 → 补 READ_SKILL 过闸（2026-08-24 实测）

## 场景

派 claude 分析「reverse-video-prompt 蒸馏能力与现有工作流融合」时，传话书 USER_REQ 直传用户原话：

```
闭环：抽帧+豆包反推 → 出片 → 对比诊断 → 迭代 prompt → 沉淀规则
```

**「出片」是用户原话里的闭环环节词，不是本任务意图**。但 kb_gate 正则不看语境，照拦：

```
SKILL_CONTRACT:WARN L1: TASK_TYPE=分析 与出片意图不匹配（应为 出片）
BLOCKED: 出片任务缺少 seedance-2-0-mini-workflow skill 加载标记
```

## 解法

传话书补一行 `READ_SKILL=seedance-2-0-mini-workflow` 即过闸，**用户原话一字不改**。

## 与既有教训的关系（不冲突）

此前教训「不要为了过卡点给非出片任务硬加 seedance 标记」针对的是**假读**（根本不读 skill 只为过闸）。

本条是**真读**：融合分析任务必须读 seedance-2-0-mini-workflow——分析闭环涉及出片环节，要评估与现有出片规则（单镜时长/负面词/首尾帧）的关系。标记 + 任务书方法区写「第零步 read_file 该 skill」成对出现即合法。

判定标准不变：标记对应「真的会读」= 合法；对应「根本不读只为过卡点」= 假读违纪。

## 教训

USER_REQ 直传用户原话时，原话里可能含触发词（用户说「出片/视频生成」是常态）。发现 BLOCK 后：
1. 先看是不是 USER_REQ 引文命中（不是任务书正文讨论出片链路）
2. 是 → 补 READ_SKILL，不改写用户原话
3. 不是 → 按既有误伤词分类处理（正文讨论/目录列举/标识符原文/否定语境）
