承接 `gz-full-fix-round1-4-verification-patterns.md`。本轮模式：**代码全 PASS 后，问题全在部署说明/文档层**——且文档层错误有停产量级后果。

## round6 验收结论（codex 修文档后）

**P0-H/P1-J/P2-K/P2-L 全 PASS**（映射表补行、六份基线、§3.6 门禁、白名单两步硬顺序、回滚首条、基线来源标注、§3.5 第一条实机 md5 门禁、is_checked 差异披露、净改善对照）。代码 8 文件 MD5 与 round5 逐个相同。

**3 个新问题（全是文档层）：**
- **P1-M（停产量级）**：文档写「当前复扫只得 1 项，容器已收缩」——验收把脚本原文照跑（晚于文档落盘时间）得 `WEAK_COUNT=17`，17 个 flag 的 mtime **和 ctime** 全部早于文档落盘、无一被删改——「收缩」没发生。**同错换位迁移**：round5 修了「17 vs 1」清单，round6 把「只剩 1 项」写进「当前状态」栏继续错。危险链：执行者采信「只剩 1 项」→ 重 mark 一个就判 WEAK_COUNT=0 达标 → 按部署第 10 步切 BLOCK → **另外 16 个项目即时停产**。
- **P2-N**：强标记路径写错（`cli_novel_001/qingfuren` 不存在，真实 `projects/qingfuren`）——判断对，抄了验收速查表的排版缩写。
- **P2-O**：第 6 步「本批不摘 HERMES_GATE_SOFT」（选择对）+ 第 7 步跑三个探针——但 `_HARD_ENTRIES=set()` + `SOFT_PASS=1` → soft=True 对 execute/video_talk 都成立 → `_verdict()` 恒返回 None，从响应侧无法区分闸是否触发。解法：reason 原样留在 `SOFT_PASS … reason=` 审计里，文档补一句观测通道即可。

## 可复用的修法/断言

1. **映射表机械断言**：staging 下每个 `*.py/*.sh/*.yaml` 必须在部署说明映射表出现一次、条数相等，否则停止——这是唯一能物理终结「静默不部署」的写法。
2. **文档事实声明验收 = 原文照跑**：文档自带脚本一字不改跑一遍，输出贴进验收结论；事实断言（数量/路径/MD5/清单）全部复算。
3. **修事实错误后全文档 grep 同型断言**：数量词/路径/清单逐处核对——修一处不够，同错会换位置继续存在。
4. **基线来源必须标注**：快照复制 vs 实时 scp 证明力不同；「部署前实机 md5sum 必须等于基线值，不等停止重取」作为第一道门禁可物理关闭基线过期问题。
5. **部署顺序写成显式硬步骤**：先建 root 白名单（root:root 0644、规范化绝对路径）→ 再部署读它的代码；顺序不能颠倒（白名单缺失时 fail-closed 走 FULL 是安全的）。
6. **止损**：循环超过 4-5 轮主动给用户 A/B/C 选项，不默默继续。

## 执行器分工实录

- round6 纯文档轮 → 任务书硬约束「只改文档，8 个代码文件 MD5 必须与 round5 完全一致」——codex 遵守，验收逐个 md5sum 确认。
- codex 容器缺 Claude 凭据 → 如实声明「无法自证 claude PASS」，不冒充验收（claude 独立验收是必经环节）。
- docker permission denied（网关进程早于 docker 组启动，组快照未刷新）→ `sg docker -c` 包裹重跑即可，不换通道、不改配置。
