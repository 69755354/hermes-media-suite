# 精确裁剪到内容边界（crop-to-boundary）

> 2026-08-18 火龙漫剧素材处理实测。用于：裁剪界面截图时「把上面的边修到对齐画面」「顶部修到靠白框」「对齐白色的边框」这类需求。

## 核心坑

- **用户说「对齐白框/修到白边」= 裁到白色内容的第一行/第一列，不是裁掉明显黑边就完事。** 会话实录：第一轮只裁了顶部 15px（亮度阈值误判），用户回「顶部要修到靠白框啊」——实际深色残留到 row 35，row 36 才是白色内容起点。
- **vision_analyze 的像素描述只能定位「大概」**（说顶部黑边约 15px，实测 row 0-35 全暗），精确边界必须用像素扫描确认。

## 可靠流程

1. **先备份**：`cp <文件> <文件>.bak`（改完用户确认定稿后再删备份）。
2. **亮度扫描找白色起点**（顶部黑边/深色残留）：
```python
from PIL import Image
import numpy as np
img = Image.open('x.png')
arr = np.array(img.convert('RGB'))
h, w, _ = arr.shape
row_means = arr.mean(axis=(1,2))
# 白色内容行 ≈ mean > 240；深色残留行 ≈ mean < 50
# 找第一个 mean > 240 的行 = 白色内容起点
```
3. **饱和度扫描找渐变标题栏起点**（顶部是人物/头发，下面是渐变 UI 栏时，亮度可能都不高，饱和度跳变更可靠）：
```python
def saturation(row):
    sat_sum = 0
    for px in row[::4]:
        r,g,b = [x/255 for x in px]
        mx, mn = max(r,g,b), min(r,g,b)
        sat_sum += (mx-mn)
    return sat_sum / len(row[::4])
# 渐变 UI 栏饱和度 0.5+，头发/暗背景 0.1-0.2，找跳变行
```
4. **右侧白边扫描**（列方向同理）：
```python
col_means = arr.mean(axis=(0,2))  # 注意轴是 (0,2)，不是 (0,1)！
# 找最后一个 mean < 240 的列 = 内容右边界；白边列 mean 243+
```
5. **裁剪**：`img.crop((left, top, right, bottom))`，裁完**验证**：打印前 5 行亮度应 ≈240+（白色起步）。
6. **发回给用户确认**（一次一张），用户说「可以了」才算定稿。

## 验证要点

- 裁完打印新图前几行/列的亮度，确认从白色/内容开始，不是从残留开始。
- 发 MEDIA 给用户看效果，等「可以了/定稿」再删备份、进行下一张。

## 坑记录

- 列方向均值轴写错会 IndexError（`arr.mean(axis=(0,1))` 得到 3 通道值，不是每列）——用 `axis=(0,2)`。
- 亮度阈值扫描对「深色 UI 背景 + 深色残留」不敏感（都可能 <40），此时用饱和度或 vision 局部 region 确认。
- 用户说「删」就删（含未确认过的），说「留」就留；不要自作主张批量删。
