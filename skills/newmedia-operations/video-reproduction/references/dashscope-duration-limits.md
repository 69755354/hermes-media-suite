# DashScope (快乐马/wan3.0) 时长限制与复刻对齐（2026-08-27 实测翻车）

## 触发事件

复刻火龙漫剧通用口播原片（40秒，分镜7+7+8+9+9=40s）。快乐马每段设了`--duration 10`，5×10=50秒拼出来比原片多10秒。用户批"我靠，什么叫复刻？"——复刻的时长必须照原片，不能自己设。

## API 时长档位限制

DashScope `dashscope_video.py` 的 `--duration` 参数直接传给阿里API的`parameters.duration`字段，是整数类型。**happyhorse-1.1-r2v 只支持5和10两个档位**（不支持7/8/9等自定义值）。

脚本代码无choices校验（不像resolution有`choices=["480P","720P","1080P"]`），传7不会在脚本层报错，但API侧会拒绝或不保证效果。

## 两种生产模式

### 模式A：逐段音视频捆绑（适用于纯数字人口播视频）

原片是纯数字人从头说到尾（没有画面切换），每段生成10秒音视频捆绑体，拼接时按原片段时长裁剪。

#### 情况1：原片段时长≤5秒 → 直接生成5秒

#### 情况2：原片段时长在5-10秒之间（如7s/8s/9s）

1. **生成时设`--duration 10`**（取大于等于原片段时长的档位）
2. **拼接时用ffmpeg `trim` 裁剪到原片段精确时长**：
   ```bash
   [0:v]...trim=duration=7,setpts=PTS-STARTPTS[v0];
   [0:a]atrim=duration=7,asetpts=PTS-STARTPTS[a0];
   ```
3. **前提：台词必须在裁剪点前讲完**——用whisper转写验证每段台词结束时间<目标裁剪时长

#### 情况3：台词占满10秒，目标时长<10秒

这就是本次翻车的根因：原片台词版字数比通用版多，每段台词都讲到了~10秒，无法在7/7/8/9/9秒内裁剪——切了就断台词。

**判定方法**：生成后ASR转写，检查`speech_end < target_trim_duration`。
- `speech_end > target_trim` → 台词讲不完，不能裁剪 → 要么换短台词版（如通用版），要么接受实际时长
- `speech_end < target_trim` → 可以安全裁剪

### 模式B：混剪模式（适用于AI视频+录屏交替的视频，2026-08-27 用户定案）

**这是本次翻车后用户揭示的正确生产模式。** 原片（火龙通用口播40s）不是5段纯数字人口播——它是AI数字人视频 + App录屏混剪，口播音频是一条整条轨。

#### 原片实际结构（拆解报告D节）

| 时段 | 画面 | 口播 |
|:---:|:---|:---|
| 0-9.8s | 数字人口播 | 有些人我真是无语了…太折磨人了吧 |
| 9.8-15.2s | **剧情片段** | 人家火龙漫剧…直接看到大结局 |
| 15.2-16.5s | 数字人 | 没有任何限制 |
| 16.5-31.9s | **App界面**（分类/榜单/播放） | 题材丰富…快进快退一点都不影响 |
| 31.9-36.7s | 数字人收束 | 追剧体验…知道去哪看漫剧了吧 |
| 36.7-39.8s | 片尾导粉 | （无口播） |

数字人只出现在约16秒（0-9.8 + 15.2-16.5 + 31.9-36.7），其余15秒是剧情和App界面。口播音频从头到尾连续不断。

#### 正确生产流程

1. **整条口播台词 → TTS生成一条完整音频**（40秒，外部工具如edge-tts/Qwen-TTS）
2. **AI视频只做数字人口播画面段**（按原片时间轴，数字人出现时段才生成）
3. **ffmpeg混剪**：AI画面段 + App录屏段 + 一条连续TTS音频
   - 数字人段：放AI视频画面，音频用TTS轨
   - App录屏段：放录屏画面，音频继续用TTS轨（音频不停）
   - 剧情片段段：放剧情画面，音频继续用TTS轨

#### 为什么不能逐段生成音视频捆绑体

- 快乐马每段生成10秒=画面+音频捆绑，5段拼起来50秒，比原片多10秒
- 段间音频不连续（每段独立生成，语气/语速/音色可能漂移）
- 丢了画面交替结构（原片是人物-界面-人物-界面交替，不是5段站桩）
- 台词占满10秒时无法裁剪到目标时长

#### 用户原话

> 「他就是先把整个音频用其他工具生成了，然后在那个画面的时候，他放那个APP素材的时候，他的音频是跟着一起在放的」
> 「你不要就被规则限定死了，你是要去参考原视频的。原视频它可能一段才12秒，那我们肯定也要做到12秒」
> 「实际上他那个视频就是ai视频和录屏视频混剪的」

## 火龙两种模板的时长差异

| 模板 | 台词字数 | 每段语速 | 每段实际时长 | 拼接总长 |
|:---|:---:|:---:|:---:|:---:|
| 网赚版原片台词 | ~37-46字/段 | ~5.1字/秒 | ~10秒 | ~50秒 |
| 通用版台词(分镜表) | ~20-30字/段 | ~5.1字/秒 | ~7-9秒 | 40秒 |

**根因**：通用版台词是codex仿写的缩短版（"追漫剧最烦的，就是刚到关键处，又被广告打断"≈20字/7秒），原片台词版字数更多（"有些人我真是无语了，放着白嫖的漫剧你不看，非要守着那些看广告才能解锁一集的漫剧"≈37字/10秒）。

## 铁律

1. **复刻时长=原片时长**，不能因为API只支持5/10就全部设10秒。先查原片每段多长，再决定生成参数。
2. **生成前先算台词字数÷原片语速**，预估每段实际需要时长。字数多→需要10秒，字数少→生成10秒后裁剪。
3. **拼接时按原片分镜表的目标时长裁剪**（`trim=duration=X`），不是按生成时长直接拼。
4. **台词讲不完时不能硬裁**——ASR验证台词结束时间>目标裁剪时长=该段不能裁，要么接受更长总时长，要么换更短的台词版本。
5. **拼接后总时长偏差>1秒要查原因**——大概率是某段没裁剪或台词字数与原片不匹配。
6. **🔴 先判断原片是纯口播还是混剪**——纯口播用模式A逐段生成；混剪（数字人+录屏交替）用模式B整条音频+画面交替。判断方法：拆片时看原片画面是否在数字人和其他画面之间切换，如果切换了就是混剪，不能逐段生成音视频捆绑体。

## ffmpeg拼接模板（模式A：逐段裁剪拼接）

```bash
# 5段各生成10秒，按7/7/8/9/9裁剪拼接=40秒
ffmpeg -y \
  -i hh_01.mp4 -i hh_02.mp4 -i hh_03.mp4 -i hh_04.mp4 -i hh_05.mp4 \
  -filter_complex "
    [0:v]scale=1080:1920...,trim=duration=7,setpts=PTS-STARTPTS[v0];
    [1:v]scale=1080:1920...,trim=duration=7,setpts=PTS-STARTPTS[v1];
    [2:v]scale=1080:1920...,trim=duration=8,setpts=PTS-STARTPTS[v2];
    [3:v]scale=1080:1920...,trim=duration=9,setpts=PTS-STARTPTS[v3];
    [4:v]scale=1080:1920...,trim=duration=9,setpts=PTS-STARTPTS[v4];
    [0:a]atrim=duration=7,asetpts=PTS-STARTPTS[a0];
    [1:a]atrim=duration=7,asetpts=PTS-STARTPTS[a1];
    [2:a]atrim=duration=8,asetpts=PTS-STARTPTS[a2];
    [3:a]atrim=duration=9,asetpts=PTS-STARTPTS[a3];
    [4:a]atrim=duration=9,asetpts=PTS-STARTPTS[a4];
    [v0][a0][v1][a1][v2][a2][v3][a3][v4][a4]concat=n=5:v=1:a=1[v][a]
  " \
  -map "[v]" -map "[a]" -t 40 output.mp4
```

前提：每段台词在目标裁剪时长内讲完。ASR验证`speech_end < trim_duration`。
