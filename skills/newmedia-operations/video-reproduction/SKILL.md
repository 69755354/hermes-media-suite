# 视频复刻/仿拍类任务

老板/客户发一条视频链接（抖音/小红书等）说「复刻这条」「仿拍」时的完整方法论。本 skill 管「复刻这类任务怎么做对」，底层出片/剪辑/绕检流程见 `huoshan` / `video-production`（用户自有，按需加载）。

## When to Use

- 「帮我复刻这条视频」「仿拍这条」+ 链接
- 「文案对白不变，人物场景往 XX 人群靠近」类需求
- 复刻 App 推广广告/剧情/口播素材

## 🔴 最高铁律：复刻=所有复刻（2026-08-27 老板定案，一句话）

**复刻=台词、结构、节奏、大字、画面时间轴、画中画时段全部照抄原片，只换人物和场景。原片台词一字不改（含白嫖/没有任何限制/全都有/一点都不影响等客户指定卖点词）。自作主张改台词=违规。语速对齐原片（原片5.1字/秒），底片偏慢要提。**

> ⚠️ **2026-09-21 新规例外（优矩口径，压倒前后一切旧表述）**：含无广告类利益点／躺赚白嫖／吊打竞品／绝对免费／「直接提现/立马到账」的句子**必须删改，不许照抄**；照抄=拒审=白花钱。收益类只用 4 条固定话术。


用户原话：「复刻就是所有的复刻，除了人物、场景不复刻以外」「记住这条规则」。

实操要求：
1. **台词逐字扒原片**（whisper转写→繁简转换→逐字对照），禁止自写"通用口播"替代原片台词
2. **语速对齐**：底片生成后转写验证字数÷时长，与原片语速偏差>15%要重跑
3. **参考图必须先确认**：生成前向用户确认用哪张参考图，不能凭记忆选——用错参考图=人物全错=白烧钱（0827实测：用了灰蓝上衣低马尾的旧参考图，用户说"人物用错了"，要的是米白V领齐肩黑短发那张）
4. **客户指定卖点词不改（2026-09-21 收窄）**：非违禁的卖点词不改；但**无广告类／躺赚白嫖／吊打竞品／绝对免费／直接提现属新规禁项，必须删改**

> ⚠️ **2026-09-21 新规例外（优矩口径，压倒前后一切旧表述）**：含无广告类利益点／躺赚白嫖／吊打竞品／绝对免费／「直接提现/立马到账」的句子**必须删改，不许照抄**；照抄=拒审=白花钱。收益类只用 4 条固定话术。


## 核心铁律（2026-08-17 火龙复刻纠偏，老板连续纠正 3 次）

**「人物场景往 XX 人群靠近」≠ 视频角色改成那类人，而是指目标受众。**

例：老板说「复刻这条火龙漫剧广告，人物场景往中年下沉市场靠近（女性 35+、三线以下）」——**35+ 下沉女性是目标用户（视频要打动谁），不是把视频主角改成 35 岁阿姨**。

正确流程（顺序错 = 方向错 = 出片白费）：

1. **拆原片**（不花钱先做）：下载原片 → ffmpeg 抽帧（720p 竖屏 `-ss <秒> -frames:v 1`）→ 转写对白 → 逐帧看画面（人物/场景/App 界面/尾卡）→ 落盘节点0拆解（对白逐字稿 + 画面分析）。
2. **先分析目标用户表达偏好**：这类人平时刷什么内容、什么表达让她们停下看完/相信/行动；对产品（如「看剧赚钱」App）的信任点/疑虑点（怕骗钱/怕提不出/怕拉人交钱/怕绑定权限）；对比原片表达 vs 目标用户偏好差异。
3. **再设计复刻的角色/场景/演绎**：角色 = 让目标用户觉得「这是自己人」的形象（火龙案例：县城四十多岁说话实在的邻里姐姐「芳姐」，不是刻板 35 岁阿姨）；场景 = 目标用户熟悉的日常（县城自建房客厅+门口小院，不做脏乱穷式下沉想象）。
4. **先出方案给老板确认方向**，再出片。

## 运镜核验：老板点「模仿运镜/尤其是运镜」时（2026-08-22 高颜值版分镜实测）

> ⚠️ **2026-08-22 晚 codex 像素实测（SHOT_REF）推翻了本节部分结论**：火龙实测切点是 10.05s（男→女）/19.95s（女→男）/29.95s（景别硬切），不是下文写的 14s/22s/35s；S01 运镜是「拉远」不是「推近」（人物外接框缩小）。**本节方法（抽帧对比确认方向）仍有效，但最终以 SHOT_REF 像素实测为准**——vision 判断运镜方向不可靠，外接框/像素测量才是事实。

拆片时运镜不能只写「画面描述」，必须核验成**可执行的镜头语言**（Seedance prompt 能表达）：

- **同人物跨时码抽帧对比景别变化**确认运镜方向：0s 帧 vs 10s 帧同人物，人物占比变大 = 推近（zoom in）；坐姿→前倾→站起 = 人物运动带动运镜。vision 问「这个帧和 0 秒帧对比，镜头是怎么运动的」直接得结论
- 分镜表每镜运镜列写「**起幅景别→运动方式→落幅景别**」（如「中近景平视起幅，随人物站起镜头缓慢推近至近景」）——只写「站立讲述」= 废片
- **人物切换点是运镜断点，镜界 = 人物硬切点（2026-08-24 口径定案）**：实测切点以像素实测为准（火龙 10.050 男→女 / 19.950 女→男 / 29.950 景别硬切，不是早期估的 14s/22s/35s）。分镜按人物切换切镜，不硬拆。**UI 层切换（App 页面出现/消失、贴纸变化）不算镜界**——人物底层连续，只作段内后期贴片时点（火龙 12.083/23.950/34.600 三处页面消失均不是镜界，正确拆法 4 段：0-10.050 男主／10.050-19.950 女主／19.950-29.950 男主／29.950-40.000 男主；S02 2.033s 低于下限并入 S03 生成，见下）。scene detect 测的是「画面变化」不是「人物切换」，不能直接当镜界。完整判定链与火龙证据数据见 `references/镜界判定-人物硬切vsUI切换.md`。
- 老板批「人物出场近景运镜没解决」= 出场镜（0-14s）的推近运镜要在 prompt 里显式写（动作序列带时码：坐姿→前倾→站起→举手机，每段带秒）
- 抽帧时用已有帧目录（如 `wiki/teardowns/原始素材/<批>/frames/<id>/f_xxx_<秒>.jpg`）按时间点看切换帧，不用重新抽

## 复刻素材要点

- **原片人物盘点（多人不漏，2026-08-17 老板批「第二个人物画面+贴图全没搞下来」）**：拆片时按 2-3 秒间隔全片抽帧，逐帧确认**出现几个人物、各自时段**。原片可能 2+ 人物（主口播 + 次要人物如「女举手机展示签到页」18-20s）——**次要人物的画面（视频+帧）和她/他手机上的素材贴图也要提取**，只提主人物 = 漏素材。
- **原片素材有些是视频片段不是截图**：手机展示 App 播放（动态）、App 录屏、尾卡是**视频素材**——`ffmpeg -ss <起> -t <长> -i 原片.mp4 -c copy <片段>.mp4` 截段提取，不是只抽帧。
- **App 界面可能有多处，全部盘点提取**：福利中心主页/加桌面弹窗/签到弹窗/播放页/选剧页/特效页/签到福利页……按字幕时段逐段抽帧盘点，缺一个复刻就少一个画面证据。
- **Logo/品牌素材必须完全参照原片，绝不重画（2026-08-17 老板批「火龙的logo也不是这样的」）**：codex 按想象重画的 Logo（Q 版卡通龙）与原片（扁平化 m 形龙 + 紫蓝绿渐变）完全不符。**Logo/App 界面等品牌素材一律从原片抽帧抠取**（`ffmpeg -ss <秒> -frames:v 1` → PIL 裁剪手机屏区域 → vision_analyze 确认完整），重画 = 跑偏。
- **Logo 出现多次、大小不同 → 全帧扫描找齐所有出现位置（2026-08-17 老板「它这个Logo出现了好多次，每出现的地方大小不一样，你要去看全帧」）**：原片 Logo 可能在画面左下角贴图/手机屏内/弹窗左上角等 5 个位置、3 种大小（火龙实测）——**每个出现位置都要抠**，只抠一处 = 漏素材。用全帧拼图逐张 vision 扫描「哪几帧有 Logo、在哪个位置、多大」。
- ⚠️ 原片带水印 / 「内容由 AI 生成」角标 / 原片人物 → **直接截不能用**，需重做无水印版（抠 Logo、重做界面图、尾卡重做）或按老板拍板。
- **文案逐字保留**：转写字幕逐句保留（含繁体/转写词不静默纠错；「复刻」= 贴原稿，不自由发挥）。

## DashScope（快乐马/wan3.0）r2v 台词整段写法（2026-08-25 实测定案）

**快乐马/wan3.0 的台词必须写成整段连续文本，一个"人物说："后面跟完整台词，禁止逐句时码分割。**

实测对比（同一角色、同样9句台词、10秒）：
- ✅ 整段写法（火龙原版/华合寄卖行，无乱语）：`人物说：喂你知道吗，现在看漫剧也能赚零花钱了，就是这个火龙漫剧，直接把福利拉满……`
- ❌ 逐句时码分割（V20夜店复刻S01，后半段全乱语）：`0.500到1.100秒：人物说：哎，跟你说个新发现。1.100到3.000秒：人物说：现在刷漫剧……`

根因：快乐马的语音生成是模型内部生成的（不是TTS），逐句时码分割导致模型处理不过来，后半段崩成乱语。整段连续写法让模型自己分配语速节奏，反而稳定。

规则：
- ✅ 台词写在一句话里：`人物说：完整台词内容，一气呵成。`
- ❌ 禁止逐句时码分割台词：`0.5秒说：xxx。1.1秒说：xxx。`
- 动作时码可以保留（`0.000—6.800秒保持坐姿`），但台词不按时码拆
- 之前成功案例：火龙镜1整段9句台词10秒无乱语；华合寄卖行整段台词9秒无乱语
- **wan3.0 乱切画面问题（0825实测，老板批「它怎么一直在切画面啊」）**：wan3.0 r2v 即使prompt写「一个连续物理镜头不切画面」，模型仍会自行添加景别切换（全景→脸部特写→全景），像电影剪辑。快乐马不乱切但画质/fps弱。解法：prompt反复强调「一个连续物理镜头，不切画面，不跳镜，不换景别」；仍切则换快乐马跑画面+后期配音。

老板原话：「我觉得是你提示词写的有问题，因为开始那个静怡用快乐马生成过一段，也是这么多台词，一点问题都没有」——说明快乐马能扛住多句台词，问题在写法不在模型能力。

语速问题根因（0825实测三版对比）：
- V20原片(Seedance)：71字/10秒 = 7.1字/秒（正常，因Seedance精确控时码）
- 快乐马v2(整段)：87字/10秒 = 8.6字/秒（太快——因多写了16字混入镜2台词）
- wan3.0 v2(整段)：75字/10秒 = 7.5字/秒（正常，语义理解强能自调语速）
- **语速快的根因不是台词多，而是字数写多了**——V20原片71字10秒正常，多写16字就快。快乐马采样率24000Hz vs wan3.0 44100Hz（不影响语速但影响音质）

**定案：台词字数严格按原片对应镜次的字数，不多写不混入其他镜次台词。** 快乐马/wan3.0整段写法 + 字数对齐原片 = 语速正常。

**⚠️ 版本时长差异导致语速变化（2026-08-26 火龙V15 vs V20实测）**：同一套28句台词，V15定版40.5秒 vs V20原片43秒，V15短了近3秒 → 每句平均时间窗口缩短 → 听感语速更快，尤其镜1+镜2台词密集段最明显（方沐阳反馈"第一第二个人语速过快，第三个人正常"——镜3a/3b台词间距大所以不受影响）。根因不是TTS/Seedance语速参数，是字幕时码按40.5秒排的，每句话的时间窗口被压缩了。**规则：改版本时长（砍尾卡/缩短分镜）后，必须重新对齐台词时码到新时长基准，不能照搬旧版时码——时码被压缩=语速变快，时码被拉长=语速变慢。** 检查方法：对比新旧版本总时长差异，时长差>1秒时台词密集段（每镜8+句）会明显感知到语速变化。

**⚠️ V20原片用Seedance生成（不是快乐马），提示词写法不同（2026-08-25 查task_S01_v4.json确认）：**
- V20原片镜1是Seedance出片，prompt用逐句起声时码（`0.500s"喂你知道吗"；1.100s"现在看漫剧..."`）——Seedance能精确控每句起声时间
- 快乐马/wan3.0 **没有逐句时码控制能力**，必须用整段台词写法
- V20原片用3张参考图（@图1人物三视图 + @图2场景 + @图3闪屏页），闪屏页在生成时直接放入手机屏（不是后期贴）
- DashScope复刻时必须同样传3张参考图，漏@图3闪屏页→手机屏空白
- **跨模型适配时必须查原片task JSON确认参考图数量和台词写法，不凭记忆**

**⚠️ wan3.0乱切画面问题（0825实测，老板批「它怎么一直在切画面啊」）：** wan3.0 r2v即使prompt写「一个连续物理镜头不切画面」，模型仍会自行添加景别切换（全景→脸部特写→全景）。快乐马不乱切但画质/fps弱（24fps vs wan3.0 30fps）。解法：prompt反复强调「一个连续物理镜头，不切画面，不跳镜，不换景别」；仍切则换快乐马跑画面+后期配音。

## 合规红线 vs 客户指定卖点（2026-08-25 老板纠正，血泪）

**「换话术」≠ 删卖点。客户指定要用的词就是核心卖点，不是高危词，禁止自作主张软化或删除。**

老板原话：「谁让你去改那些词了？那些词是客户指定要用的，不是高危词。别人让你换个话术，不是让你把这些核心的卖点去给改了。」

正确理解：
- 「仿写文案/换话术」= 用不同的表达方式说**同样的卖点**，不是把卖点删掉或弱化
- ⚠️「吊打同类」「躺赚白嫖」「现金提走」「全部免费」**2026-09-21 新规下属禁项，必须删改**（旧口径「必须保留」已作废，优矩为准）
- codex 自作主张把「吊打同类」改成「用起来确实有点意外」、「躺赚白嫖」改成「多领一份小福利」= **删卖点**，不是换话术，这是错的
- 换话术的正确示例（仅限非违禁词）：「题材特别多」→「想看的基本都有」，卖点保留，表达变了

**任务书必须写明：客户指定的卖点词全部保留，只换表达方式，禁止删除/弱化/软化核心卖点。否则执行器会按合规逻辑自动软化。**

**🔴 复刻方案审查铁律（2026-08-25 实测翻车）：Hermes 派 codex 出复刻方案时，codex 会按自己的合规判断自动降级/删卖点——方案出来后 Hermes 必须逐句核对原片卖点词是否保留，不能直接拿 codex 方案跑。** 火龙 V20 夜店复刻方案把「吊打同类」「全部免费」「现金提走」「躺赚白嫖」全砍了换成了软化表达，老板批「谁让你改那些词了」「你不要自己给它去降级」。**Hermes 审方案时必须 grep 客户指定卖点词，缺失=方案不合格，打回重写或 Hermes 直接改正后再跑。**

## 合规红线冲突（出片会卡住的点）

原文案含**收益承诺/竞品贬低/绝对免费**（「躺赚白嫖」「吊打同类」「全部免费」「换成现金提走」）命中平台/项目拒审红线时，执行器（codex）会主动 `COMPLIANCE`/`BLOCKED` 停付费——**这是对的（出了也投不了）**，但会卡住任务：

- **必须老板拍板**：方案 A 原样保留出片（可能拒审）/ 方案 B 改风险词能过审。
- 老板拍板后，**任务书写明「文案原样保留，不再因合规停」**，否则执行器反复停。
- **⚠️ 但「仿写/换话术」任务里，合规软化不等于删卖点（2026-08-25 老板纠正）**：客户指定要用的卖点词必须保留，只换表达方式。执行器把「吊打同类」改成「有点意外」= 删卖点不是换话术。任务书必须显式写明「保留全部客户指定卖点，只改表达方式」。
- 分辨率同理：原片 720×1280 vs 投稿标准 1080×1920 冲突时问老板（「复刻」= 跟原片一致，但投稿标准要 1080，需拍板）。

## 🚨 口播配音铁律（2026-08-17 火龙复刻成片被批「配音跟口型完全对不上」根因）

**口播镜头的声音必须由 Seedance 直接生成（prompt 里写台词），禁止用 TTS（edge-tts 等）后期叠轨配音。**

- ✅ 正确：Seedance prompt 里写台词（**英文双引号 `""` 包裹**，不是中文「」）→ Seedance 生成画面时自带人声+口型同步
- ❌ 错误：Seedance 只生成「表演底片」（人物张嘴动），后期用 TTS 音轨叠上 → **口型完全对不上**（客户一眼看出，成片返工）
- 方案文档里写「仅生成表演底片，最终对白以锁定音轨替换」= 口型必然不同步，这是设计缺陷，禁止采用

**红果验证过的口播参数（wiki/cases/红果漫剧_复盘.md）：**
1. **prompt 禁止「语速快/语速偏快」（2026-08-22 镜1 样片老板批「你的声音太快了」）**：统一写「语速适中，吐字清晰」。写「语速偏快」Seedance 口播明显过快，听感差。同理「句间短停顿」可以，但语速只能适中。
   - **⚠️ 2026-08-23 实测修正：「语速适中」在台词密度高时仍太快（S01 十秒九句 1.17x 赶词，老板批「语速太快了把」）**：台词密集镜（每镜 8+ 句或 10s 内多句）光写「语速适中」压不住，Seedance 默认往快读。改法：写「**语速从容偏慢、吐字清晰，句间留出自然停顿、从容不赶节奏**」，并把「兴奋/激昂」类表达基调收敛（兴奋容易读快）；台词原文和时码不动，只调声音描述。全片多镜统一复制粘贴同一段声音描述（男声段/女声段各自一致），防止逐镜漂移。
2. 台词用英文双引号 `""` 包裹（「」中文直角引号 → 概率性念错；A/B 实测英文双引号全对）
2. **单镜台词 ≤20 汉字**（超了拆镜，否则念错/念不完）——**但这是 5s 镜的保守值**
3. **每镜 5s 完整口播**（不压缩时长，段时长≥口播实际时长，避免尾字被切）
4. prompt 加「开头先停顿半秒，然后直接开口说台词，不说任何多余的字」+ 负面「多余的话、乱语」
5. 高危字词（模型 G2P 拟合差的音节）同义换词绕开；结尾重复念 → 重跑抽卡选最优
6. 口播念错与否**以人耳为准**（whisper-small 中文同音字识别不可靠，只能辅助）

### ⚠️ DashScope（快乐马/wan3.0）台词整段写法（2026-08-25 老板纠正+实测验证）

**快乐马/wan3.0 的台词必须写成整段连续文本，一个"人物说："后面跟完整台词，禁止逐句时码分割。**

实测对比（同一角色、同样9句台词、10秒）：
- ✅ 整段写法（火龙原版/华合寄卖行，无乱语）：`人物说：喂你知道吗，现在看漫剧也能赚零花钱了，就是这个火龙漫剧，直接把福利拉满……`
- ❌ 逐句时码分割（V20夜店复刻S01，后半段全乱语）：`0.500到1.100秒：人物说：哎，跟你说个新发现。1.100到3.000秒：人物说：现在刷漫剧……`

根因：快乐马的语音生成是模型内部生成的（不是TTS），逐句时码分割导致模型处理不过来，后半段崩成乱语。整段连续写法让模型自己分配语速节奏，反而稳定。

规则：
- ✅ 台词写在一句话里：`人物说：完整台词内容，一气呵成。`
- ❌ 禁止逐句时码分割台词：`0.5秒说：xxx。1.1秒说：xxx。`
- 动作时码可以保留（`0.000—6.800秒保持坐姿`），但台词不按时码拆
- 之前成功案例：火龙镜1整段9句台词10秒无乱语；华合寄卖行整段台词9秒无乱语

老板原话：「我觉得是你提示词写的有问题，因为开始那个静怡用快乐马生成过一段，也是这么多台词，一点问题都没有」——说明快乐马能扛住多句台词，问题在写法不在模型能力。

**⚠️ 视频延长 = Seedance duration 4-15s（2026-08-17 老板「小鹿那边不是搞了什么视频延长」确认）**：
- Seedance 2.0 Mini 支持 `duration` 参数，有效范围 **4-15 整数秒**（或 -1 模型智能选，默认 5）——单镜最长 15s。
- **按剧情/台词自然段切镜，不硬拆 5s**（红果教训「按剧情切镜不按时长凑」：11s 登场+对白一气呵成）。
- 老板要的「视频延长」= 在当前模型硬上限内延长非口播镜头；口播仍按实际试读拆段，每段不超过10秒。
- 口播拆镜前先试读；超过10秒就按语义气口拆段。非口播只在超过当前模型硬上限或叙事确实分段时拆。
- **⚠️ 低于 4s 下限的镜头不能单独生成（2026-08-24 火龙 S02 实测：2.033s 低于下限）**：合并到相邻镜头一段生成，合并依据 = ①FULLSCAN 实锤人物底层连续（中间只是 UI 层切换如页面消失，无人物硬切）；②两镜时长合并后落在 4-15s。火龙 S02+S03（10.050—19.950）合成 G2=9.9s，后期在原切点叠 UI 层。分镜侧保持原镜数（叙事结构），生成侧按合并分段——「分镜归分镜、生成归生成」，两码事。同理 S04（4.0s 正好卡下限）就不必合并。

### 生成段设计与复核教训（2026-08-24 火龙 4 段 reviewer 复核抓 4 硬伤后固化，video-remake 同款）

- **生成时长不锁死 10s**：Seedance 单镜 4-15s，按段实际需要取够长（10.050s 的段生成 11s 裁切到精确分段时长），规则写「≤15s 按需取」不是「每段 10s」——G1/G4 曾定 10s 档裁不出 10.050s，成片实得 39.9s 缺帧；邻段富余素材（跨换人）不可挪用
- **负面约束不能封死景别机制**：要求「近景→全身」+ 负面禁「突然推镜/人物倒退/插入切镜」= 固定机位下景别变大的两条路径（人物后移/摄影机后拉）全被封死，该镜不可生成。景别按原片实测写；未确认的过渡保留「未确认」，不脑补也不禁死
- **任务书 R 清单覆盖全部用户定案**：检查清单要含所有定案（@图3 直出/声音/负面/参考图三件），不能只查 @图1/@图2——火龙 R7 只查前两者，@图3 手机屏品牌页直出被降级成后期贴片没人拦（违反 8-23 定案），reviewer 复核才抓到。产出者自检的覆盖范围 = 任务书 R 清单的范围，清单漏项 = 定案漏检
- **跨界句音轨规则统一成一套**：跨镜句不能三段三套规则（一段缺音/一段重复生成/一段起点对不上）——统一：跨界句在所属段内生成一次、邻段不重复；口播门禁起点与台词起点对齐

## ⚠️ 贴片/LOGO 位置随合成脚本版本漂移——对比上一版是默认动作（2026-08-24 火龙 v14→v19 连续6版 LOOG 放错，老板「你怎么老是犯同样的错误」「你自己去对比上一版的视频 我懒的每次跟你说」）

**症状：** 成片某处多了/移了原片没有的贴片或 LOGO，且这个问题跨多个合成脚本版本连续存在，每版都继承。老板批评「又犯同样错误」= 位置漂移被逐版复制、没人核对出来。

**根因：** 合成脚本（compose_vXX_fix.sh）的 overlay 坐标/时间段在某个版本大改（如 v14「贴片全面修正」）时被一并改动/误伤，之后每版基于旧版复制，**改错的参数被永久继承**。脚本头注释有时甚至留着旧说明（v19 头写「镜4左下角加火龙小LOGO」，但镜1也贴了个）。

**老板期望的默认方法（2026-08-24 明示「你自己去对比上一版」「我懒的每次跟你说」）：**
- **贴片/LOGO 位置可疑时，第一动作是对比上一版视频成品 + 复刻参考版，不要反复问老板**。老板已经烦了「每次都要我说」——对比 v18 vs v19、对比原片 vs 成片，自己找差异。
- 用 `compose_vXX_fix.sh` 的 git 历史/逐版本 `grep overlay` 追踪坐标漂移：`for f in compose_*.sh; do echo $f; grep -oE "\[[a-z0-9_]+\]overlay=x=[0-9]+:y=[0-9]+" $f; done` ——能直接看到位置在哪个版本变了。
- 判定「哪版引入错误」：往前翻版本找 overlay 坐标首次出现「错误位置」的那版，确认是误伤还是有意。**v14 是「贴片全面修正」大版最容易顺手改坏**。

**像素差分客观检测贴片/死帧（比猜可靠，但只能证伪不能证真）：**
- **静止死帧检测**：64x64 灰度转 PGM 逐帧像素 diff，相邻帧 diff >25% = 镜切/大变化，`<5%` = 静止死帧。「素材 10 秒后静止」就是素材实际到头的死帧，被 `trim=end=11.104` 拉长裸露 → 成片中间卡顿。
- **⚠️ 高差异 ≠ 坏帧——闪屏/走动/手机内容变化都表现为高差异（2026-08-24 老板「反正手机里也有闪屏」纠正）**：素材 8-10s 全程 83-93% 差异最初被误判为「画面坏了/鬼畜闪烁」，实际是人物走动+手机闪屏动画的正常跳动。**只有 diff 骤降到 <5% 才是死帧起点**——高差异段是有效画面，不能裁掉。判定顺序：先找 diff <5% 的静止区起点 → 那之前全是有效画面 → trim 截到死帧起点前。
- **贴片有无**：原片 vs 成片同时间点、同区域彩色占比对比——成片某区彩色占比远高于原片（如 60% vs 13%）= 明显多贴了东西。
- **⚠️ 但不能证真「那 60% 一定是 LOGO」**——彩色占比分不清「贴片 LOGO」和「画面里手机屏内容刚好在右下」。像素只能给出「该区域异常」，**判断是不是 LOGO、位置对不对必须实看原片/上一版**（vision 或发老板）。对比判断不了就发帧给老板，一次到位，别反复像素猜。

**音频 adelay 重对齐（改 trim 后必做，2026-08-24 实测）：**
- 改某镜视频 trim（如镜1 从 11.104→10.0）后，后续所有镜的音频 adelay 必须同步前移：`新adelay = 旧adelay - (旧trim - 新trim)`。镜2/3/4 的 adelay 全部减去同一个 delta（如 delta=1.104s）。
- 总时长 DUR 也要同步调整：`新DUR = 新镜1时长 + 镜2时长×3`（或实际各镜时长之和）。
- 镜1 自身音频 `[0:a]` 如果没有 atrim，会带满原始时长（11.104s），多出的尾部由 `amix` + `-t ${DUR}` 截断——但如果镜1尾部有跨界句（如第9句在 10.0s 起声），trim 到 10.0 正好保留起声、10.0 后的死帧音频被截。分镜台词时码验证：跨界句起声点 < trim 截点 = 安全。
- **改完脚本先做 12s 试片验证**（复制脚本改 DUR=12 + OUT=试片路径，不覆盖正式成片），抽帧确认 LOGO 位置 + 死帧避开 + 音画衔接，再跑正式全片。

**修复 + 防再犯（固化参数 + 自检）：**
1. 删除错的 overlay 行（如 `[o01][app]overlay=x=430:y=880:enable='between(t,2.680,4.640)'`），链式 overlay 直接跳级（改 `[o01][play_g1]...` 替代中间那级），**同时删掉 split=2 里不再用的分支**（`split=2[app][app_small]` → `[app_small]`，防 ffmpeg 未消费分支）。
2. 改动后写脚本验证孤儿引用：grep `[app]`、`[o02]` 应返回 0，`[app_small]` 保留引用正常。
3. **把正确位置固化成固定参数**，并在合成脚本头注释写清「镜1 无 LOGO / 镜4 左下 LOGO」——防止下次合成时又凭记忆改漂移。
4. 合成脚本改动的判定标准 = 原片 + 上一版确认版，不是自己想象。

## 字幕样式照原片（2026-08-17 老板「看看参考视频的字体是怎么做的」）

复刻字幕**完全参照原片的字幕样式**，不自己设计。火龙原片实测（3 帧核对一致）：

- 主字幕：**顶部居中**（不是底部！），粗黑体、白色大字、深黑圆角背景条
- 右下角：平台水印（抖音 logo+账号）——复刻不仿（平台自己的标识）
- 底部：合规小字（「具体金额以实际活动为准」类）

做法：拆片时抽 2-3 帧字幕区（`PIL crop 底部/顶部` 放大）→ vision 确认字体/颜色/描边/背景条/位置 → 复刻按同款做。字体渲染规范（红果复盘）：Noto Sans CJK Bold（TTC index=2 SC，防日文字形）、超宽自动换行、重点词单独一行。

## ⚠️ 复刻对照检查：防「读了 skill 但自由发挥」（2026-08-22 老板「你为什么不按照纪律」「闸门感觉没用啊」）

**闸门管不住内容质量——这是「小鹿一直犯的错」的根。** 实测链路：Hermes 读了 skill、任务书带 READ_SKILL 标记、走完 confirm/permission/kb/task_brief 全闸链 → prompt 里自由发挥（运镜自己判断、景别没照原片、LOGO 让模型生成）→ 闸门全绿放行 → 出片跑偏。现有闸门管「流程/权限」（没授权不出片、没读知识库不出活、任务书不带原话不派活），**不检查「内容是否照原片」**。用户感觉「闸门没用」是对的：闸门防住「乱烧钱」，防不住「乱发挥」。

解法 = **复刻对照检查（内容层物理卡点）**，落地模式参考 kb_gate 的 READ_SKILL 字符串检查：

1. **拆片阶段产出对照表**（codex 逐帧核验，每镜必列）：景别（近景/中近景/中景 + 人物占比 + 头部留白）、人物位置（居中/偏侧、头部高度、朝向）、运镜（方向+幅度）、素材贴法（LOGO/界面后期贴的位置）、台词逐句、切换点。

## ⚠️ vision_analyze 坐标盲裁不可靠（2026-08-17 实测）

用 vision_analyze 问「Logo 的精确像素坐标」来盲裁，**多轮给的坐标每次都不一致**，按坐标 crop 裁到窗外背景/错误区域。**精确裁边（对齐白框/修到内容边界）用像素扫描，见 `references/crop-to-boundary.md`（2026-08-18 新增：亮度/饱和度扫描找边界 + 验证流程）。** 可靠做法：
- 先裁一个**较大的区域**（手机屏/中右区域，宁可多裁背景），在**大区域图上**问素材位置；

## ⚠️ 手机屏贴图必须跟随手机移动 + 严丝合缝（2026-08-18 老板批「你就是把那个图标固定在那里，然后等着手机过去」「他的手机贴图是做的严丝合缝的，你的看起来就是贴上去的」）

复刻 App 广告时，手机屏内的界面/Logo 贴图是**后期贴进画面**的（原片也是贴的），但贴法决定成败：

1. **固定坐标 overlay 贴图 = 穿帮**：ffmpeg `overlay=x=固定:y=固定` 贴死在画面上，手机一动就「图标钉在那等手机过来」——老板一眼看出。**贴图必须锚定手机屏，手机动贴图动。**
2. **ffmpeg 无原生贴纸跟踪**（`mestimate`/`minterpolate` 是插帧不是跟踪）——需 OpenCV 光流方案（⚠️ 2026-09-17 用户定案：「生成后贴屏」路线已废弃、对应 skill 已删——手机屏内容改为生成时把闪屏页/界面图当参考图喂给视频模型直接渲染进屏幕）（2026-08-18 实测：锚点帧初始化 + 双向光流 + 每90帧重检测 + 丢帧插值）。
3. **贴图要「像屏幕内容」不是「贴纸」**：原片手机屏内容是圆角匹配屏幕、带玻璃反光、顶部刘海留白——贴图要加圆角 mask + 顶部刘海黑条 + 顶部反光渐变，否则直边矩形一眼假。
4. **贴图起点避开手机举起过渡段**：手机从低位举起/转向时屏位置剧变，光流易丢——0-3.5s 手机屏本来就暗（原片 3s 前也不显示界面），这段不贴，从手机举起稳定后开始贴。
5. **检测器选型坑（实测）**：Canny 边缘检测在 Seedance 画面（圆角+反光+手遮挡）**拟合不出四边形（全程 0 个合格）**；**黑屏二值化**（阈值 35 反色 + 竖长形过滤）才有效。第一帧手机又小又低位检测失败是常态 → 扫描后续帧找手机最大最清晰的锚点帧（如 5-9s）再初始化。
6. **合成后必须验证「贴图跟手机屏同步」**：抽 4-5 个时点帧，像素检测手机屏中心 vs 贴图中心，偏差应 <5px；贴图钉死（偏差大）就是跟踪失败。

**汇报视频任务结果时：术语必须翻成大白话，关键数字必须自己复算，不能直接转述执行器交接包。**

1. **术语大白话对照（汇报时直接换成人话，或出现即解释）**：门禁指针=系统里登记的新旧版本指向；FULLSCAN=逐帧扫描原片；SHOT_REF=原图像素实测表；attest=执行者签名；G_CREATIVE_READY=分镜质量闸；rc=0=通过。老板喊「说人话」= 上面这类词又冒一堆，立刻用大白话重讲一遍（用户画像早有「技术报告翻大白话」，说明只写进画像不够，汇报前就要自查）。
2. **执行器交接包/自述报告的数字不能直接转述（2026-08-24 实证翻车）**：claude 交接包写「旧分镜 7 镜 vs P2 8 镜」，实际两版都是 7 生成镜 + 1 二维尾卡——交接包把「标题段数 8」和「门禁解析生成镜 7」混着写，直接转述就报错了。交付前关键数字（镜数/时码/门禁结果/字节行数）用工具自己复算一遍；复算值和交接包不一致时以复算为准。注意 `parse_seedance_shots` 收的是**内容字符串**不是文件路径（传路径返回 0），正确用法 `parse_seedance_shots(open(f, encoding='utf-8').read())`。
3. **「镜数」口径先统一再汇报**：文件里 `## S0N` 标题数 ≠ 门禁解析的生成镜数——二维尾卡段（如 S08，无四层结构或标注「不进入生成通道」）不算生成镜。报镜数时说清「X 个生成镜 + Y 个尾卡」，不要只报一个数。
4. **拆镜数=原片实际切点，不是时长拍脑袋（2026-08-24 老板「15秒的视频你也能拆成7镜？」）**：15 秒只有 3 个真实切点就只能拆 3 镜，硬拆=凑数=模型生成鬼畜。汇报拆镜结果时带切点时码表（每镜起止时码+切点依据，如 scene detect/灰度 MAD 实测），证明每个切点都有实测证据。火龙 43s 拆 7 生成镜+1 尾卡，靠的是 FULLSCAN 实锤的 8 段切点，不是「40 秒能拆 7 镜」。
5. **切点要分「人物硬切 / UI层切换 / 未定性过渡」，镜界只认人物硬切（2026-08-24 老板「我看原片后面男的不就两段？」后定案）**：FULLSCAN 实锤女主后男主只有 19.950、29.950 两个真硬切，23.950/34.600 只是「页面消失露出人物」（UI 层切换，高阈值场景检测未命中），人物底层连续——**不算镜界、不拆镜**，只在段内按时点贴 UI。老板看原片说两段 = 对的，先认。汇报先给「人物段」再给「生成段」，别拿旧 8 镜口径压老板观感。生成分段按人物硬切 4 段：0-10.050／10.050-19.950／19.950-29.950／29.950-40.000。
6. **出镜时长账只算真人段（2026-08-24 老板「不要尾卡」）**：尾卡/平面素材（如真实搜索尾卡 3s）不是人，不并进出镜时长。报全片账分开列「男主 Xs + 女主 Ys + 尾卡 Zs（平面素材不算人）」。火龙实测：女主 9.9s = S02+S03（2.033+7.867 连续出现，中间只换页面）；男主 30.1s = S01 10.05 + S04-S07 20.05；真人共 40s。

## 常见坑

- **🔴 复刻时长=原片时长，不能全部设10秒（2026-08-27 用户「我靠，什么叫复刻？」）**：快乐马API只支持5秒和10秒两个档位，但原片分镜可能是7/7/8/9/9=40秒。正确做法：①查原片每段多长 ②生成10秒 ③拼接时用ffmpeg `trim`裁剪到原片段精确时长。**前提：ASR验证台词在裁剪点前讲完**——台词占满10秒时不能硬裁（会断台词），要么换短台词版，要么接受实际时长。详见 `references/dashscope-duration-limits.md`。
- **🔴🔴 混剪视频≠逐段生成音视频捆绑体（2026-08-27 用户三次纠正，血泪）**：原片（火龙通用口播40s）是**AI数字人视频 + App录屏 混剪**——口播音频是一条整条轨，画面在数字人段和录屏段之间切换，音频连续不断。**错误做法**（本次翻车）：把整条台词拆5段、每段用快乐马生成10秒音视频捆绑体→5×10=50秒，比原片多10秒，丢了画面交替结构。**正确做法**：①整条口播台词→TTS生成一条完整音频（40秒）②AI视频只做数字人口播画面段（按原片时间轴出对应时长）③ffmpeg混剪：AI画面段+App录屏段+一条连续TTS音频。详见 `references/dashscope-duration-limits.md` 混剪模式。**用户原话：「他就是先把整个音频用其他工具生成了，然后在那个画面的时候，他放那个APP素材的时候，他的音频是跟着一起在放的」「你不要就被规则限定死了，你是要去参考原视频的。原视频它可能一段才12秒，那我们肯定也要做到12秒」**
- **⚠️ 交付分镜/提示词前 grep 旧规则词清零（2026-08-22 高颜值版实测）**：codex 产出分镜时可能沿用旧模板/旧知识库写法，本次 3D 风格定案后分镜仍带「从彩色铅笔人物还原」残留（4 处）——交付前 `grep -c '彩铅\|彩色铅笔\|还原写实\|从彩铅'` 必须 0（「不经彩铅」这类否定表述除外），有残留先 patch 改净再发老板。任务书规则更新后，执行器不知道旧规则已废弃，清理是打包方/质检方职责。
- **⚠️ 拿原片瑕疵当借口 = 自欺欺人（2026-08-18 老板「你不要自欺欺人好吧」）**：被批「比参考视频粗糙」时，说「原片贴图边缘也没对齐」这类话是找台阶——原片整体观感就是比我们好，观众看整体不看技术拆解。正确反应：老实找差距（逐帧对比成片 vs 原片，vision 逐条列差异），承认差距，再修。
- **别把「目标用户」当成「视频角色」**——这是本类任务第一纠偏点。
- **执行器会做多余生图**（彩铅三视图后又做彩绘绕检多轮）——三视图 + 脸部特写已够锁脸；绕检图是被 Seedance 拦截时的预案，不是锁脸必须。任务书里明确「不再生图/不再绕检，素材直接用」可提速。
- **剪素材帧时盲裁会切掉文字**——裁剪后必须 vision_analyze 确认 Logo/文字完整；原片手指遮挡导致文字不全时接受（Logo 完整即可），不要反复盲调。
- **⚠️ 从原片截「录屏/界面」素材会混入原片人物（2026-08-17 成片 QC 抓到的真实 bug）**：把原片某段（如 24.1-35.8 秒）直接截成「App 录屏素材」时，**那段原片里是原片人物举手机在说话**（年轻男），截下来的是「人+手机」不是「纯 App 界面」→ 合成后成片出现原片人物，与复刻人设冲突。**截录屏前必须逐帧确认素材里只有 App 界面、没有原片人物**（抽帧 vision_analyze 验证：纯界面 ✅ / 含人物 ❌）。含人物就不能直接截，要么用 Seedance 重出「复刻角色举手机展示」镜头，要么只裁手机屏幕区域。
- **⚠️ 成片 QC 必须逐帧查人物一致性 + 素材来源（不止查分镜表）**：QC 只按分镜表查「Seedance 4 镜都是芳姐」会漏掉「录屏段混入原片人物」。全片按 3-5 秒间隔抽帧、逐帧确认「每个出现人物的画面都是复刻角色，没有原片人物/其他角色」；对每个素材（尤其从原片截的）单独验证内容纯净。
- **⚠️ 参考图用错=人物全错=白烧钱（2026-08-27 实测翻车）**：项目目录有多张参考图（旧版灰蓝上衣低马尾 vs 新版米白V领齐肩黑短发），生成前未向用户确认用哪张，直接用了旧图，用户说「你人物用错了」。**规则**：生成前必须向用户确认参考图，不能凭记忆选。参考图URL要更新到公网可访问地址，广州机Caddy `http://<GZ_HOST>/<文件名>` 放在 `/home/ubuntu/public/` 目录下。
- **⚠️ 火龙有三套独立模板不是两套**（0827实测翻车）：①网赚版（提现/金币/白嫖，28句原片台词，3张参考图含闪屏页，举手机+App展示）②通用版（追剧痛点/选集页/热播榜，codex仿写台词，3张参考图，举手机+App展示）③痛点版（痛点吐槽/全集/题材/画质，199字改写台词，2张参考图无闪屏页，不举手机纯口播）。三套模板台词完全不同、参考图数量不同、动作不同。用户问"台词跟原片一样吗"时必须先确认是哪套模板再查台词来源。痛点版台词来源=拆解报告765152.../765812...样本改写，非原片765330...的28句。详见 `dashscope-r2v-replica-workflow` skill `references/huolong-painpoint-version-structure.md`
- **⚠️ 发素材群前必须核对版本+台词+文件完整性（2026-08-27 实测两次翻车）**：①发错版本——用户说"发"，要发的是通用版原片台词成片，Hermes发了网赚版（白嫖漫剧那段），用户说"你发的什么视频？""你发的是网赚版"；②台词被改写未发现——成片v3用的是改写版台词（"追漫剧就怕这个…"），不是原片原文（"有些人我真是无语了…"），用户问"你那个台词跟原版一样？"才发现。**规则**：发群前①确认版本（网赚版/通用版）②grep核对台词是否原片原文③ffprobe验证文件完整性（scp超时只拉一半=坏文件，HH-1只有1.8MB vs 正常3MB，ffprobe报moov atom not found）。三条全过才发。
- **⚠️ 口播声音必须明亮有力（2026-08-27 用户纠正）**：快乐马prompt里声音描述写"像家人之间聊天分享"太柔，用户批"声音要大些，像口播的感觉"。**规则**：口播/广告类视频声音描述统一写"口播风格，声音明亮有力，音量充足，像对着镜头跟观众说话"，禁写"像家人之间聊天分享"。
- **⚠️ 广州机成片拉本机必须ffprobe验证（2026-08-27 实测）**：快乐马成片在广州机生成（`/home/ubuntu/workflow/projects/happyhorse_output/`），scp -P 2222拉到本机`/tmp/`再发飞书。scp可能超时只拉一半→坏文件（moov atom not found）。**规则**：scp拉完必须`ffprobe -v error`验证完整性，文件大小对比广州机源文件，不一致=重拉。
- **⚠️ 语速偏慢要提，对齐原片实测（2026-08-27 用户「速度、口语速还有点慢」）**：底片生成后用whisper转写验证字数÷时长，与原片语速对比。原片5.1字/秒，底片HH-4只有4.6字/秒=偏慢。prompt统一写「语速适中，吐字清晰」但实际语速取决于台词字数÷生成时长，字数写多了语速快、写少了语速慢。**规则**：台词字数严格按原片对应段字数，底片时长对齐原片段时长，语速偏差>15%重跑。
- **⚠️ 选集页录屏素材白屏+黑边修复（2026-08-27 实测）**：App录屏素材（如选集页4.76s）前3秒是播放页、第4秒白屏加载、末尾才出选集列表。直接用全段=成片22秒处白屏。**修复方法**：①抽最后一帧（选集列表加载完成）冻结延长替代白屏段；②用ffmpeg `scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920` 统一不同分辨率素材（540×1116/620×1280）避免黑边。重建UI覆盖层时逐秒像素检测白屏（`PIL`采样四角+中心+下半区，`>240=白`），vision验证无白屏后再合成。
- **⚠️ 画中画(PIP)合成后必须逐帧验证是否真出现在成片里（2026-08-27 实测翻车）**：合成方案明确定义了圆形画中画overlay，用户说「你那些画中画根本没有啊」。检查发现成片右上角的圆形小窗是App录屏素材自带的原生平台UI（被一起录进去了），不是后期做的画中画overlay。**铁律**：合成后逐帧抽帧+vision验证每个后期叠加层是否真出现在成片里，不能假设方案写了就等于做了。画中画圆形遮罩用ffmpeg `color+geq`生成圆形mask→`alphamerge`→`overlay`，PIP位置不能遮住剧名/集数/分类标签。
- **复刻是「贴原稿」：结构/文案/素材对齐原片，只换目标用户相关的人物/场景/演绎。**
- **🔴🔴 画面跟着口播台词走，不是按固定时间轴排（2026-08-27 v4→v5→v6三版翻车定案，血泪）**：原片的App画面/剧情片段出现的时间点 = 口播台词说到那个功能/卖点的时刻。台词说"直接看全集"→切播放页；说"题材丰富"→切分类页+画中画；说"新剧上架"→切热播榜；说"画质高清"→切播放页。**第一步必须建立台词→画面对照表**（whisper逐句转写→标注每句对应什么画面→素材出现时间=台词时间），不能自己拍脑袋排时间轴。用户原话：「你是素材放错地方了，完全没有跟着口播稿走，原片素材是跟着口播稿走的。你先梳理清这个逻辑。」详见 `references/台词驱动画面时间轴_20260827.md`
- **delegate写的对比报告≠成片实际**（0827实测翻车）：把原片拆解报告+合成方案+台词本打包给delegate_task子agent写「对比修正报告」，子agent基于文档分析说「大字完全缺失」「画中画缺失」，但实际抽帧+vision_analyze看成片发现大字已烧入、画中画是素材自带的原生UI不是后期叠加。**铁律**：delegate文档分析只做参考，实际成片验证必须自己抽帧+vision_analyze逐张看，不能拿文档分析结论当事实
- **合成方案写了≠ffmpeg命令做了**（0827实测翻车）：后期合成方案明确定义了画中画overlay，但实际合成成片后用户说「你那些画中画根本没有啊」——检查发现成片右上角的圆形小窗是App录屏素材自带的原生平台UI（被一起录进去了），不是后期做的画中画overlay。合成后必须逐帧验证每个后期叠加层是否真的出现在成片里，不能假设方案写了就等于做了
- **⚠️ 出片被批后先整理素材发老板确认，再重做（2026-08-17 老板「你先把素材整理好以后发给我看」）**：成片有质量问题（口型/人物混入/Logo 不对）时，不要直接重做——先出**素材清单**（截图类+视频片段类分列、每项内容/来源/复刻用途、缺什么/问题点如「录屏含原片男怎么处理」）发老板确认，对齐后再让执行器按确认结果重做。素材没对齐就重做 = 重做也白做。
- **⚠️ 试跑被批后先总结全部问题清单，再动手改/重跑（2026-08-23 老板「先不跑 把问题先全部总结清楚」）**：样片/试跑被批（语速/运镜/念错字/景别/声音/动作）时，**不要逐条收到反馈就立即改一条重跑一条**——先把已确认问题汇总成清单（含你自己抽帧/转写定位的证据），交给老板过目，老板认可问题清单后再统一改 prompt/分镜。逐条改=反复烧钱重跑+改漏；先总结=一次改全。同一轮反馈里老板可能连批 6-7 项（语速快、坐太近、声音难听、缺走动、念错字……），只有列全了才知道哪些是同一根因（如「缺走动」导致「运镜观感差」「站原地僵硬」全是同一个动作缺失）。（例外：老板明确说「先改 X 重跑」时按单条走）
- **⚠️ 交付前不用旧对照表背书，老板亲测反馈是最高证据（2026-08-23 火龙 S01 老板「你让codex去对照，你去对照老是错的」「我怎么感觉你越来越傻了」）**：被批「手机一闪而过/语速快/原片有走路环节」时，**第一反应不能拿旧对照表（08-18 做的）当依据反驳**——旧表漏了走路环节，拿它反驳 = 错上加错。正确：①老板亲测反馈直接采信，先认不嘴硬；②重新 0.25s 间隔逐帧实测原片，以实测为准；③拆原片/对照始终是 codex 的活（见上），Hermes 只抽帧搬运、不做画面判断。旧 SHOT_REF/对照表是依据但不是免检品，老板反馈后必须重新实测（已有 SHOT_REF 全片重测教训同理）。
- **⚠️ 动作节点用台词锚定，不只用秒数排（2026-08-23 老板「他说直接两个字的时候就开始起身准备走路了」）**：起身/走路等动作节点跟台词强关联（原片第4句「直接把福利拉满」说「直接」两字时开始起身）——拆片时把「每句台词开始时间」和「动作节点」对齐成一张表，prompt 写「说到『直接』时起身」这类锚定，不只写「4.5秒起身」。帧内字幕出现时间 = 台词时间锚点（原片口播段几乎都带字幕），逐帧找字幕出现帧即可推台词时间，不必依赖 ASR。
- **⚠️ 语速参数必须实测原片，禁止用分镜时长倒推（2026-08-23 老板「语速怎么比原视频快这么多」）**：S01 语速 6.3 字/秒是拿台词字数÷分镜时长倒推的，实测原片 73 字/14 秒 ≈ 5.2 字/秒，快 25% 听感就赶。拆片时实测原片语速 = 原片段台词字数 ÷ 原片段实际时长，写进对照表；prompt 语速描述按实测值写，不按分镜时长倒推。
- **⚠️ 彩铅三视图用途：出片 @图1 绕检垫图，还原只发生在 Seedance 生成阶段（2026-08-23 老板「彩铅三视图是在生视频的时候还原」）**：彩铅三视图 → Seedance 生成时从彩铅还原真人写实。**禁止在生图阶段做「彩铅→真人写实」两步图生图转换**（多此一举，Seedance 还原效果才是定版）。真人写实静态图不是出片必需，顶多给老板预览形象；老板质疑用途时如实说明「出片用不上它」。
- **⚠️ 三视图排版必须对齐原版式（2026-08-23 老板「三视图是这个排版吗」）**：彩铅/3D/写实三视图统一横版 1 行 4 列（左列脸部+肩部特写竖条，右侧正面/侧面/背面全身横排，人物大小一致，纯白底）。codex 文生图默认出竖版 2x2 四宫格——prompt 必须写死「横版 1 行 4 列排版」+ 横版尺寸（如 2304x1728），生成后 vision 核对排版再交付。

- **⚠️ BGM 源文件丢失 + 合成脚本 BGM 步骤被删（2026-08-24 火龙 v18→v19 实测）**：两个坑叠加导致成片无 BGM：① BGM 源文件（如 `bgm_song1_43s.m4a`）在清理工作目录时被删；② 重构 compose 脚本时把 BGM 步骤整段删了（当时复用旧版整条音轨所以还有 BGM），改成四段自带音频拼接后只剩 voice。**防再犯**：a) BGM 源文件单独备份到 `audio/bgm/` 子目录，不跟临时文件混放；b) SoundHelix Song-1（`https://www.soundhelix.com/examples/mp3/SoundHelix-Song-1.mp3`，免费商用）作为通用 BGM 兜底源，下载到 `/tmp/` 即可；c) 合成脚本改动后必须检查 BGM 步骤是否还在（`grep -c 'bgm\|BGM\|amix.*bgm' compose_vXX.sh` 应 ≥1）；d) 验证 BGM 真叠上了：`ffmpeg -ss <语音稀疏段秒数> -t 0.4 -i 成片.mp4 -af volumedetect` 看 mean_volume，纯 voice 段 -25dB 以下 = BGM 没叠上，-15dB 左右 = BGM 在。
- **⚠️ BGM 太小听不到 = 源文件本身极静 + amix 自动压半（2026-08-26 火龙夜店版 V6→V11 连续6版实测）**：BGM 源文件 `环境音与轻BGM_43s.wav` 实测 mean=-44.9dB max=-35.6dB（极静），即使 volume=8.0（+18dB）后经 amix normalize=0 混音，BGM 仍被压到听不清。用户从 V3(volume=3.0)→V7(6.0)→V9(8.0)→V10(20.0) 连续4版说「BGM还是很小」「bgm调到2倍太小了」。**根因**：amix 默认把两路音频各取 50% 混合，BGM 被再降一截。**解法**：volume=50.0 + `alimiter=limit=0.95` 防爆音，最终成片 mean=-9.9dB max=0.0dB 才够响。**经验**：BGM 源文件 volumedetect 先测，mean<-35dB 的极静文件直接换源或拉到 50 倍+limiter，不要从 3 倍开始逐版翻倍试（烧用户耐心）。用户说「换一个」= 换 BGM 源文件，不是继续调 volume。
- **⚠️ 动态视频素材 overlay 必须 stream_loop -1，stream_loop 0 只播一次后变静态截图（2026-08-26 火龙夜店版实测）**：双列流界面素材（`双列动态_用户提供.mp4`）和 AI 动效素材（`竖屏页动态_孙悟空_clean.mp4`）是视频片段，overlay 时必须用 `-stream_loop -1 -i <视频素材>`（无限循环播放），用 `-stream_loop 0` 或不带 stream_loop = 视频只播一次后停在最后一帧 = 成片里看起来像静态截图。用户批「你现在都发的是截图」= stream_loop 参数错了。验证方法：抽同一段素材两个时间点帧（如 29.0s 和 29.5s），像素 diff >30% = 动态播放，<5% = 静态死帧。
- **⚠️ 贴片时码必须跟当前版本口播对齐，不能照搬旧版（2026-08-26 火龙夜店版实测）**：夜店高颜值版口播节奏跟中年下沉版（V19）不同，但贴片时码照搬了 V19 的时码 → 口播说「双列流界面随心滑动」(25.6s) 时双列流素材还没出（28.6s 才出），口播说「竖屏沉浸式看剧模式」(31.2s) 时竖屏素材还没出（33.4s 才出）。用户批「素材用错了」「素材跟口播对齐」。**规则**：换了口播版本后，所有贴片素材的 enable='between(t,X,Y)' 时码必须重新对齐当前版本的语音段/字幕时码，不能照搬旧版。对齐方法：用 silencedetect 或波形能量检测测当前版本实际语音段 → 字幕时码对齐语音 → 贴片时码对齐字幕内容（如「双列流」字幕出现时双列流素材同步出现）。
- **⚠️ 贴片 y 坐标下移后可能反而挡脸（2026-08-26 火龙夜店版实测）**：V6 把所有贴片 y+80 下移（修「不挡脸」），但金币页素材（height=770）从 y=150 移到 y=230 后，素材顶部到 y=230，人物脸部在 y=100-300 → 反而挡住了人物右半侧脸。用户批「10秒那个素材挡住脸了」。**规则**：贴片下移不是无脑 +80，要算：素材顶部 y + 素材高度 vs 人物脸部 y 范围。素材顶部在脸部下方 = 不挡脸。金币页改到 y=350（素材顶部在脸部下方）才解决。同理双列流素材（height=700）y=185 时底部到 885，跟字幕（MarginV=380 → y≈900）重叠 → 用户批「26秒素材重叠了」→ 改 y=80 + height=700 底部到 780 给字幕留空间。
- **⚠️ 尾部 logo+箭头在砍尾卡后要重新安排时码（2026-08-26 火龙夜店版实测）**：V19 的 app_small logo + red_arrow 在 39.2-43.8s 出现（尾卡时段），夜店版砍了尾卡缩到 40.5s，logo+箭头没了。用户要求「最后说到左下角的时候要出现那个小logo和红色箭头」→ 口播「现在左下角开启火龙漫剧」在 36.26s → logo+箭头 enable='between(t,36.260,40.500)'。**规则**：砍尾卡/改时长后，尾部 UI 元素（logo/箭头/CTA）时码要重新对齐到当前版本的「左下角」口播时段，不能丢掉。

## ⚠️ SHOT_REF.yaml = 复刻唯一画面依据（2026-08-22 晚 codex 像素实测定案）

**原片拆解的最高产物不是「画面分析 md」，是机器可读的 `SHOT_REF.yaml`**（codex 产出）：逐镜字段 = 切点（灰度 MAD 实测）/景别/人物位置（像素归一化）/运镜/动作序列（带时码）/素材与贴法（贴哪个文件、贴哪块区域、禁模型生成什么）/LOGO 水印文字位置/台词（逐句带时码）。全链路（分镜/prompt/素材贴图/质检）**唯一画面依据**——执行器每个画面决定必须指回 SHOT_REF 具体 shot/字段，指不回去 = 自由发挥 = BLOCK。

**codex 像素实测方法（比 vision 判断可靠，vision 两次结论冲突时以像素为准）：**
1. **切点用灰度 MAD**：ffmpeg fps=2（0.5s 间隔）密集抽帧，切点附近按 60fps 相邻帧逐帧灰度 MAD（阈值 30）——实测火龙硬切点 **10.05s（男→女）/19.95s（女→男）/29.95s（男主景别硬切）**，另有合成层变化点（如 12.083s 现金页消失）。**稀疏抽帧 + vision 判的切换点不可靠**（旧表 14s/22s/35s 全错，连 10.5s 也只是近似）。
2. **人物位置量化**：720x1280 帧像素读取人物外接框/头部中心后归一化——S01 男主头部中心 x=0.50±0.05W、y=0.18H→0.15H，外接框 0.85W×0.94H（坐姿腿部裁切）→0.55W×0.82H（全身）。
3. **运镜用外接框变化判定，不用 vision 感觉**：外接框变小 = 拉远。**实测火龙 S01 0-5s 是「拉远/后撤」**（近景坐姿 → 全身中景），5s 后稳定——**不是推近**。此前 vision 两次判「推近」全错（vision 会被人站起来后「看到更多环境」误导）。写 prompt 前必须查 SHOT_REF 的运镜字段，别信自己的 vision 印象。
4. **素材贴法逐镜实测**：手机屏状态（S01 亮屏显示品牌页 → 后期贴《火龙漫剧_品牌页_手机屏贴图_用户提供.jpg》；S02/S03 **手机背面朝镜头，屏幕不可见**——禁止写亮屏展示）、覆盖区域（如福利中心页贴 x≈0.08-0.78W/y≈0.16-0.85H）、弹窗用哪个素材文件（签到弹窗用客户提供的干净版）、**LOGO 实测在亮屏手机内（画面右侧随手移动），无固定左下 LOGO**。
5. **ffmpeg 抽帧/montage 操作坑（2026-08-23 实测）**：①输出文件名含数字会被 image2 muxer 当序列模式（`segA_1.png`/`ma_3_5.5s.png`）→ 报 `Cannot write more than one file with the same name`，文件名用「字母前缀+时间戳后缀」（`f_3.5s.png`），montage 输出名避免含数字；②`tile=2x5`（10 格）塞 11 帧 → tile 输出第 2 张写同名报错，先 `ls | wc -l` 数帧数再选格数（11 帧用 3x4）。

SHOT_REF 产出流程：codex 读原片（0.5s 间隔抽帧 + MAD 切点验证 + 人物外接框测量 + 素材贴法核验）→ 落 `staging/SHOT_REF_<日期>.yaml` + 人类可读对照表 → 分镜/prompt 从 SHOT_REF 指回 → 老板确认分镜 → 出片。参考火龙 SHOT_REF：`/home/ubuntu/workflow/projects/huolong-guide/staging/SHOT_REF_20260822.yaml`。

**⚠️ SHOT_REF 可能系统性错误：把「人走近」误写成「镜头推近」（2026-08-23 火龙全片重测实测，老板「你这个复刻怎么这些东西都没复刻到呢」后固化，血泪）**：旧 SHOT_REF（codex 2026-08-22 像素实测产出）把人物向镜头走近误判成摄影机推近——S01/S02/S04/S07 四镜运镜机制全错，还漏了 S01/S07 的走动主动作（原片是「拿着手机面对观众边走边讲、镜头后退跟随」）、多段后期层时码（S01 约6.583—7.483 灰度小窗/约9.000 红圈箭头、S02 红包贴纸早于现金页约0.18s、S07 红箭头实际 (36.500,36.600] 出现 vs 旧稿 37s、金币 (38.650,38.700] vs 旧稿 39s）。复刻链路（分镜/prompt）每一环都「忠实」回指 SHOT_REF = 错误被完整继承 → 成片「站原地僵硬、运镜不对」。**教训：SHOT_REF 是依据但不是免检品——试片后必须全片重新实测**。**判定「人走近 vs 镜头推拉」用背景锚点法**：背景（床/窗框/灯等）尺度和位置变化远小于人物 + 人物快速变大 + 下肢跨步 = 人物走近（摄影机近似固定）；背景同步放大/位移 = 镜头推/移。人物占可见框比例不可靠（站起会让比例回升、看起来像推近）。**误判方向不固定——两边都可能错（2026-08-23「人走近误写成推近」vs 2026-08-24 G3「镜头拉近误判成人走近」实录）**：FULLSCAN 写 S04「20.450/20.950 连续向镜头走」实为人物固定原地、镜头拉近（取景缩小），分镜/提示词照写「走近」→ 生成视频人物真走路 → 老板「原视频没有走路这一段吧」。**写分镜前动作类事实必须 fps≥3 抽帧 + vision 逐帧核实脚位/背景**（老板实看 > FULLSCAN/抽帧推断）；「走/移/停/坐」这类词没有原片实看证据就删。同方向补充（2026-08-24 G4）：人物真走近穿场景时 prompt 必须写清「背景随人物移动连续变化（列出经过区域）」，只写「走近」模型会在同一背景原地拉近拉远来回横跳；手机持机手不重要（老板「手机哪个手不重要」），只锁手机状态与屏幕内容。**全片重新实测（FULLSCAN 模式）**：每镜 6+ 时点抽帧 + 走动镜加密 250ms 间隔 + 背景锚点对比 + 后期层时码 60fps 精确卡位 + ASR 台词核对（faster-whisper small 本地词级时间戳，禁止云转写），输出「实测 vs SHOT_REF vs 分镜」三列对照表 → 重出分镜以实测为准、SHOT_REF 只作对照。S06 这类被 UI 遮挡、重构机制不可验证的段，如实标注「不确定」不脑补。

**稀疏抽帧（0/10/14/35s 四帧）会漏真实切换点 → 分镜结构错误、台词归属错。**

实测：旧对照表「14s 切女主」是稀疏抽帧得出的；加密抽帧（1.5-2s 间隔 25 帧）后确认**实际 10.5s 已切女主**（此值仍为 vision 近似，codex 像素 MAD 实测精确定为 **10.05s**——以 SHOT_REF 为准）——切换点差 3.5s，「火龙币也能直接换成现金提走」那句实际是女主段台词，归镜1 就错。

规则：
1. **拆片按关键帧驱动抽帧**（2026-08-26 用户「需要每帧都拆」）：先 `ffprobe -show_frames` 拉全部 I-frame 时间戳，关键帧±1帧 + 0.5秒间隔补抽（40秒视频≈118帧）。旧法1.5-2s间隔会漏UI层变化/画中画/字幕大字变化。详见 `references/keyframe-extraction-method.md`
2. **切换点用相邻帧验证**：前一帧 A 人物、后一帧 B 人物 → 切换点在两帧之间，取较早帧为准
3. **分镜/对照表以加密核验为准**，不沿用旧对照表的切换点（旧表可能抽帧不够密）
4. 运镜判断用**拼图法**：一段帧拼 5 列大图（PIL tile），一次 vision 看整段（人物占比变化=推拉、背景位移=摇移），比逐张看高效
5. 分镜里的运镜/动作细节必须来自逐帧核验，不是设计发挥——「复刻」= 逐帧照原片，只换目标用户相关的人物/场景/演绎
6. **人物位置是核验必列项（2026-08-22 老板批「说了让你去分析原视频人物的位置」）**：除了景别大小，还要逐帧记录**人物在画面中的位置**（横向居中/偏左/偏右、头部在画面什么高度、人物朝向、手机位置）——prompt 里写「人物位于画面右侧三分之一」「正面平视」「头部留白约五分之一」这类位置约束，只写景别（中近景）不够，Seedance 默认构图会偏
7. **拆片/原片分析是 codex 的活，Hermes 不自己抽帧+vision 粗糙判断（2026-08-22 老板「开始分析视频是谁分析的？」）**：原片拆解（下载/抽帧/转写/画面分析/人物盘点）历史上由 codex 执行（TASK.md 标注「执行者：codex」）。Hermes 只做调度，**分析类（含运镜/景别/人物位置核验）外包 codex**——Hermes 自己 vision 判断容易粗糙（本次两次结论冲突），且违反智力活外包原则。Hermes 可做的是给 codex 派任务书时把「必须逐帧核验人物位置/景别/运镜并量化」写进要求。

## ⚠️ 样片必须跟原片逐帧对比景别/运镜（2026-08-22 老板「你这个运镜哪里是跟原视频一样啊」）

**Seedance 样片出来后，prompt 写了运镜 ≠ 运镜对齐原片。** 实测：prompt 写「持续匀速推近」样片确实推近了，但起幅景别比原片远（样片 1s 中景 vs 原片 0s 中近景人物占 1/2）、推近幅度比原片猛（推到脸部特写，原片只推到站立中近景）——老板一眼看出「运镜跟原视频不一样」。

规则：
1. **样片抽帧（1/3/5/7/9s）+ 原片同时间点帧，拼图或并排 vision 对比**：逐帧问「景别/人物占比/可见部位」，差异列出来（起幅远了/推太猛/角度不同/动作时序不对）
2. **起幅景别要显式写进 prompt**：「中近景起幅（人物胸部以上占画面约一半，头顶留约五分之一空间）」——不写起幅，Seedance 默认从更远的中景起
3. **推近幅度写「克制」**：「极缓慢轻微推近，推近幅度克制，镜头几乎不动」+ 落幅约束「落幅仍是中近景站立构图，不推到脸部特写」
4. vision 对景别判断可能两次冲突（1.5s 间隔说推近、1s 间隔说拉远）——冲突时用单帧精确问「头顶到画面顶距离/可见部位」裁决，不要凭感觉
5. 对比确认差异 → 改 prompt 重出（改运镜描述后重出是正常流程，不是返工浪费）

## 付费出片前人工闸（2026-08-17 火龙复刻实测，老板「先发一段来看看」「提示词发出来看看」；2026-08-22 增补分镜确认闸）

烧付费 API 前，先给老板确认，别闷头整片生成：

> ⚠️ **分镜确认闸只卡「付费出片」，不卡「拆解→分镜→提示词」的前置产出（2026-08-24 老板「拆完后直接出分镜脚本和提示词」定案）**：复刻类任务老板明确「拆完参考视频直接出分镜脚本和提示词」时，**中间不来回停下确认**——拆解→分镜→提示词一条链跑完再交付；分镜确认闸在「出片/调用付费 API」前生效，不是每个中间产物都要停下等确认。任务书按「拆→分镜→提示词一次产出」打包，别在拆解完问「要不要继续」。

0. **🔴 分镜脚本确认闸（2026-08-22 老板连续批「你现在怎么跟小鹿一样 不需要确认就跑」「我让你先出分镜脚本 你就跟我跑镜头」）**：**分镜脚本必须经老板确认后才能出片（含样片）**。写分镜 → 发老板审 → 老板说「出/跑」→ 才调 Seedance。禁止「写了分镜直接跑镜头」。老板说「先写分镜脚本」= 只交付分镜等确认，不碰付费 API；老板说「出了镜1 才知道对不对」≠ 授权直接出片——先确认分镜，再出镜1。流程铁序：拆原片 → 分镜脚本 → **老板确认分镜** → 出片提示词发老板审 → 样片 → 全片。本次实证：分镜未确认跑了镜1 样片（3 次付费），老板批「不需要确认就跑」——付费操作前确认是红线，分镜确认是第一步。
1. **出片提示词先发老板审**：Seedance 分镜 prompt（人物/场景/台词/绕检写法）写好后，**先发老板看**再调用——老板会当场挑出结构问题（如台词试读超时未拆段、绕检写法漏了）。prompt 里要含：参考图1/图2 路径、彩铅还原写实句、台词（英文双引号）、开场停顿、负面词。
2. **先出 1 段样片验证再全片**：不要一次生成全部镜头——先用锁脸图出 **1 段样片**（如开场第一句口播，Seedance 直接配音）发老板，验证人物对不对/口型同不同步/配音对不对，OK 后再批量逐镜。样片不合格就调（人物形象/提示词/绕检），避免 8-12 镜全生成后返工烧钱。

彩铅三视图等**中间绕检资产不用发老板**（「彩铅图不用发了」）——老板只关心定妆图（人物长什么样）和最终样片/成片。
