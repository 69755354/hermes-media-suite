# 头条图文配图通用标准（2026-09-05 天行者定案）

## 触发

头条图文配图制作时使用。

## 配图数量与尺寸

| 配置 | 数量 | 适用场景 |
|:---|:---|:---|
| 标准 | 3张 | 短-中篇文章，够用 |
| 最优 | 4-5张 | 阅读停留、收藏数据表现更好 |
| 上限 | 不超过6张 | 过多造成加载长、划读疲劳，反而拉低读完率 |

**尺寸规格：**
- **所有配图统一 800×800 正方形**（封面、正文信息卡、插图全部 800×800）
- **多张图必须颜色统一、风格一致**：同一组配图用同一套配色体系和底色风格，不要深色白底混搭
- 禁止大段文字堆一张图上，手机看不清

## 封面图规则（2026-09-07 天行者定案）

- **封面图 = 正文第一张图，不额外做封面专用图**
- 三张正文图全部可以当封面用，用户在头条编辑器自己选哪张做封面
- 正文第一张图放在开头第一段后面（头条编辑器默认抓正文第一张图当封面候选）
- **不再做900×500横版封面专用图**，统一走800×800正方形

## 实操建议

1. 正文第一张图放开头第一段后，当封面候选
2. 正文优先放信息卡（分档卡、案例卡等），是提升收藏的核心
3. 可选再加一张行动清单卡，总共4张图足够
4. 优先做文字信息卡，少用网图，规避版权
5. 信息卡内容来自文章本身的真实数据/来源，不脑补

## 信息卡制作流程

用 html-to-image-render 技能渲染：
1. 写 HTML（纯CSS+HTML，不用外部字体）
2. playwright 截图 → PNG（device_scale_factor=2 出高清）
3. vision_analyze 逐张检查（文字是否溢出/裁切/对齐）
4. 有问题改 HTML 重截，全过才交付

## 实操案例

3张图配置（社保医保文章）：
1. 冲突对比图（800×800）：深色底，左右对比核心数字冲击（如¥0 vs ¥14153）
2. 分档卡（800×800）：4行竖排，每行档位+说明+金额
3. 案例卡（800×800）：时间线展示真实案例金额对比

所有图统一深色底、统一配色体系（绿→黄→橙→红递进）。

## 与自动化产线配图链的关系

- 自动化产线走搜索真实图（A0素材来源页 > A1豆包搜索 > B Commons兜底）
- 手动配图/信息卡制作走HTML渲染，内容来自文章本身
- 两种方式互补：事件图走搜索，信息卡走渲染
- 最终交付都是图片文件，由用户在头条编辑器手动上传

## 配图质检纪律（2026-09-07 定案）

- 每张图生成后必须 vision_analyze 逐张检查：文字是否重叠/出框/乱码、数字是否正确
- 三张图必须颜色统一、尺寸统一（800×800）
- 检查全过才发用户，禁发未检图

## 交付格式

- 图片文件通过 MEDIA:/absolute/path/to/file 发送
- 用户复制到本地后在头条编辑器上传
- 不发服务器路径文本
- 不发 Markdown 图片语法
