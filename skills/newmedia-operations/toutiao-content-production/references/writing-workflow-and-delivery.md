## 二、对生产流水线的强制要求

- 出稿**必须内置深度改写环节**（喂真人风格、加案例细节，避开低困惑度）——对应「喂养AI原创写作/拟人化/去AI味」提示词
- **产出禁标 AI**（天行者 2026-08-19 定案）：文章文件不带「AI生成/AI辅助」字样；发布时平台若要求勾选 AI 声明，由客户自选，产线不代选不设硬项（见「一之补」）
- 禁止同模板批量灌水（账号行为分析会抓）
- 禁止 AI 编造数据/事件
- 头条首发（图文）项目：写文章不需要视频；视频工具只用于 ①视频文案提取当素材 ②文章转视频多平台分发（可选）

### 教程原版角色设定与投喂式prompt（2026-09-07 教程补全）

教程给AI设定了完整的角色链和两段式投喂prompt，派codex写头条文章时必须沿用：

**写作两段式：**
1. 第一段喂对标文章→AI当"文本分析大师"学结构
2. 第二段正式写作→AI当"热点文章写作大师"分三部分写（事件概述/内容主体/争议结尾），每部分写完暂停等人工确认

**六个技能角色：** 文章结构优化大师/写作手法优化大师/写作风格优化大师/评论大师/搜索联网/技能固定——任务书必须完整写入，不能只写"按教程方法写"

**标题两段式：** 先喂10-20个爆款标题→AI当"标题分析大师"拆A+B+C结构和6元素（金钱/生死/异常/对比/转折/刺激）→再按素材生成10个标题

**投喂纪律：** 两段分开投/六个技能不能省/每段写完暂停等确认/对标由人选不由AI找

完整prompt模板和技能角色原文见 `references/tutorial-role-prompts-20260907.md`。已整合进方法论文档 `toutiao_methodology_v1.md` 第三章"第二步半"。

### 🚨 人工润色 = 方法论里已有的专门方法（2026-08-19 用户连续追问确认）

深度改写不是新发明——客户方法论里**有专门的人工润色方法文档**，两个环节：
1. **「AI拟人化提示词」文档（10 条改写指令）**：人工看完 AI 稿，对不满意段落挑对应指令让 AI 重写（加口语/语气自然/对比手法/比喻/转折刺激/吸引眼球/方言/生动具体/心理活动/幽默轻松）。链接 `https://m59itnl68e.feishu.cn/docx/MzzBdfPqDopcdAxbXNEc0QLmnDf`（原文标题「ai拟人化的写作方式」）。
2. **喂养AI原创写作的分段确认**：AI 每写完一部分必须问人工意见，满意才继续下一部分，不满意按人工要求重写。

完整链路：**AI 分段写 → 人工审 → 不满意用 10 条指令改 → 满意过 → 下一篇段**。做流水线/派任务时必须把人工润色写成显式环节（不是「深度改写」一句带过），这是让文章困惑度正常、有真人温度的核心，直接对上四层滤网第 1 层。

### 冷启动互动钩子规则（2026-09-05 数据复盘定案，优先级最高）

**背景**：头条冷启动数据证明，点击率24%+读完率71.8%双优，但零互动=零放大流量=卡在25展现。互动行为（评论/收藏/转发）是算法放大流量的必要开关，高点击+高读完只是入场券。

**产线硬要求**：每篇文章结尾必须埋互动钩子结构，包含两层：
1. 评论钩子：围绕核心痛点提一个开放式问题，制造评论动机。示例："你试过哪条路？踩了什么坑？欢迎留言聊聊"
2. 收藏引导：一句话告诉用户收藏后能用来做什么。示例："收藏这篇，下次想动手时拿出来照着挑路径、算成本、避开坑"

**禁止的反面**：结尾只留一个开放式提问但没有评论动机设计（"你怎么看？"太弱），或结尾升华总结收场（"AI时代来了，拥抱变化"=零互动）。

**与"去AI味"的关系**：评论钩子和收藏引导不是"点赞收藏式AI引导"——那种是"求关注求点赞求转发"的乞讨式话术。互动钩子是设计具体的评论动机和收藏动机，两者必须区分。去AI味环节（05_deai_card）不得删除互动钩子，格式回炉（09_format_rewrite）不得删掉钩子。

**自检标准**：03_selfcheck 的"共鸣度"维度，结尾缺少评论钩子或收藏引导时不得高于60分。

交付格式：头条文章发用户时用纯文本，禁 Markdown 符号（2026-09-04 用户纠正，2026-09-06 再次违反——用户原话「说了不要带星号这些」，交付前必须 sed 去 ** 再发，这是硬规则不是建议）

**⚠️ 长正文用文件附件交付，不要发聊天消息（2026-09-06 用户原话「这种格式我复制过去都搞一起了」）**：飞书聊天里发长正文（1000字+），用户复制到头条编辑器时段落会粘在一起丢失换行。正确姿势：存成 .txt 纯文本文件，用 MEDIA: 发附件，用户打开文件复制就不会丢格式。短文本（标题、几句话）可以发聊天，长正文一律走文件附件。

头条编辑器不渲染 Markdown。飞书聊天里用 `**加粗**` 发的文本，复制到头条编辑器会原样显示 `**`，很难看。交付文章正文给用户（用于复制粘贴到头条）时：

- 去掉所有 `**` 加粗标记——头条编辑器用自带按钮加粗，不用 Markdown
- 去掉所有 `##` / `###` 小标题标记——小标题就是「一、二、三、」独立行纯文本
- 文章正文用纯文本，段落间空行分隔，不加任何 Markdown 语法

产线内部 `format_gate` 仍用 `**...**` 检查加粗（内部质检口径不变），但最终交付给用户的文本要 strip 掉所有 Markdown 符号。

**⚠️ 去Markdown时禁止用emoji正则删字符（2026-09-06 实测血泪教训）：**
- 用 `re.sub(r'[\U0001F600-\U0001F64F...\U00010000-\U0010ffff]+', '', text)` 删emoji会**把所有汉字也删掉**——汉字扩展集（CJK Unified Ideographs Extension B-F）在U+20000-U+2FFFF范围，被emoji正则的范围覆盖到
- 1735字文章跑完只剩95字节，全是数字和标点
- **正确做法**：只做 `text.replace('**', '').replace('👇', '').replace('⚠️', '')` 等逐个替换具体emoji字符，不要用宽泛unicode范围正则
- 或者用 `emoji` 库（`pip install emoji`）精确匹配emoji字符，不影响汉字

### 评论欲望设计：钩子不只放结尾，中段也要截（2026-09-05 实测）

冷启动互动钩子规则要求每篇结尾埋评论钩子+收藏引导。但只放结尾不够——读者读到结尾时可能已经没有表达欲了。

**中段钩子技巧（03篇实测有效）：**
- 在读者最有「脑补答案」冲动的位置截住。例：5个问题刚列完，读者脑子里已经在回答→此刻插一段「看到这里你是不是已经蹦出一个答案了」→引到评论区
- 结尾钩子用真实案例引发冲动而非直接要评论。例：「一条仓库管理的评论底下盖了四十多层楼」比「请在评论区留言」有效得多
- 钩子要让读者觉得留一条评论有具体回报：「我每条都会帮你往下挖两层」「你能在别人的留言里找到搭伙的人」

**禁止的反面：**
- 干巴巴「欢迎在评论区分享你的看法」=零动机
- 结尾只问「你怎么看」=太泛太弱
- 升华式结尾（「AI时代来了拥抱变化」）=主动杀死评论欲
