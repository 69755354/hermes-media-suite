# 头条合集策划工作流

## 触发条件
用户说「搞成一个合集」「做成合集」「整理成系列」时触发。

## 核心步骤

### 1. 盘点已有文章
- 读取 runs/ 目录下所有已产出文章的标题、日期、选题ID
- 标注每篇的品类（实操类/避坑类/认知反思类/行业分析类）
- 确认已发 vs 待发状态
- **读全文**：不仅看标题，要 cat/read_file 每篇完整正文，后续要全文塞进任务书

### 2. 确认合集主题
- **关键**：用户会给出一个聚焦主题，不要自己泛化
- 本项目案例：用户从「副业合集」收窄到「用AI做副业」合集
- 已有但不在主题内的文章不要硬塞进合集，另开合集或独立发布

### 3. 打包任务书派Codex
任务书必须包含：
- 合集主题（用户原话，不要添油加醋）
- **所有已写文章的完整正文逐字粘贴**（不是摘要）——codex需要看到实际散文才能判断角度重叠，摘要不够
- 每篇已写文章的定位标签（角度：总览/行业背景/方法论；作用：合集第几篇）
- 要求产出：
  1. 合集结构设计（10-15篇，每篇含标题/层级/解决问题/衔接关系/角度边界）
  2. 写作顺序（考虑冷启动：前3篇要有争议性和共鸣感，品类交替）
  3. 差异化设计（每篇核心数据来源方向+互动钩子方向；角度去重表：每篇一个唯一动作，标注禁止扩写到什么）
  4. 合集核心差异化与读者价值闭环
  5. **事实风险审计**：逐篇标注已写文章中哪些数据/断言需要发布前核验或更新
- 合规提醒：AI内容标识办法、个人信息保护法、收入声明真实性
- TASK_TYPE=分析（过闸用）

### 4. 派活命令
```
codex exec --skip-git-repo-check -c model_reasoning_effort=high -c sandbox_mode=danger-full-access "读取 inputs/brief_xxx.md，按里面要求执行。产出写入 outputs/xxx.md，结尾用 OUTPUT: 标注路径。" 2>&1
```
- effort=high 需5-6分钟，stdout前期为空是正常的
- codex会独立联网搜合规数据源（AI内容标识办法、个人信息保护法、著作权案例等），这是预期行为
- 用 background=true + notify=true 跑，不阻塞会话

### 5. 头条合集平台规则（2025-2026）
- 头条文章和视频均可创建合集，微头条不行
- 目前无明确粉丝/文章数量门槛
- 在头条创作者后台直接操作
- 合集内文章按发布顺序排列

### 6. 合集封面生成
合集需要一个封面图（900×500横版）。生成流程：
1. 写 HTML 文件（`/tmp/collection_cover.html`），用 CSS 渐变+网格背景+主标题+副标题+流程链
2. 用 playwright 渲染截图：`node -e "const{chromium}=require('playwright');(async()=>{const b=await chromium.launch();const p=await b.newPage({viewport:{width:900,height:500}});await p.goto('file:///tmp/collection_cover.html');await p.waitForLoadState('networkidle');await p.waitForTimeout(2000);await p.screenshot({path:'<output>.png',type:'png'});await b.close();})()"`
3. 用 vision_analyze 自检：文字完整可读、渐变色正常、布局无重叠截断
4. 发飞书用 `hermes send --to feishu "MEDIA:/path"`
- 设计风格：深色科技风（深蓝底+紫渐变高亮关键词），适配AI副业主题
- 封面要含：合集名称、副标题（篇数+一句话）、底部流程链（5步胶囊）、右下角篇数标识

## 事实风险审计（codex产出关键部分）

codex的合集计划产出中会包含已写文章的逐篇事实风险标注。这是高价值环节——已写文章可能在以下方面有问题：
1. **数据过时**：如Gartner AI支出预测已有更新版本，原稿用了旧数字
2. **断言无来源**：如「3个月零收入是常态」「90%因过早放弃」——没有可确认的原始样本支撑行业事实
3. **收入区间需回原始订单核验**：销售额≠利润，需分开
4. **处理原则**：找不到来源就删/改成个案观察，不把多个不同口径拼成同一条趋势线

## 互动钩子铁律（冷启动）
合集内每篇文章结尾必须埋：
1. 评论钩子：制造评论动机的开放式问题（让读者交代身份+具体经历+下一步选择，不问泛泛的「你怎么看」）
2. 收藏引导：必须对应一张能再次使用的表或清单，不用空喊「干货建议收藏」
- 去AI味和格式回炉环节不得删除钩子

## 品类多样性与发布顺序
合集内文章品类应交替，避免连续多篇同类。发布顺序≠目录顺序：
- **发布顺序按冷启动优化**：前3篇选争议强/共鸣高的（避坑类优先拉评论，认知反思类拉收藏），实操类放中段
- **目录顺序按行动链排列**：读者从认知→避坑→实操→进阶的逻辑顺序
- 合集目录固定1→N，实际发布可打乱

## 角度去重规则
每篇合集文章只回答一个动词（如「看路」「验需求」「算报价」），编辑时用它判断是否跑题。任何新资料若不能归入已有动词，不硬塞进正文，进候补选题库。

## 单篇范围收窄纪律（2026-09-05 用户三次纠正）
合集计划定了每篇的定位和角度边界，但写正文时仍容易扩写超出范围。用户会反复收窄：

1. 初版往往把「挖+用+选+做」全写了 → 用户说「太片面/太宽」→ 砍
2. 砍了一轮还有残留 → 用户再纠正 → 再砍
3. 最终用户说「这篇文章就写X」→ 整篇重写，只写X

**执行规则：**
- 派codex写合集单篇时，任务书必须显式写「禁止写XX/XX/XX」列出禁止扩写的方向
- 用户说「重新写」=从零重写，不在旧版上修补
- 角度迭代3次以上说明任务书的范围定义不够窄——下次派活前先把范围砍到一句话
- 合集衔接关系（前篇→本篇→后篇）是天然的边界：本篇只做衔接链上的一个环节，不做下游环节的事

**03篇案例：**
- 合集结构：01全景→02行业变化→03挖能力→04筛假项目
- 03的动词只有「挖」。但初版写了挖+杂交+做交付+选行业→被纠正三次→终版只写5个问题→AI追问两层→能力考古→隐藏能力清单
- 正确范围：挖到清单为止。「怎么用清单做副业」是下一篇的事

## 评论欲望设计（2026-09-05 实测补充）

合集每篇结尾埋钩子是硬要求（见「互动钩子铁律」），但钩子设计本身需要技巧：

1. **中段截击**：在读者最有表达冲动的位置插钩子，不只在结尾。例：5个问题列完→读者脑里已有答案→此刻插「你是不是已经蹦出一个答案了」
2. **结尾用案例**：用真实感案例引发评论冲动（「一条仓库管理的评论盖了四十层楼」），比直接要评论有效
3. **评论回报具体化**：让读者觉得留评论有具体回报（「我每条帮你往下挖两层」「你能在别人留言里找到搭伙的人」）
