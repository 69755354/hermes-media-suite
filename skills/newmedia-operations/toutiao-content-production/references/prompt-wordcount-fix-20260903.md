# Prompt字数指令冲突修复 2026-09-03

## 问题
GLM 初稿写 3078 字（目标 1450），三部分各写 ~1000 字加起来远超 1600 字上限。

## 根因
`prompts/02_feed_write.txt` 模板 83 行很长，中间第 67 行写了「全文汉字数以 {{WORDCOUNT_TARGET}} 字为目标」（渲染后 1450 字），writer.py 在模板末尾追加分部额度「本部分必须为 195-240 字」。**两个字数指令冲突**——GLM 执行了中间的全文字数（1450），末尾的分部额度被淹没。三部分各按 ~1450 字理解 → 各写 ~1000 字 → 合计 3078 字。

模板还写了「按以下顺序输出三个部分」——但实际是分三次调用每次只写一个部分，这条指令让模型以为要一次性输出全文。

writer.py 代码注释已写「模型对长提示词中部的额度执行弱」但没根治。

## 修复（codex 实施）

### 改动点
1. **删掉全文字数固定值**：模板中间不写「全文1450字」，改成「合并后全文满足」（用占位符动态注入）
2. **删掉三部分输出指令**：「按以下顺序输出三个部分」→「当前调用只写末尾指定的一个部分」
3. **字数唯一标准**：只执行末尾动态注入的「本部分必须为X-Y字」，明确写「任何全文档位、示例长度和素材长度都不是当前输出的字数指令」
4. **末尾指令最高优先级**：明确声明「提示词末尾的「本次只写」与「本部分必须为…字」具有最高优先级」

### diff 关键行
```diff
-文章分为三个部分进行写作
+最终文章由系统分三次调用生成；当前调用只写提示词末尾指定的一个部分

-全文汉字数以 {{WORDCOUNT_TARGET}} 字为目标
+合并后全文2-4个一级小标题（三部分合并后满足）

-按以下顺序输出三个部分
+系统会在本提示词末尾追加「本次只写：某个部分」及该部分的字数额度
+
+字数唯一标准：只执行提示词最末尾动态注入的「本部分必须为…字」
+提示词末尾的「本次只写」与「本部分必须为…字」具有最高优先级
```

## 验证
- codex 验证：渲染后提示词不再出现全文 1450 或 1300-1600 字数指令
- test_format_rewrite.py 20/20 通过

## 重跑结果
修复后初稿仍超（1851字 > 1600上限），但格式门回炉3次从1851裁到1431字，格式门 PASS。比修复前（3078字）明显改善。

## 教训
1. **模型对长 prompt 中部的指令执行强、末尾追加指令执行弱**——字数指令不能放中间，末尾追加的要更强硬
2. **分次调用时模板不能写全文字数**——模型会按全文字数理解，每部分都写满
3. **字数指令必须清晰唯一不矛盾**——中间不能有固定全文字数干扰分部执行
4. **「按以下顺序输出三个部分」会误导模型**——分次调用时要明确说「只写当前部分」
