# 多渠道工作流设计（2026-07-16 沉淀）

## 背景

原工作流默认走抖音。本会话将工作流改造为支持6个渠道的多选+顺序适配模式。

## 支持的渠道

| 渠道 | 内容形式 | 核心差异 |
|:----|:--------|:---------|
| 抖音 | 15-60秒竖屏视频 | 快节奏钩子，每5秒新信息点，完播率驱动 |
| 快手 | 15-60秒竖屏视频 | 老铁文化，越真实越好，老板/店员出镜 |
| 小红书 | 图文（6-9张图）或 15秒-3分钟视频 | 种草/攻略风，emoji分段，CES评分驱动 |
| 视频号 | 30-60秒视频 | 社交裂变，转发权重高，评论区理性 |
| B站 | 3-10分钟中长视频 | 干货/深度，年轻用户，批判性评论 |
| 公众号 | 图文长文 | 深度内容，标题+正文+图片排版，无视频 |

## 入口流程

```
客户说需求
  ↓
① 实体店还是自媒体？
  ↓
② 发哪些平台？（可多选）
  ↓
├── 选了多个 → 追问顺序
└── 只选一个 → 跳过
  ↓
③ （仅小红书）图文还是视频？
  ↓
节点0：渠道选择→定位判断→回头客预检
  ↓
新客户→节点1采集信息 | 老客户→直接复用
  ↓
（多选时）做下一个渠道→重复
```

## 节点编号（2026-07-16 重编号后）

| 节点 | 名称 | 说明 |
|:----|:-----|:-----|
| 节点0 | 渠道选择+定位判断+回头客预检 | 新加，客户说清了就不问 |
| 节点1 | 按渠道采集信息 | 原节点0移过来，仅新客户 |
| 节点2 | 用户分析 | 原节点1 |
| 节点3 | 爆款拆解 | 原节点2，按渠道搜 |
| 节点4 | 选题 | 原节点3 |
| 节点5 | 文案（含人设） | 原节点4，按渠道换风格 |
| 节点6+ | 分镜→生图→提示词→合规→视频→合成→检验→交付→发布→复盘 | 顺延 |

## 信息采集差异

不同渠道在节点1问不同的问题：

- **抖音/快手**：门头照、店内环境、招牌菜、价格
- **小红书（图文）**：好看的菜品照、顾客拍过的图、特色故事、评价
- **小红书（视频）**：出镜人、最出片的角落、好评点
- **视频号**：出镜人、差异化卖点、老顾客故事
- **B站**：懂行的创始人/厨师、产品工艺、行业干货
- **公众号**：开店故事、产品原料、创始人背景、媒体报道

## 小红书适配分析（三轮自检结论）

原有工作流缺3个功能：图片制作节点、关键词布局、封面点击率优化。需新增7份知识库文档。

## 客户交互原则

- 客户说清楚了就不问
- 定位/人设类问题自己分析，不问客户
- 新客户首次对话告知支持的平台和内容形式
