# 记忆 / Wiki / SOUL.md 三权分工

> 本会话（2026-07-11）用户纠正的核心问题：用错了存储层，导致「不是不记得，是没去调」。

## 三层的用途和禁区

| 层 | 用途 | 禁区 |
|:---|:-----|:-----|
| 🧠 **记忆** (memory) | 全局刹车规则、行为禁令、用户偏好（如：「用户极度反感跳步骤」） | ❌ 不准存项目细节（地址/电话/套餐） |
| 📁 **Wiki shop-info/** | 每个客户的独立档案（店名/地址/电话/套餐/实景描述/合规红线/历史记录） | ❌ 不准在memory里再存一份 |
| 📜 **SOUL.md** | 永久行为规则，比记忆更硬（如：第9条自动wiki恢复铁律） | ❌ 不需要频繁改，不存临时规则 |

## 触发路径

```
用户提店名
    ↓
【SOUL.md 第9条铁律】  ← 自动触发，不可跳过
    ↓
read_file(wiki/shop-info/<店名>.md)
    ↓
有档案 → 全量恢复，不问用户
无档案 → 走采集流程
```

## 为什么不能依赖记忆

记忆的问题（本会话已验证）：
1. **容量限制**（2,200字符）→ 存不下完整项目信息
2. **碎片化** → 只记得关键词，拼凑容易漏（如漏了合规红线）
3. **容易过时** → 用户更新了价格/套餐，记忆不会自动更新
4. **不区分项目** → 多个项目混在一起更难找

## 正确答案

- **wiki shop-info/** = 完整、可维护、可追溯的项目档案
- **记忆** = 只存让你「会去读wiki」的刹车规则，不是存wiki里的内容
