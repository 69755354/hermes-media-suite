# 抖音自动发布 worker 部署（浏览器自动化执行层）

> 2026-08-21 实测沉淀：NewMe 短视频自动化 skill 适配分析 → 单账号抖音试点部署方案。
> 触发：客户要求「自动定时发布」/ 抖音起号要自动发 / 把 NewMe 那套适配到我们工作流 / PUBLISH_OPERATE 节点执行层落地。
> 完整部署方案落盘：`workflow/projects/newme-adapt-analysis/本地生活单账号抖音试点部署方案_20260821.md`（310 行，20 条验收标准 + 9 个老板决策点）。

## 核心认知：自动发布 = 浏览器自动化，不是 API

抖音/视频号/小红书网页版没有给个人/企业号的「公开发布 API」。NewMe 那套自动发布是 **Playwright 驱动真实 Chrome 打开创作者中心网页，模拟人工上传/填表/点发布**。所以落地前提不是「写个脚本」，是「一台能跑真实浏览器的机器 + 登录态 + 人工值守」。

必须满足三件事：
1. 一台能跑 Chrome 的机器（电脑或服务器都行，见选型）
2. 登录态：发布账号先人工扫码登录一次，之后靠 cookie 保活（NewMe 有 login_keepalive/心跳脚本）
3. 人工值守：扫码、验证码、账号异常跑不了自动，必须留人

## 机器选型：常开电脑首选，当前新加坡服务器不当真发机

| 维度 | 服务器（新加坡 3.6G/2核/20G） | 常开电脑（Mac/桌面） |
|---|---|---|
| 内存 | 单个 Chrome 发布吃 1.5-2G，原保活代码要求启动前剩 ≥2G 可用；与产线共存余量不足 | NewMe 验证基线 8GB Mac 单 Chrome 串行；专机更接近 |
| 登录态/风控 | 机房出口 ≠ 账号常用登录地，切换设备/出口扩大验证码/掉线风险 | 放在账号日常使用地、固定网络设备，环境变化少 |
| 扫码路径 | 要远程可视窗口或短时可撤销二维码传递，链路复杂 | 值班人本地可视窗口直接扫码，路径短 |
| headless | 不能假设 headless 可用（视频号明确不可），需真实显示/虚拟显示 | 原生桌面会话天然支持 |
| Linux 交互差异 | Meta+a→Control+a、Mac UA/profile/路径/keychain 全要改；有 Chromium ≠ 抖音已可用 | 可复用更多 Mac 已验证经验 |
| 7x24/服务监督 | 机房稳，适合控制面/队列/审计/告警（systemd） | 要关睡眠、处理更新重启，GUI 会话恢复复杂（launchd） |
| 改造工作量 | 高：发布器/保活/扫码/键盘/显示/密钥/profile 全 Linux 化 | 中：客户化+审批门+回执+幂等+审计 |

**结论**：首选「账号常用登录地的一台专用常开电脑做浏览器 worker + 服务器做控制面」。当前 3.6G 服务器不做首期真发机。服务器作备选必须同时满足：内存 ≥8GB 基线、账号方确认出口可用、经验证的真窗口/虚拟显示 + 远程扫码、阶段 0-3 全过。

## 落地四阶段（任一不过不进下一阶段）

- **阶段 0：阳性对照门禁（不连真实账号）**——定义 publish_plan/StepResult/审批回执/幂等键/状态机；发布函数封装在硬门禁后，普通 adapter 不持有直接点击权限；每条绿判据配一个必红坏样本
- **阶段 1：登录、保活与人工扫码值班**——老板定 worker 机器+授权书；独立系统用户+加密 profile+账号注册表；人工登录登记；只读保活，掉线只告警不自动扫码不回灌 cookie
- **阶段 2：单条发布全链路**——固定测试素材 fill×10 且 10/10 全绿；账号方人工比对第 10 次 fill；一条低风险 canary 真发（账号方在场确认）；回读平台作品 ID 生成发布回执
- **阶段 3：定时任务与异常告警**——接入 PUBLISH_OPERATE，默认 manual_package，只有授权账号+有效批准才 approved_publish；fail-closed

## 四条人工门（自动化不许绕过）

1. **书面授权门**：账号所有者书面授权（允许动作/有效期/撤销方式），无授权只生成手动发布包
2. **内容审批门**：批准人逐条确认，审批令牌绑定内容 hash + 计划 hash，任何变化使旧令牌失效
3. **扫码值班门**：登录失效只告警留证，由指定值班人扫码；不自动刷新二维码
4. **首条 canary 门**：第一次真发必须账号方在场确认

## 关键验收判据（全部硬项）

- 发布成功 = 作品管理页能读到**平台作品 ID**；URL 跳转/toast/标题命中都不单独算成功
- 结果不确定（点击后断网/超时）→ 任务进 UNKNOWN 先回查作品管理页，未经人工确认不再次点击
- 幂等：同 account+platform+content_hash+schedule_at 重试不产生第二条作品
- 缺失值语义：不可得字段写 None+原因，真实 0 才写 0（不能拿旧快照掩盖本次抓取失败）
- 登录判据正面证据优先（账号名/头像/资料卡），URL 和营销词不能决定在线状态
- 凭证卫生：日志/截图/任务体无 cookie、密码、二维码、签名 URL
- 单浏览器与进程卫生：同账号一个写任务，结束后 profile 的 Chrome 进程为 0

## 复用 vs 重写（NewMe 仓库实测结论）

- 可直接借算法：schedule_target.py（单一窗口源/北京时间/130 分钟安全下限/14 天上限/明确报错）、detach.py、shot_index.py
- 必须重写：publish_*.py（三平台适配器、硬编码 Dubai/账号/路径/macOS 键盘）、login_keepalive（vm_stat→/proc/meminfo、Mac UA）、wx_login_remote（固定 COS/账号/secret 路径）、profile_guard（路径与锁重写）、_run.sh（→ 作业队列/服务监督）
- NewMe AGENTS.md 是金矿：假判据清单（上传完成≠出现重新上传、话题≠页面有 #xxx、封面≠弹窗消失、登录≠页面无营销词）、抖音发布键永不禁用（点下去就发，体检是唯一防线）、绝不 pkill -f chrome（精确杀 profile）、不回灌旧 cookie 快照、headless 不碰微信
