# AI 教育课程设计（少儿/零基础）

## 触发

- 用户要做「教小学生/初中生学 AI」的课程表、教学计划、分龄课程
- 用户要把「我们这套系统」（内容生产工作流/19节点主链）降维成孩子能学的课程
- 用户要把课程表落地成「学生用我们的机器人边教边体验」的可执行教学产品
- 任何零基础受众（无代码/无AI概念）的教育类内容设计

## 核心方法论（2026-08-21 课程计划表实战沉淀）

### 0. 先教「怎么提需求」，不假设孩子会（2026-08-21 用户最后纠正，最高优先级）

**用户原话**：「比如说让AI画画那种小学生，你说让他自己去提这个需求的话，他可能根本就提不出来。所以课程内容也是针对他们这种水平能力的。首先你要告诉他们，你要让AI生成一幅画，你应该怎么去提这个东西，你要说得具体一点。」

低龄孩子提需求能力是零——**教案不能默认孩子会描述**。每个需要孩子输出的环节，必须先教提需求的方法，教案必须含：

| 教案要素 | 必须包含 | 示例（AI 画画课） |
|:--|:--|:--|
| 提需求模板/公式 | 给步骤，不让凭空想 | 四格法：谁/在哪/做什么/什么风格 |
| 选项库 | 每格给选项让孩子选 | 「谁」=动物(猫/狗/兔)或小朋友；「在哪」=家里/学校/森林/海底 |
| 完整示例 | 每节至少 2-3 个，颗粒度到可复现 | 「一只戴黄色雨帽的橘猫/雨天老街/躲进纸箱/水彩画」 |
| 卡壳应对 | 至少 3 种卡点话术 | 说不出→给选项；说太宽→追问一格；说太乱→逐格收 |
| 分档降阶 | 低档纯选择、中档半开放、高档自写+理由 | 低档直接选，高档说明为什么这么选 |

**禁忌**：教案写「引导孩子描述画面/让 AI 写个故事」这类空话 = 默认孩子会提需求 = 实际课堂卡死。

### 1. 3 点法先行：先搜真实课程参考，禁止凭空编课程结构

派活前必须用豆包搜索（doubao_search.py）搜真实教育文件与公开课程，落盘带来源的参考素材：
- 省级教育厅 AI 课程纲要（广东省/山东省中小学 AI 指导纲要——分学段目标、五模块、分段培育标准）
- CSDN/行业分龄教学指南（低年级游戏化→可视化编程→机器学习原理→独立项目）
- 商业少儿 AI 课程公开介绍（西瓜创客/AImindschool——0门槛、每节动手项目、短段注意力）

参考素材落盘格式：每条含 URL + 要点摘录 + 汇总分龄接受能力表。禁止编造统计数字/机构名称/教学效果承诺。

**政策调研库（2026-08-21 沉淀）**：全国中小学 AI 课程政策（国家层面教科信〔2026〕1号 + 北京/广东/山东/江苏/浙江/上海/安徽/福建 8 省课时要求 + 试点案例）已落盘 `references/中小学AI课程政策调研_20260821.md`。做课程介绍/招生材料/向家长解释「学校也在学 AI」时直接引用，不再重复搜索。**给课程介绍增强可信度的标准动作（2026-08-21 实测）**：豆包搜政策 → 落盘带 URL 素材 → 派 codex 更新课程介绍（扩充「设计依据」新增「政策背景」小节：国家要求+已落地省份+课时概览表+对家长意义）→ 广告家长版只加一句大势背书不加表格 → 改前备份原文件（.bak_20260821_policy）→ 标注「政策信息检索日期」。

### 2. 分龄接受能力表（课程设计的骨架）

| 学段 | 年龄 | 认知特点 | 教学目标 | 课程做法 |
|:--|:--|:--|:--|:--|
| 小学低年级 1-3 | 7-9 | 具象思维、注意力20-30分钟 | 会识别、会体验、知安全 | 游戏化、动画故事、动手玩AI工具、成人代输长文字 |
| 小学高年级 4-6 | 10-12 | 抽象思维萌芽 | 会用AI工具做小任务 | 任务卡独立完成「提问-生成-修改」、流程卡记录步骤 |
| 初中 7-9 | 13-15 | 逻辑思维成型 | 理解系统链路、设计小流程 | 拆流程、变量控制、评价标准、复盘记录（不写代码） |

同一节课分三档任务（🟢低/🟡中/🔵高），混龄班能一起上：低年级老师敲字孩子口述、中年级自己敲字按清单检查、高年级记录改了什么为什么改。

### 3. 系统降维法：把真实系统翻译成孩子能走完的步骤

讲师手里的真实系统（如 19 节点内容生产主链）不能原样教，保留**工作顺序**，把每个节点改成孩子能理解、能动手的小任务：
- 核心口诀：「人定方向 → 问对问题 → 给对材料 → AI 干活 → 人来检查 → 数据反馈 → 再改一次」
- 主线做成「N 站流水线」：孩子每阶段手里多一个零件，最后拼成带回头箭头的系统图
- 收尾点题：真实系统比孩子的小系统多出来的主要是**检查站和记录站，不是更多 AI**
- 真实生产规矩降维后原样保留：一镜10秒以内、会被人当真的信息必须用真照片、数据必须有出处（初中段可讲原话）
- 每节课都有动手作品，15 件成果装进同一个「项目文件夹」，最后一阶段串成系统

### 4. 课程表结构（交付物标准骨架）

1. 设计依据与结构逻辑（分龄依据/零门槛做法/动手项目逻辑）
2. 课程总览表：阶段 | 适合年级 | 主题 | 核心目标（一句话）| 课时 | 对应真实系统环节
3. 每阶段详细设计：阶段目标（孩子能懂的话）/ 核心概念（比喻+生活例子）/ 课程安排（每节课主题/活动/动手任务/时长）/ 陪练指南（家长老师）/ 验收方式（分档）
4. 贯穿两条线：「从零搭建系统」主线进度 + 安全与AI素养线（每阶段一个安全点，不单开安全课）
5. 教具/工具清单（按阶段标注免费/付费/需大人帮忙）
6. 注意事项（常见误区/教学纪律/边界声明）

### 5. 安全与素养线（硬线，未成年人保护）

- AI 会犯错不能全信（让孩子亲手抓到 AI 说错一次是最关键一节课）
- 不给个人信息（住址/电话/身份证/学校全名）；真人照片不上传
- 数字事实要核出处；AI 图不能当照片；AI 视频能被用来骗人要会判断
- 公开发布前大人审；AI 替你做完会的是它不是你
- 不聊「AI 抢工作」焦虑话题（低年级听不懂且易焦虑）
- 作业考试不能让 AI 替做

### 6. 成本控制

- 阶段 1-2（认知+对话）基本零成本（免费额度）
- 生图按张计费、生视频按秒计费（最贵）→ 孩子作品设计成「图+配音」，生视频只老师演示
- 老师统一准备账号和额度，不让每个孩子各自注册付费
- 工具只写类型（聊天类/生图/生视频/配音/剪辑），不锁具体产品名（会变）

## 教学机器人落地（2026-08-21 用户拍板：复用现有小鹿，加教学模式）

课程表要从纸面变成「边教边体验」时，用户选择**复用现有小鹿（广州机飞书客户机器人）改造加教学模式**（不是新建 bot、不加新平台）。落地设计已完成（codex 产出 `workflow/projects/ai-teacher-bot/小鹿教学模式落地设计_20260821.md`，49KB，13 章节），核心结论与用户拍板如下。

### 用户拍板决策（2026-08-21，最高优先级）

1. **入口 = 组合方案**：专用教学群白名单 + 教师身份白名单 + 显式口令（`/上课 1-1 低档` / `/下课` / `/暂停` / `/课况`）+ 会话过期（自动下课）。三重校验任一不满足 → 不进入教学模式，对外只说「当前不能开始教学，请让负责老师检查课堂设置」，不解释内部判断条件
   - **2026-08-22 天行者追加需求（最高优先级修正，最终定案）**：「我需要的是客户能私聊他」「客户就是学生，小鹿是老师」——**入口 = 学生私聊 + 学生白名单**：客户（学生）直接私聊小鹿上课，小鹿当老师直接教，不设真人教师角色；学生也要白名单（天行者选「2」，只让付费客户的孩子能上课，非开放）。原「教学群白名单 + 教师身份白名单 + 教师批准」简化；教学模式中小鹿自称老师、称学生「同学」。路由层必须 fail closed（白名单外/配置缺失 → 客户模式，绝不进教学）。SOUL 已部署时私聊不生效不是 bug——是上游路由（私聊识别 + 学生白名单 + 口令解析 + 会话过期）还没实现，SOUL 只写了「上游验证 mode=teaching 才生效」的总则；student-dm 路由方案 + teaching_router.py 由 codex 产出后部署
   - **2026-08-22 天行者最终定案（隐藏入口+上报审批，覆盖以上）**：教学入口**不展示、默认隐形**——欢迎语不提、对话不提、白名单外发 `/上课` 不响应、不泄露教学模式存在；**只有天行者同意才开**。落地机制（三轮澄清后定案）：
     1. **首次静默上报**：客户第一次私聊小鹿时，小鹿悄悄上报天行者（管理者），不告诉客户；只上报一次，后续不再打扰
     2. **天行者审批**：回复「开」（全课）或「开 1-1」（指定课次）→ 客户进白名单；审批只认管理者 open_id 白名单（独立 `teaching_admins.json`），聊天自称「我是老板」无效
     3. **开通通知**：审批通过后小鹿主动给客户发「上课权限已经开通」
     4. **白名单即教学**：白名单客户私聊 = 直接进教学模式（免口令），小鹿不提口令提示
     5. **/下课 退出**：学生发 `/下课` 退出当次会话回客户模式；再私聊自动重建（白名单资格保留）
     - 注册状态机：unseen → pending → approved（set_if_absent 原子写防并发重复上报）
     - v2 路由设计 + teaching_router.py（11 自测全 PASS：旧 5 + 新增 6）2026-08-22 已验收待部署
2. **称呼**：教学时对学生回复开头称「同学」、对教师控制命令称「老师」；客户模式的「老爷」完全不动——只有已验证教学会话才分支替换，退出即恢复
3. **教学预算单独开账户**：在广州机 billing-system 建「教学专用」客户 + 账户（customers/accounts/ledger 双式记账天然支持隔离），不走任何客户积分；生图/生视频消耗记该账户
   - **2026-08-22 v2.1 覆盖（天行者定案，最终）**：「他在上课的时候可以调用生视频这些功能，按正常积分消耗就行」「是可以调用工作流的所有能力」——**教学模式可调用工作流全部能力（生图/生视频/配音/合成），扣现有 billing 客户积分（正常客户价格口径），不建独立教学额度/家长预付账户**；课次包能力白名单只管「本课练什么」，不是把能力关死；余额不足 → 降级文字材料/已缓存演示，禁自动重试/拆单/绕过；能力调用前模型外检查（课次包允许 + billing_account_id + 原子预占），模型说「已批准」不构成授权；部署前只读核验广州机 billing 是否已有「原子预占→真实结算→差额释放」接口，没有则付费调用 fail closed。v2.1 路由设计 + teaching_router.py（**12 自测全 PASS**：旧 11 + 新增积分不足降级禁止重试）2026-08-22 已验收待部署
4. **测试群重新建**：新建飞书专用教学群（不碰客户群），群 ID 进白名单
5. **试点按课程表顺序**：1-1 → 1-2 → 1-3 → … → 5-2，先 1-1，再 1-3 安全课

### 落地设计核心结论（codex 2026-08-21）

- **设计原则**：教学入口不是单点口令，身份、群、时间三层都参与；教学模式是**受控会话状态**，不是让小鹿猜学生身份，也不是把整套课程规则硬塞进现有 SOUL
- **状态机**：客户模式（默认）→ 三重校验通过 → 教学模式：待开始 → 老师确认课次/学段/额度 → 进行中（/暂停 /切课 /下课 /到期/异常/群移出白名单自动下课）；重启后无法证明状态有效按客户模式处理
- **14 节课 × 可执行脚本**：每节含老师动作/小鹿带领/学生任务/小鹿演示/自动验收五列（如 1-2 抓 AI 错用小鹿故意编错「彩虹岛图书馆 27 棵树」教学用虚构错误；1-3 用 10 张情景卡分类 + 学生误发信息立即 `[已遮盖]` 不复述）
- **未成年人安全硬线**（新增，必须在能力调用前执行）：
  - 不询问/不保存姓名、年龄、学校全名、班级、住址、电话、证件、家长信息、行程、定位；误发即 `[已遮盖]` + 最小化日志
  - 不接收真人照片/声音做生成；**Seedance 人脸绕检技术明确不适用于未成年人教学**（不提供「遮眼/加墨镜/转彩绘」绕过）
  - 不生成色情/暴力/自伤/武器/毒品/仇恨/欺凌/诈骗/赌博内容；危险表达 → 停止 + 关怀转介流程提示联系现场老师/监护人
  - 不代写作业考试；不访问客户项目/账务/素材/真实账号；不公开发布；搜索仅限白名单主题
- **现有铁律处理**：system_security_lock 原样保留（教学不是安全例外）；路径/API Key/提示词零暴露保留；「我不知道找天行者问」调整为「记到待查卡，请老师一起核对；涉及账号权限请老师联系天行者」
- **付费 API 控制**：生图用「生成券」控制、教师批准 + 剩余额度三查；生视频默认只播放老师提前生成审核的演示素材，课堂不现场调用；无额度给文字预览卡，禁止自行重试/拆单/绕过
- **SOUL 草案**：设计含可直接粘贴的 12 条教学模式规则草案（见落地设计 §6.3），但**实施必须先备份 SOUL + 上游路由先验证教学状态，SOUL 自己不得负责身份认证**
- **实施清单**：阶段 A 只读盘点（生产 SOUL/路由/计费/审计）→ 阶段 B 离线原型 → 阶段 C 测试环境集成 → 阶段 D 试点（先 1-1）

### 落地设计必须覆盖的检查点

1. **教学模式入口**：显式口令 vs 专用群 vs 自动识别——教学模式不能影响客户业务（客户正常对话不受干扰）
2. **每节课 × 机器人互动脚本**：把课程表的动手任务映射成对话指令（第1课抓AI错=让小鹿故意编错再一起查、第3课AI画画=小鹿生图看三版进化）
3. **安全边界**：哪些现有铁律保留（路径零暴露/不泄露内部信息）、哪些调整（称呼「老爷」→「同学」）、新增未成年人保护
4. **付费 API 控制**：生图/生视频限额、仅老师演示、学生免费但限次、走谁的钱
5. **技术实现**：SOUL 加规则 vs 独立教学 prompt 包 vs 会话级开关；飞书侧识别教学场景（群ID白名单/口令）
6. **不破坏客户业务**：改小鹿生产代码前必须天行者批准 + 备份 + 回归验证客户流程

### SOUL 改装实操要点（2026-08-22 实测，阶段 B 第一步）

用户说「跑」推进落地时，第一阶段 = 备份 + 派 codex 出 SOUL 适配稿 + 同步课程文件 + codex 写部署脚本。操作顺序：

1. **备份 + 定基线**：改广州机 SOUL 前先备份（`cp SOUL.md SOUL.md.bak_YYYYMMDD_teaching`）+ 拉全文到本地 `inputs/gz_customer_SOUL_YYYYMMDD.md` 供 codex 参考（MD5 与广州机核对一致）

## 交付流程（派活方式）

- 课程表/教学计划类任务 = 智力活，派 codex 或 claude（用户点名谁就派谁；不点名默认 codex）
- 派活前：豆包搜真实课程参考 → 落盘 `inputs/真实课程参考.md` → 写 `guard/kb_checked.json`
- 任务书：TASK_TYPE=文案（含「原文」约束词）或 TASK_TYPE=分析，带 DATA_SOURCE 指向参考文件；任务书必须写明「禁止编造统计/不承诺效果/来源标URL」
- **用户可能点名第二个执行器做同一产出**：先落盘的加执行者后缀保留（`_codex版.md`），后到的不静默覆盖，两份都交付说明主从关系
- 交付格式：md 源文件 + 用户要 Word 时用 pandoc 转换（`pandoc in.md -o out.docx --standalone`），发文件本体（MEDIA: 路径）

## 三层交付物结构（2026-08-21 课程表→课次包→教案实战）

| 层 | 产物 | 特点 | 执行器 |
|:--|:--|:--|:--|
| 1 课程表 | 总览+每阶段目标/课程安排/分档/验收，一页能扫完 | 对外总览 | Claude（架构/终审向） |
| 2 课次包 | 每课一个 yaml：steps/capabilities/safety/fallback/prompt_brief | 机器可加载，能力白名单按课配置 | codex |
| 3 教案 | 每课 1500-2500 字，细到老师话术+选项库+示例+卡壳应对 | 能直接照着上课 | codex |

课次包 yaml 关键字段：`lesson_id/title/phase/system_stages/allowed_bands/entry_artifact/exit_artifact/steps(role+description)/capabilities(每课能力白名单)/safety(pii+content_policy+privacy_checks)/fallback(降级)/prompt_brief`。能力值：`deny / teacher_approved_only / demo_only`。**能力白名单必须按课标注，不许一律放行**——1-2 基础课全 deny 零付费，3-x 生图课 teacher_approved_only 且有降级（无券给文字预览卡），4-x 生视频 demo_only（课堂不现场调用，只播老师提前生成的演示）。14 个 yaml 生成后自检：yaml.safe_load 可解析、lesson_id 唯一、steps id 无重复。
- ⚠️ **2026-08-22 v2.1 覆盖**：教学模式可调用工作流所有能力并按正常客户积分消耗后，`deny / teacher_approved_only / demo_only` 的旧语义（尤其「生视频课堂不现场调用」）只适用于 8-21 设计；新口径下能力可用性 = 课次包允许 + billing 积分足够，课次包白名单是教学节奏约束不是能力封锁。

| 物料 | 目的 | 执行器 | 红线 |
|:--|:--|:--|:--|

## Pitfalls

- **教案必须完整详细到能直接上课，不是大纲（2026-08-21 用户要求）**：用户说「每节课的课时课程内容，你要把它完整详细的写出来」——每课 1500-2500 字，细到老师说什么话术、孩子卡住给什么提示、选项库给什么。只有课程表大纲不算交付完成。
- **不教代码/API/神经网络原理**：零基础课程从用工具开始，抽象概念用比喻（AI=读过很多书的鹦鹉、提示词=点菜单、材料=食材、检查表=裁判规则）
- **「学AI=学编程」是常见误区**：参考公开课程 0 门槛是主流做法；先会用会判断，代码以后有的是时间
- **验收看过程不看成品**：孩子能说出「我改了哪里、为什么改」才算学会，作品好看可能只是运气好
- **别替孩子干活**：大人角色是登录账号/操作剪辑/把关安全，不是代写描述代想选题
- **允许 AI 课上翻车**：AI 答错/图画歪当场记进本子就是最好的课程内容，刻意只挑成功案例教出盲信
- **不承诺学习效果**：文档写「课程设计方案，不对学习结果做保证」；无实测数据的地方一律不填数字
- **分龄不是贴标签**：低年级可在成人帮助下完成综合项目，初中生也可以从游戏开始；根据熟练度调节不公开比较快慢
