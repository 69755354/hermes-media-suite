# 写作系统改进分析报告（2026-09-07 Codex 分析）

## 背景
对比外部AI内容流水线（6节点：选题→素材→初稿→精修→平台适配→发布）与我们现有17节点工作流，识别可借鉴点和改进方向。

## 核心结论
不砍节点，改架构："共享主干 + 母内容包 + 平台适配分支 + 视频按需分支"。

## 6项改进（按优先级）

### P1: 工时埋点
- 每个节点记录真实耗时、重试次数、回退次数
- 先量再改，结束凭感觉删节点

### P2: 母内容包+标准提纲+事实编号
- 不再“写一篇长文再改写”，而是先做“事实编号+内容块+母稿”
- 各平台从内容块取需要的组合，不新增未登记事实
- 六类提纲：知识教程型/案例复盘型/趋势观点型/产品转化型/对比选购型/故事情绪型

### P3: 平台适配器并行
- 一篇母稿→三平台版本（头条/小红书/抖音）
- 适配器允许重排内容块，用平台清单单独验收
- 消除重复劳动，一次研究多次交付

### P4: persona分层+范文检索
- persona从完整文件改成分层继承（全局→平台→内容类型→角色）
- 建立审核通过样本库，少样本范文优先于微调
- 减少反复调prompt，防风格漂移

### P5: 17节点改条件DAG
- 文章跳过分镜/生图/视频节点
- 合并界面不删除能力
- 硬门依据风险和交付物设置，不依据节点数量

### P6: 自检熔断按错误类型分流
- 不同错误类型走不同修复路径
- 减少无效自循环

## 实施风险
- 母稿错误被三平台放大 → 对策：事实编号+人工门
- 适配变成机械缩写 → 对策：允许重排+单独验收
- 范文库把旧错误固化 → 对策：只收终审通过样本+失效时间
- AI百分比变成虚假KPI → 对策：百分比只作容量设计，绩效看人工时间/一次通过率/回退率

## 验收标准
1. 三平台关键事实与母内容包一致
2. 知识库/合规/QC硬门不可绕过
3. 文章任务能自动跳过视频节点
4. 任一事实修订可追踪到所有下游版本
5. 主动人工时间/周期/一次通过率有真实日志
6. 试点业务指标不低于旧流程基线

## 证据边界
| 建议 | 结论等级 |
|:--|:--|
| 模块化母内容+多交付物复用 | ✅ 有标准依据(OASIS) |
| AI承担起草/整理可提效 | ✅ 有实验依据 |
| 保留人工复核 | ✅ 有权威框架依据 |
| 少样本范文优先于微调 | ✅ 有官方产品指南依据 |
| 六类提纲/AI百分比/人工分钟目标 | ❌ 内部设计假设，需埋点验证 |
| DAG改造节省幅度 | ⚠️ 方向正确待验证 |
