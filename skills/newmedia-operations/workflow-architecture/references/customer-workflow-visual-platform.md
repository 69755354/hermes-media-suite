# 客户运营工作流可视化平台（2026-08-16 天行者定案 + Claude 架构）

> 把内部 19 节点工作流做成面向客户的可视化 Web/小程序系统。客户=完全不懂运营的实体店老板。
> 注意：这是「客户用平台」方向，不是「AI 短视频一键生成工具」方向（后者见 ai-video-factory-productization.md，已被用户纠正为参考我们自己的工作流，不是参考对标链接一键生成）。

## 产品定位（需求讨论实录，勿再理解偏）

- **给客户用**（Web 优先、小程序后续套壳），当前我们内部测试（自己登进去模拟客户）。
- 客户是「输入需求→拿结果」的盒子：填需求（店名/行业/城市/卖点/素材）→ 最终拿成品。中间大部分节点不参与。
- **飞书只是过渡壳**（网页/小程序封装出来前的临时入口）；平台做好后客户直接网页/小程序操作，飞书退居内部工具。架构不跟飞书耦合。
- 开发流程（用户定案）：**Claude 出架构 → codex 按架构执行 → 老板看到可视化页面验收**。需求没讨论透前禁止派执行器（用户「你一直停一直跑」「先讨论完再让他做」）。
- 付费 API 等老板通知才开；当前阶段付费环节留开关（`PAID_API_ENABLED=false`），客户侧只显示「处理中」。

## 客户旅程（5 屏，Claude 架构裁定）

```
P1 填需求（三步表单：门店信息/卖点+主推意向/素材+授权硬勾选）
P2 我的项目（列表）
P3 项目进度（6 大阶段进度条 + 「专业展示」开关，可关只看进度）
P4 产出物展示（按阶段折叠，默认折叠）
P5a/P5b 软确认页 C1 内容方案 / C2 成片（[没意见，继续]/[我要修改]）
P6 交付页（下载 zip + 复盘提醒卡 T+1/3/7）
P7 复盘指引 / P8 帮助 / P9 素材管理
```

内部台 `/ops`：O1 待审队列 / O2 项目详情 / O3 付费放行（单单授权）/ O4 回退操作台 / O5 审计 / O6 开关（只读）/ O7 客户模拟。

## 客户确认节点矩阵（19 节点判定结果）

- **C-SOFT 客户软确认 3 节点，收敛成 2 页**：C1 内容方案（TOPIC_EXPERIMENT + COPY_PACKAGE 合并一页）、C2 成片（MEDIA_PRODUCTION）。
- **C-VIEW 可见不用确认 11 节点**（显专业）：PROJECT_CHARTER 建档、BUSINESS_DIAGNOSIS 体检、MARKET_INSIGHT 洞察、OFFER_PATH 主推、GROWTH_STRATEGY 打法、OPERATING_INFRA 待办、CONTENT_CALENDAR 排期、CREATIVE_BLUEPRINT 画面规划、DELIVERY_PACKAGE 交付、WEEKLY_REVIEW/MONTHLY_CLOSE（后续开放）。
- **C-HIDE 纯后台 5 节点**：MEDIA_PREP 制作准备、MEDIA_PRODUCTION 出片过程、LEAD/CONVERSION/RETENTION 线索成交复购（Phase1 占位不做）。

判定原则（先定原则再逐节点判）：① 客户不懂的不审（看不懂的字不让他签）② 策略方案类展示显专业（给看不给按钮）③ 内容产出软确认（凭生活经验能判断的给两按钮默认过）④ 付费/执行/技术环节客户侧不出现 ⑤ 法律授权（数字人/素材权属/资质）是**硬勾选**在表单完成，缺项物理阻断出片。

## 关键架构决策（Claude 裁定，codex 实现必须遵守）

1. **OFFER_PATH 不给客户确认门**——让老板审「单客贡献公式」= 签看不懂的字；把选择前移到表单字段「你最想让客人来买哪一项」（可多选可留空），OFFER_PATH 产出必须显式回应它。
2. **node8_image/node12_render 确认主体改内部运营**（改主体不改门）：`confirm_gate.py confirm` 由内部台调，`actor_type=internal_ops`；客户侧不渲染。⛔ **禁用 `confirm_gate.py skip`**（它是项目级全放行，会连带废掉 node4_copy 客户文案确认）——代码库 grep `confirm_gate.py skip` 零调用是验收项 D7。
3. **C2 成片软确认不改 confirm_gate**（存量无「成片后」确认点）：落平台自有表 `client_confirmations` + 编排层前置断言——**C2 未 approved 时禁止对 G_DELIVERY_READY 调 approve**，断言失败写 `blocked_by=c2_pending`。零存量改动，规则活在编排层必须有测试（验收 A7）。
4. **软确认行为契约**：默认超时自动过（`soft_confirm_timeout_hours` 默认 24h，演示 5 分钟）；**自动放行前置 = 已触达 ≥2 次**（站内+飞书过渡通道），审计记触达证据；「我要修改」必填文本+勾选改哪块（拍什么/说法/错字 → 按 rollback_matrix 精确回退）；修改次数默认上限 2 次，超限转人工介入；`auto_advance_all=true` 全自动过（免打扰模式）；**机器事实比对兜底**（文案价格/地址/电话与 A_STORE_FACTS 不一致，客户点了没意见也不放行）。
5. **客户侧只见 6 大阶段**（S-A 建档 / S-B 摸底 / S-C 内容 / S-D 出片 / S-E 交付 / S-F 上线复盘），节点语义 ID 永不出客户端——新增 `wiki/spec/CLIENT_VIEW_LABELS.yaml`（node_id→stage/客户化名称/一句话），前端阶段名只从这表取。
6. **脱敏两道**：导出 `D_*` 时过 ticket 脱敏正则 + BFF 出站兜底正则（命中即 500 不降级渲染）。前端只吃 `D_*`，永不直接渲染 `A_*`。
7. **平台不新建门禁**：19 门判定权仍在 WORKFLOW_REGISTRY + workflow_gate.py，平台只调 check 读状态 / approve 落凭据 / 翻译成人话。
8. **交付后复盘提醒（需求 5）**：交付包含「后续复盘操作指引」（T+1 播放/完播/前3秒跳出→钩子；T+3 互动/主页访问→选题；T+7 咨询/私信/到店→承接）；提醒文案禁「发了就有流量/一定获客」；一级指标=有效咨询/留资/到店。
9. **自动发布三重开关**：编译期常量 `AUTO_PUBLISH_ENABLED=False`（不接受环境变量覆盖）+ 项目白名单 + 每次人工确认内容哈希；适配器骨架保留（manual 默认 / douyin_openapi / creator_console 占位），不绕过平台授权/验证码/频控。
10. **广州机/新加坡机分工**：广州机只跑 BFF（TLS/会话/CSRF/限流/模板渲染/流式转发，反代~30MB + Web~200MB），**执行器代码不部署**（不是配置关，是不装）；新加坡机跑 Orchestrator+Executors+项目目录+SQLite+审计；隧道只允许 `/api/v1/*` 与 `/internal/v1/*` 白名单路径；新加坡不可达 → 客户侧显示「处理中」不做本地伪造。

## 🔴 表单设计铁律：内容需求表 ≠ 经营尽调表（2026-08-16 用户硬纠正）

**用户原话链**：「哪里有这么多要填 还要酒水清单，你怎么不要营业执照」→「我是说营业执照为什么要提供？」→「酒水、瓶子这些跟你，跟我们有什么关系啊？」→「你其他行业也是一样，你让他重新整理一遍」

**核心教训：客户表单是「内容制作需求表」，不是「经营尽调表」。** 设计时想当然堆的尽调字段（酒水清单/瓶子/预约排队/经营例外/过敏原/营业执照/营业资质/库存/套餐有效期）**全部与做内容无关**，客户填表烦死、还显得我们不懂业务。营业执照是广告代投/开户资质才要的，我们做内容生产**不需要客户提供**。

**字段判据（每个字段必须回答）**：「这个字段对做这条内容有什么用？」
- 有用（保留）：行业/店名/地址/联系方式/招牌产品/核心卖点/客单价/主推套餐/照片素材/内容授权
- 没用（删除）：一切尽调类（执照/酒水/排队/过敏原/库存/经营例外/营业资质）
- 授权要保留：客户确认「同意拍摄和使用素材做内容」是合规必须（不是尽调），文案要写清「只确认内容制作与素材使用授权，不收集营业执照或经营资质材料」
