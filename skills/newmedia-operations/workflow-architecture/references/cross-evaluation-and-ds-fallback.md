# 多执行器交叉互评 + DS 降级（2026-08-12 天行者定案）

## 交叉互评决策流程

**场景：** 老板问「CC 做架构 + codex 写代码是不是最优组合」这类分工/策略题，或两个 AI 对同一问题各给判断时。

**流程（用户原话驱动的模式）：**
1. **各自判断**：把同一问题**按用户原话**分别打包给 cc 和 codex，**不加 Hermes 判断**（用户明确要求「不要加你的判断，按照我的原话」）
2. **交叉互评**：把 A 的判断发给 B 评（「同意哪些/不同意哪些/补充什么，不要客套」），B 的判断发给 A 评——两方回答互发对方评，不自己转述
3. **依据追问**：问「判断依据是什么——哪些是实测/推演/假设？去掉依据方案还成立吗？」（诚实分级：A行业标准/B逻辑推演/C仓库事实/D拍脑袋）
4. **备选方案**：问「挂了怎么办」——cc 挂/codex 挂/都挂只能用 DS 替代，要完整降级方案
5. **最终定稿**：让 Claude 吸收全部讨论出「最终定稿」（一句话规则+路由+角色边界+容灾触发+落地清单），再让 codex 确认对齐

**关键纪律：** 打包按用户原话，不加 Hermes 判断；两方回答互发对方评；交叉互评常出现「同意前提不同意结论」——分歧点就是决策要点。

## 分工定稿结论（2026-08-12）

- 共识：无固定最优 / 单一结果负责人 / 不可逆操作事前保护
- 大项目：CC 定约束 + Codex 验证并实现 + 交叉复核；小项目：Codex 端到端 + CC 终审
- Claude 替代规则更细：按**可逆性 × 事实不确定度**路由（事实不清先审计；不可逆/不可 diff 事前授权+恢复演练；可逆且事实清→单主代理+异构复核）；复核独立性靠**输入不同源**不靠角色名
- 「人是第三个代理」：唯一持久记忆 + 唯一不可逆操作授权方
- 验证方法（codex 建议）：选代表任务对比 A/B 流程，记录墙钟/消耗/返工/通过率/缺陷，用数据定

**分工落地（已写入 AGENTS.md「角色分工」节）：** CC=架构约束/契约设计/对抗审查/终审；codex=仓库实现/事实审计/跑测试收敛；DS=容灾降级；Hermes=调度/质检/交付；人=唯一持久记忆+唯一不可逆授权。

## DS 降级方案（2026-08-12 已落地实测）

**原则：DS 顶不了「审查」，顶得了「执行」**——两个执行壳（claude/codex）都能换后端，DS 缺的不是工具能力是判断力和上下文长度。

- **健康检查三层判定**（`scripts/agent_health_check.sh`）：L1 环境坏/L2 鉴权坏→**别降级**（修环境）；L3 端到端失败→真 DOWN 走降级矩阵；L3' 限流(429/503)→**等重试别降级**。L3 探针故意用「返回 a-b 的 add+断言 add(2,3)==5」一次验证读/改/跑/修正四件事——只 ping API 会把「鉴权通但改不动文件」误判为健康
- **降级执行**（`scripts/ds_fallback.sh cc-slot|codex-slot "<任务>" [workdir]`）：cc 位用 deepseek-v4-pro（claude 壳+DeepSeek anthropic 端点），codex 位只能用 deepseek-v4-flash（pro 走 codex 协议被拒）
- **降级矩阵**：cc 挂→DS 顶单文件审查/取证/跑测试（❌攻击路径构造/架构约束/终审签字）；codex 挂→**优先让 CC 端到端**（codex 位降级只有 flash 弱一档），DS 只做机械活；都挂→内容生产几乎无损（本就跑 DS）/写代码降级但分支+测试兜底/架构审查**不降级改成冻结+排队**
- **硬红线（禁止降级）**：门禁状态机/skills 树删除（Git 外不可回滚）/主干 push/数据迁移/安全边界/客户方案定稿——降级期遇到输出 `BLOCKED_NEEDS_PRIMARY:<原因>` 并停止
- **坑**：`CLAUDE_CODE_USE_BEDROCK=1` 会劫持路由（不 `env -u` 清掉请求照样打 Bedrock，报 400 model invalid 像 DS 挂了）；`codex doctor` 常态报 2 fail 是 npm prefix 冲突，**别当挂了**；降级期 bwrap 沙箱坏需 danger-full-access，WORKDIR 白名单是唯一防线
- 完整方案：`wiki/spec/DS_FALLBACK_PLAN.md`（已 git 提交 a89061b）
