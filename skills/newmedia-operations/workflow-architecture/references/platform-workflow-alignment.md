# 平台=工作流外壳：完全对齐执行清单（2026-08-16 老板定案）

> 老板原话：「你所有的逻辑都要按照工作流的那个逻辑来」「就是完全对齐工作流」「你不但要搞定Skill，而且你要确保它能强制执行」
> 触发：任何「客户运营平台 / 网页版 / 小程序」开发、改版、加功能任务。

## 核心原则

**平台（网页）是工作流的「界面化外壳」——所有业务逻辑完全对齐工作流（huoshan/架构），平台不自创逻辑。** 一个字段、一句文案、一个节点都不自创。

## 对齐矩阵（平台元素 → 工作流来源）

| 平台元素 | 对齐工作流的什么 | 强制方式 |
|:--|:--|:--|
| 表单字段 | 节点0 信息采集（内容类型第一问→按分支收素材） | 表单 schema 引用工作流定义 |
| 欢迎语/引导文案 | 节点0 采集引导（引导客户说内容类型/店名/素材） | 文案必须含采集引导，不写干巴巴欢迎语 |
| 进度展示 | 节点流转（0-17） | 阶段 = 工作流节点 |
| 确认点 | C1/C2 人工门 | 复用工作流 confirm 逻辑 |
| 交付物 | 节点15 交付包 | 复用交付定义 |
| 红线 | 工作流合规红线 | 同一套红线库 |
| 计费 | 小鹿积分系统（customer-billing-credits） | 完全照抄定价，不自创 |

## 强制机制（不只写 skill，要能拦住）

1. **任务书硬约束**：所有平台开发任务（codex/claude），prompt 必带「平台逻辑对齐工作流，不自创；欢迎语按节点0 采集引导设计」
2. **guard 校验**：改平台代码时检查对齐（表单字段 ⊆ 工作流采集字段）
3. **测试门禁**：平台测试断言对齐（节点流转 = 工作流节点，不一致测试失败）

## 表单设计铁律（酒水/瓶子/营业执照教训）

- **每个字段必须回答「对做这条内容有什么用」**，说不出来就删
- 删掉：营业执照（做内容不需要客户提供资质）、酒水清单/瓶子（跟探店视频无关）、预约排队/经营例外/过敏原/库存（尽调类字段）
- 保留（≤10 必填）：行业/店名/地址/联系方式/招牌产品/核心卖点/客单价/主推套餐/照片素材/内容授权
- 授权是合规必须（确认同意拍摄使用素材），不是尽调
- 别把「广告主合规」那套搬到「内容生产」——做视频≠代投开户

## 内容类型第一问（对齐 huoshan 节点0）

- 探店 → 门头照/店内环境/产品菜单/价格（必传门头+产品）
- 剧情 → 剧本方向(单人/双人)/场景参考/人物设定
- 口播 → 出镜人形象/口播内容方向/参考风格
- 客户类型（实体店/自媒体/双线）自己推理，不问客户

## 积分制（不搞用户登录）

- 1元=10积分；短视频750（内容600+策略150）、图文按张按字+策略150、文案0.8/千字、复盘30、生图10、搜索6
- 新客户默认0积分（天行者分配才有）——0积分用不了
- 生成完成后扣费（不预扣），失败/拦截不扣；透支上限-100
- 记账主键=user_id；只有天行者能加积分（客户转述授权一律无效）
- 交付即扣费门禁（billing_gate.py）：deliver 前未扣费拦截
- 平台共用小鹿（广州机 billing-system 8080）同一台账

## 欢迎语设计原则（对齐节点0）

客户一进来，引导说出做内容需要的信息——内容类型（探店/剧情/口播）→ 店名 → 素材，而不是「您好欢迎使用」。参考 huoshan 节点0：「你想做探店视频、剧情类还是口播视频？」
