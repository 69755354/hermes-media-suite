# 接力文档模板

## 用途

每个节点出活后写接力文档到 `/tmp/projects/<项目名>/` 下，下一节点开工前必须先读上游文件。没读到上游文件 → 卡死，不准开工。

接力文档 + 下游签收 + 外部校准 = 三层把关，防节点间信息传递走偏。

## 模板

```yaml
## 节点X：<节点名称>
### 核心输出（简）
- 要点1：xxx
- 要点2：xxx
- （只写关键决策和下传信息，不写过程）

### 已排雷
- ❌ 不准做的事1
- ❌ 不准做的事2
- ✅ 确定的方向

### 待确认
- ⚠️ 不确定项1
- ⚠️ 不确定项2
- （带⚠️标记的项，下游节点处理时如果卡住可找你确认）

### 外部校准
- 校准方式：搜了3条同赛道抖音爆款/对比了2篇小红书笔记/查了官方定价
- 校准结论：✅（方向与市场一致）/ ⚠️（有偏差但仍可用）/ ❌（方向可能错了）
```

## 下游签收

节点N+1收到接力文档后，先核验再签收，不通过就退回上游补：

```yaml
## 校验日志：节点N → 节点N+1
### 核验结果
- 信息完整度：✅ 完整 / ⚠️ 缺xxx / ❌ 缺很多
- 方向校验：✅ 此方向可继续 / ⚠️ 有偏差 / ❌ 方向错了
- 排雷遵守：已确认遵守 / 未确认

### 本节点补充
- 补了什么信息：xxx
- 修正了什么偏差：xxx

### 校准记录
- 校准方式：搜了啥/对比了啥
- 校准结论：✅ / ⚠️ / ❌
```

## 三层把关速查

| 层 | 执行时机 | 执行人 | 物理保障 |
|:--:|:---------|:-------|:---------|
| 下游签收 | 节点N+1收到文档后 | 节点N+1 | 校验日志写入磁盘 |
| 外部校准 | 节点产出后、往下传前 | 节点自己 | 校准结论写在文档末尾 |
| 剧本终审 | 节点4文案定稿后 | 用户（只这一次） | 你说「可以」才往下走 |

## 应用场景

| 场景 | 行为 |
|:-----|:------|
| 新会话启动，用户提到项目名 | 去 `/tmp/projects/<项目名>/` 读最新节点文件 |
| 跨项目切换 | 当前项目写书签 → 切到目标项目读文档 |
| 交付完成 | 写复盘报告到 `wiki/cases/<项目名>_复盘.md` → 更新 `wiki/current_projects.md` |
| 每月汇总 | 汇总所有复盘 → 更新踩坑编年史 |
