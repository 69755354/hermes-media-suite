## 节点0：信息采集

**核心流程（2026-07-20 更新：先问内容类型，不问客户类型）：**

```
① 问内容类型：「想做探店视频、剧情类还是口播视频？」
   - 探店 → 需门头照、店内环境、产品/菜单、价格
   - 剧情 → 需剧本方向(单人/双人)、场景参考、人物设定(几个角色)
   - 口播 → 需出镜人形象、口播内容方向、参考风格
② 自行推理客户类型（实体店/自媒体/双线），不问客户
③ 双线 → 追问「这次针对实体店还是自媒体？」标注本次线别
④ 按分支采集对应素材
⑤ **素材归档（2026-08-07 新增，防丢铁律）：** 客户发的所有素材（视频/图片），第一时间从 cache/documents/ 复制到项目目录 `assets/` 留档——不依赖 cache（会被系统清理）。素材丢失教训：红果漫剧5个素材丢3个（真人广告/筛选页/剧场页2）
⑥ 输出简报（含内容类型+客户类型+本次线别+素材）
```

**工具：** 豆包多模态看图（endpoint: `ep-20260710211910-f65h9` → model: `doubao-seed-2-0-mini-260215`）
**注意：** 专用于看图。视频生成走 Seedance 2.0 Mini 独立 endpoint。ARK_ENDPOINT 已写入 `.hermes/.env`。

### ⚠️ ARK看图端点可靠性警示（2026-07-11 新增，本会话实测）

**端点：** `ep-20260710211910-f65h9`（`doubao-seed-2-0-mini-260215`）

**问题：** 本端点在2026-07-11会话中对同一批熹园门头照片的分析结果，与用户直接在豆包App中看到的结果**完全不符**。用户已验证并确认API分析结果是错误的（门的位置/材质与实际不符）。

**结论：ARK看图端点的输出不可全信。** 它可能返回编造的描述（如指着一张宣传单说「这是门头实景照，门在左侧」）。

**应对策略（优先级从高到低）：**

| 优先级 | 方案 | 说明 |
|:-----:|:-----|:------|
| 1 🥇 | **问用户** | 视觉细节拿不准的，直接问用户。不用看图端点分析。 |
| 2 🥈 | **交叉验证** | 如果必须用ARK看图，把分析结果拿着去和已有的wiki档案、用户历史描述做比对，有明显矛盾就弃用 |
| 3 ❌ | ~~全信端点输出~~ | 已证实不可靠，禁止把端点的单次输出当作事实用于写prompt |

**铁律：** 写prompt时涉及门的位置/材质、桌椅布局、招牌文字等**具体视觉细节**，以**用户说的为准**，不以ARK看图端点输出为准。

### 🆕 轻量级模式：娱乐向/跟拍模板短视频

**适用场景：** 纯娱乐内容（甜妹摇头晃脑/跟拍热门模板/萌宠/卡点变装/手势舞等），**非实体店推广**。

**触发判断（满足任意一条即走轻量级）：**
- 参考视频是纯娱乐/跟拍模板，无门店推广属性
- 用户说的是「做个一样的视频」而不是「帮我推广XX店」
- 内容不需要门头/店内实景/套餐价格/地址露出
- 时长≤15秒，BGM驱动而非文案驱动

**与完整18节点工作流的区别：**

| 维度 | 完整探店18节点 | 轻量级模式 |
|:----|:-------------|:-----------|
| 前置分析 | 用户分析→爆款拆解→选题→文案→分镜 | 直接拆参考视频结构→出方案 |
| 文案 | 台词+人设+情绪节点（5段式） | **无需文案**（纯BGM+画面） |
| 分镜 | 6镜30秒带台词+场景切换 | **单镜5-10秒**或2-3镜递进 |
| 声音模式 | 口播/旁白/内心独白三选一 | **无台词**（Seedance不生成人声） |
| BGM | 平台发布时挂同款/本地SoundHelix叠轨 | 同左，见 `references/trending-content-bgm-strategy.md` |
| 时长 | 30秒 | 5-10秒（跟热门模板节奏） |
| @图2场景 | 需要门店实景照 | **不需要@图2**，纯色/干净背景即可 |

**执行流程：**
```
① 分析参考视频（结构/节奏/数据/抖音是否标注AI生成）
② 简化方案：去除非核心元素（用户说「不要猫也可以」就简化）
③ 写单镜Seedance prompt（纯动作描述+无台词+无@图2）
④ 调Seedance API生成 → 下载视频
⑤ ffmpeg叠BGM（SoundHelix免费曲目截取）→ 出片
⑥ 告知用户在发布平台挂同款热门BGM蹭流量池
```

**Seedance prompt写法（无台词纯画面版）：**
```python
@图1 作为甜妹探店博主小鹿，保留全部面部特征和穿搭不变；
照片级写实，无CG感，天然肌肤质感，明亮自然光线；
中近景镜头，画面稳定柔和，浅色干净背景；
[动作描述：跟着节奏摇头晃脑/甜笑/眨眼等]；
动态强度35%；
# 不加"同步生成中文探店人声"
# 不加任何台词内容
# 不需要@图2场景引用
```

**抖音「疑似AI生成」标签陷阱（轻量级内容尤其高发）：** 抖音会对大量真实拍摄内容打上「疑似使用了AI生成技术」标签（触发因素可能是美颜滤镜、贴纸、特效等）。**不能基于这个标签判断参考视频的内容来源。** 必须通过帧分析确认是真人实拍还是AI生成（见节点3 - 爆款拆解 > 参考视频画面逐帧分析工作流）。如果确认是真人实拍+贴纸，复刻方案应说明「小鹿是AI角色模仿真人风格」，而非宣称技术路线一致。

**BGM处理（重要）：**
- 参考视频使用平台内置热门音乐模板时 → 优先告知用户发平台时挂同款BGM（0版权风险+蹭流量池）
- 用户要求直接出片带BGM → 本地SoundHelix免费曲目截取+ffmpeg叠轨
- BGM音量0.2-0.3（无台词可略高），参考 `references/trending-content-bgm-strategy.md`

**交付：** 发视频下载链接（上传到可访问URL），告知发布时挂 #热门标签 + 同款BGM。禁止用MEDIA格式发文件。

### 🚦 渠道选择（所有客户都走这一步）

**核心原则：客户说清楚了就不问，没说清楚才追问。**

```
客户说「帮我在抖音上推广」
  → 直接记渠道=抖音，不废话

客户说「帮我做个视频」
  → 追问「你准备发哪些平台？」（可多选）
       ├── 选了多个 → 追问顺序，默认先图文后视频
       └── 只选一个 → 直接记

客户说「帮我搞个小红书种草」
  → 追问「做图文还是视频？」
       ├── **图文** → 记渠道=小红书图文，跳过视频制作链（节点6-9、11-13）
       └── **视频** → 记渠道=小红书视频，同抖音走全节点，比例16:9，时长1-3分钟

回头客查到老档案
  → 问一句：「你上次是在[上次平台]发的，这次还是发[上次平台]吗？」
       ├── 「对」→ 直接用老渠道
       └── 「这次想发[其他平台]」→ 换渠道标记
```

**只在客户没说清楚时才问。客户自己说了就不问第二遍。**

### 🧠 节点0「定位判断」（小鹿自己分析，不问客户）

**渠道确定后，基于已有信息做3个判断，定文案方向：**

| 判断维度 | 怎么判断 |
|:--------|:--------|
| **① 谁在说话？** | 有店主出镜照/老板愿意拍 → 店主自述。只有门头图没人 → 探店视角。有顾客评价截图 → 顾客口碑。 |
| **② 店是谁的？** | 客户说「我们店」「我开了几年」→ 自己的。客户说「帮朋友做」「那家店」→ 别人的。 |
| **③ 想让观众什么感觉？** | 卖套餐/优惠 → 冲动想去。讲故事/晒手艺 → 好奇/佩服。讲知识/避坑 → 解惑。 |

**定完方向再动笔写文案，方向错了改6轮也救不回来。**

### 📰 公众号专属流程（不走视频节点）

**渠道为公众号时，不走视频制作链（节点1-16中大部分），只走4步：**

```
节点0(渠道选择) → 写文案(标题+正文) → 正文排版 → 合规检查 → 交付图文
```

**公众号内容不涉及：**
- ❌ 门头照/店内环境/菜品图（不需要视频素材）
- ❌ 用户分析/爆款拆解/选题（不需要）
- ❌ Seedream生图/Seedance视频/ffmpeg合成/配音（全不需要）

**公众号4步流程：**

| 步骤 | 操作 | 示例 |
|:----|:-----|:-----|
| **① 写文案** | 标题15-28字含数字/痛点/悬念；正文1200-2000字，总-分-总结构，2-3个小标题分段 | 「开了10年火锅店，我想跟你说3句实在话」 |
| **② 排版** | 空行分段、关键信息加粗、配图2-3张（从客户给的素材或网上找）、文末引导关注+在看 | 正文见上方 |
| **③ 合规** | 通用违禁词扫一遍（最/第一/治疗等） | 同节点4规则 |
| **④ 交付** | 发给客户复制到公众号后台发布 | 「公众号推文做好了，直接复制发就行」 |
