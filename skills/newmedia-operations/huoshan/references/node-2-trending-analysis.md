### 🚨 爆款拆解数据源铁律（2026-07-18 新增，本会话完整沉淀）

#### 数据源透明度原则

**爆款拆解的输出质量取决于数据源质量。每一条拆解结论必须标注数据来源和局限性，不准隐瞒。**

| 数据来源 | 可信度 | 标注方式 |
|:---------|:------:|:---------|
| **Tavily搜索引擎缓存**（赞数/日期从缓存摘要提取） | ⚠️ 有延迟、可能四舍五入 | 「基于Tavily公开索引缓存，非实时精确数据」 |
| **CDP浏览器截图** + **ARK Vision分析**（实际看到画面） | ✅ 高 | 「基于实际画面分析」 |
| **标题/标签推演**（没看视频，靠标题和行业模板推结构） | ❌ 低 | 「根据公开标题和爆款模板进行的结构推演，非原视频逐字稿」 |
| **用户发的一手截图/笔记** | ✅ 最高 | 「来自一手分析，数据可信度高」 |

#### 完整工作流（Tavily搜→CDP看→下载源视频→全帧提取→Vision分析→出方案）

```
① Tavily搜索 → 找到高赞视频链接 + 缓存赞数/日期
  ↓ 标注数据来源局限性
② CDP浏览器打开视频页 → browser_console取 video.currentSrc → curl下载
  ↓ 拿到原始mp4文件
③ ffprobe查帧率 → ffmpeg fps=帧率值 全帧提取（如30fps视频出315帧）
  ↓ ⚠️ 禁止fps=1（用户明确纠正：太粗，错过动作细节）
④ 豆包Vision分批分析（每批10-15帧，每帧分析：嘴/眼/头/表情）
  ↓
⑤ 基于逐帧分析结果 → 输出分镜拆解+节奏分析+复刻方案
```

**优先顺序：** 用户发截图 > CDP下载源视频→全帧分析 > CDP截图+Vision分析 > Tavily缓存数据 > 标题推演

#### 铁律

1. **绝不搬运原视频** — 只输出可原创复刻的方案，不照搬原视频素材和文案
2. **绝不编造脚本** — 没看到画面就说没看到，不用标题+行业模板编一套「伪拆解」
3. **数据局限性必须写进接力文档**，不准隐瞒
4. **搜不到确定的依据** → 标「无确切来源，需实测验证」

### 🚨 参考视频画面逐帧分析工作流（2026-07-19 新增：本会话用户连续纠正后沉淀）

**触发条件：** 用户说了「做一个一样的」「参考这个视频」「按这个风格做」等涉及具体参考视频的指令。

**背景（本会话的教训）：** 用户发了一个抖音参考视频，我只看页面元数据（标题/时长/点赞/标签）就凭想象写prompt出片，导致内容方向全错。用户连续纠正后，正确的流程是**下载原视频→逐帧分析画面内容**，而非仅看页面数据推演。

**完整流程：**

```text
① CDP浏览器打开视频页 → 获取页面元数据（标题/时长/赞评藏/标签）
  ↓
② 确认视频已加载（看snapshot中进度条显示00:XX/00:YY）
   如果被登录弹窗挡住 → 刷新或点击页面其他区域
  ↓
③ 用 browser_console 获取视频源地址：
   browser_console(expression='document.querySelector("video").currentSrc')
  ↓
④ 用 curl 下载原视频：
   curl -sL -o /tmp/reference_video.mp4 "<source_url>"
  ↓
⑤ ffmpeg 抽帧（短视频<30秒建议用fps=2，即每0.5秒一帧）：
   ffmpeg -i /tmp/reference_video.mp4 -vf "fps=2" -q:v 2 /tmp/frames/frame_%02d.jpg
   ⚠️ fps=1会漏掉关键动作变化（如张嘴→闭嘴切换），10.5秒视频应抽21帧而非11帧
  ↓
⑥ 用 ARK Vision（doubao-seed-2-0-mini-260215）逐帧分析内容：
   每帧分析6个维度：人物/动作（嘴巴张闭+眼睛睁闭+头部位置）/表情/背景/贴纸/风格
   分批分析（每批7-10帧）
   输出格式：帧X: 嘴巴[张/闭], 眼睛[睁/闭], 头部[位置], 表情[描述]
  ↓
⑦ 根据分析结果输出帧序列表，明确动作节奏后再动笔写prompt
```

**分析的6个维度（每帧必问）：**

| 维度 | 具体问题 |
|:----|:---------|
| 人物 | 有人物吗？性别/年龄/长相/穿搭？正脸还是侧脸？全程位置是否变化？ |
| 动作节奏 | 嘴巴张开/闭合？眼睛睁开/闭着？头部有无移动？每个状态持续几帧？ |
| 表情变化 | 微笑/张嘴惊喜/嘟嘴/眨眼？表情切换节奏是否卡BGM节拍？ |
| 背景 | 室内/户外？纯色还是实景？颜色？光线（暖/冷/自然光）？ |
| 贴纸/特效 | 有没有贴纸覆盖？位置在哪？是否和人物动作同步？ |
| 画面风格 | 真人实拍（有无美颜滤镜）/AI生成/二次元？ |

**⚠️ ARK Vision 分析存在局限性：**
- 对画面细节描述可能出错（已验证会编造细节）
- **关键结论必须交叉验证：** 对比多帧之间的变化是否自洽
- 最终以用户描述为准，不盲信分析结果

**⚠️ 抖音「疑似AI生成」标签陷阱（本会话关键发现）：**
- **「疑似AI生成」标签不代表画面是AI生成的。** 真人实拍+美颜滤镜/贴纸的视频也会被标注AI生成
- **必须通过帧分析确认画面风格**，而不是凭标签推演（本会话中一个真人女生+贴纸被错误判断为AI生成）

### 渠道分支

**小红书（图文）：** 用web_search搜小红书同类目爆款笔记（≥5条）。拆解标题公式/封面设计/正文结构/图片数量/评论区互动点。输出小红书素材库（标题模板+封面参考+关键词清单+热门话题标签）。

**小红书（视频）：** 用web_search搜小红书同类目爆款短视频（≥3条）。拆解开头钩子/节奏/完播点/互动引导。输出素材库同图文模式。

**快手（视频）：** 同抖音流程，web_search搜快手同类目爆款。拆解结构同抖音，但话术风格注意——快手要真实接地气，不整精致钩子，老板/店员出镜优先。

**视频号：** web_search搜视频号同类目爆款。拆解开头/结构/互动引导。注意视频号内容重干货/情感共鸣/社交价值——能让人转发朋友圈的内容才容易爆。

**公众号：** 不走爆款拆解节点。直接采集客户开店故事/产品工艺/创始人背景，写公众号长文。
