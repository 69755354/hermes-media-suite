## 〇、视频源获取（CDP提取·必须前置）

**前提条件：** 浏览器CDP已连接（端口配置见 `browser.cdp_url`，本机9222）

抖音页面有反爬签名+登录弹窗，静态HTML/curl拿不到视频，但Video标签在DOM里：

```python
# 1. CDP浏览器打开视频页 → 等待Video标签加载
# 2. 用browser_console提取视频源地址
browser_console(expression="document.querySelector('video').currentSrc")
# 返回的result就是可直接下载的mp4 URL

# 3. curl下载
curl -sL -o yuan_video.mp4 "<从browser_console拿到的URL>"

# 4. 查验下载
ls -la yuan_video.mp4              # 确认文件存在
ffprobe -i yuan_video.mp4 -v quiet -select_streams v:0 -show_entries stream=r_frame_rate,nb_frames -of csv=p=0
# 输出示例: 30/1,315  (30fps, 315帧, 10.5秒)
```

**铁律：**
- ✅ 先试 browser_console 取 currentSrc（最快，无额外请求）
- ❌ 不要试图从页面HTML/script标签解析（反爬混淆JS）
- ❌ 不要用browser_vision截图代替帧提取（登录弹窗遮挡+模型不支持image_url）
- ⚠️ 源URL有时效性（签名过期后无法下载），拿到后立即下载

## 二、画面分析（CDP截图 + ARK Vision）

### 封面分析
```
1. 角色（人物/表情/姿态/眼神方向）
2. 背景（室内/室外/风格/色调）
3. 构图（居中/三分/留白）
4. 标题文字（字号/颜色/位置/描边）
5. 整体色调（冷/暖/对比度）
```

### 分镜分析（全帧提取 · 豆包Vision逐帧分析）

```bash
# === 前置：确认视频帧率 ===
ffprobe -i yuan_video.mp4 -v quiet -select_streams v:0 -show_entries stream=r_frame_rate -of csv=p=0
# 返回如 30/1 → 30fps

# === 全帧提取（fps=帧率值）===
# 30fps视频：fps=30 → 10秒出300帧
# 不要用fps=1（采样太粗，错过动作细节）
mkdir -p frames
ffmpeg -y -i yuan_video.mp4 -vf "fps=30" -q:v 2 frames/frame_%05d.jpg

# === 分批用豆包Vision分析 ===
# 每批10-15帧（15帧约消耗16500 tokens）
# 总成本：315帧约53万tokens ≈ 几毛钱（doubao-seed-2-0-mini）
python3 << 'PYEOF'
# 伪代码逻辑：
BATCH_SIZE = 15
for batch_start in range(1, TOTAL_FRAMES+1, BATCH_SIZE):
    frames = range(batch_start, min(batch_start+BATCH_SIZE-1, TOTAL_FRAMES)+1)
    # 每帧转base64，全部塞进一个messages数组
    # prompt格式：
    text = f"分析视频第{time_sec}秒开始的连续{len(frames)}帧(30fps)。每帧用以下格式输出：\n帧[编号]: 嘴[张/闭/微张], 眼[睁/闭/半闭], 头[位置], 表情[描述]"
    # → 装15张image_url + 1条text → 批量提交ARK Vision
    # → 返回逐帧分析结果
    time.sleep(0.5)  # 防限流
PYEOF

# === 输出示例 ===
# 帧00001: 嘴[闭], 眼[闭], 头[正], 表情[闭眼微笑]
# 帧00002: 嘴[张], 眼[睁], 头[正], 表情[张嘴惊喜]
# 帧00003: 嘴[闭], 眼[闭], 头[正], 表情[闭眼微笑]
```

**铁律：**
- ✅ 抽帧fps必须匹配视频实际帧率（ffprobe查，不要猜）
- ✅ 批量传10-15帧/次效率最高（token≈16500-25000，不超过32K上下文）
- ❌ fps=1采样太粗，漏掉动作细节（用户明确指出错误）
- ❌ 不要用随机抽帧或等间隔抽帧（错过关键帧过渡）
- ⚠️ 豆包Vision的嘴/眼判断可能有偏差（如把"微张"说成"张"），分析结果需交叉验证或用一致性检查：相邻帧的嘴眼状态不应突变

### 分镜分析（粗采样·旧方法·仅用于预览）
```
0s帧 → 开场画面/钩子
5s帧 → 第一信息点
10s帧 → 转折/发展
15s帧 → 高潮/情绪高点
20s帧 → 收尾/CTA
```

## 三、14问拆解框架（每案必过）

> 2026-08-28 升级：原10问 + 4项独立维度（借鉴「桃子的AI小屋」反推提示词方法论，将混在场景/质感里的维度独立出来）

```
1. 视频类型（口播/探店/剧情/情绪短片/知识分享）
2. 出镜者特征（外貌/穿搭/表情变化/眼神）
3. 背景环境（室内/户外/虚化程度/道具）
4. 画面风格（色调/滤镜/颗粒感/光影）
5. 构图景别（特写/中景/远景/运镜方式）
6. 时间线变化（0s→5s→10s→15s→20s各画面什么变化）
7. 字幕/文字信息（提取所有屏幕上出现的文字）
8. 整体节奏（快/慢/情绪曲线）
9. 它为什么爆？（钩子/共情/画面/情绪/选题）
10. 复刻关键要素（画面/结构/节奏/包装）
11. 前中后景关系（前景/中景/背景各自有什么，层次分离还是平面化，景深虚实）
12. 运动速度（人物运动速度/镜头运动速度/节奏快慢量化，如「人物缓步前移约0.5m/s」）
13. 材质（皮肤质感/布料纹理/金属反光/玻璃通透感/环境表面材质）
14. 交段构图（相邻镜头间的构图衔接关系，切换时画面结构如何过渡，如「镜1右三分构图→镜2居中构图，靠人物位置平移过渡」）
```

## 八、AI 视频逆向提示词分析（2026-08-15 补充：拆 Seedance/即梦 AI 生成视频时使用）

> 适用：参考视频是 **AI 生成**（Seedance/即梦等），目标是反推其提示词结构用于复刻。
> 铁律：只提取不编造；基于画面/音频分析反推，非原作者公开 prompt；证据不全就停，不硬拆。

### 8.0 前置约束（采样边界，写死）

- 稀疏关键帧采样（如 3 帧/15s）不是逐帧全量；细微快速动作、瞬时表情变化会丢失
- 不可反推原始 seed、原始调用参数、内部触发标记
- 输出是「大概率长这样」的结构反推，不是原始 API 入参
- 反推结果必须过 Harness 物理校验节点才能进 Seedance，不直接调用

### 8.1 信息分层

| 层 | 来源 | 能推出什么 |
|:---|:---|:---|
| 元数据层 | 标题/作者/标签/互动 | 选题意图、目标人群、作者风格 |
| 音频层 | 口播转写/BGM 识别/人声特征 | 台词文本、叙事结构、情绪节奏 |
| 画面层 | 抽帧 + 视觉模型 | 角色/场景/光影/构图/特效 |
| 动态层 | 帧序列对比 | 运镜、动作幅度、时长分配 |

每层独立提取，不互相脑补。

### 8.2 六维画面分析（各维度输出带置信度 0-1.0）

| 维度 | 看什么 | 反推什么 |
|:-----|:-------|:---------|
| 1 镜头与运镜 | 机位固定/运动、景别切换、焦段感 | `固定机位零位移`/`缓慢推近`/`环绕运镜` |
| 2 人物与表演 | 外貌跨帧一致性、表情变化幅度、动作自然度 | 锁脸强度、肌肉级描述、动态强度 XX% |
| 3 光影与质感 | 光源方向/色温、皮肤质感、胶片感 | `暖侧光`/`天然肌肤质感`/`胶片色调` |
| 4 场景一致性 | 场景类型、物体漂移/变形、虚化程度 | `背景锁定`/`浅景深`/场景 prompt 结构 |
| 5 AI 痕迹与破绽 | 手指/五官/边缘/物理规律 | 负面词候选（现象 vs 推测严格区分） |
| 6 结构与节奏 | 镜头数、每段秒数、情绪曲线、切换方式 | `几镜拼接`/`每镜 2-3.5s`/`首尾帧插值接力` |

### 8.3 第七维度：音频-口播分析（独立于画面六维）

- 台词文本：whisper 输出，做断句、停顿位置
- 人声音色特征：稳重/年轻/甜美，语速快慢
- BGM 类型、音量层次、环境音
- 输出标注证据：✅ 音频 00:02-00:07 女声语速偏缓；❌ 无法反推原始 TTS 参数
- **输出汇入 prompt 的【音频板块】，不混在画面描述里**

### 8.4 置信度标签硬规范

每条结论带 **置信度 0-1.0**，下游按阈值取舍：
- 置信度 > 0.8：直接写入全局锁
- 0.5-0.8：放入正向补充，允许模型适度浮动
- < 0.5：丢弃，不参与 prompt 组装，不脑补

### 8.5 现象 vs 推测必须区分（AI 破绽维度）

- 现象：未观察到手指畸形、五官崩坏
- 推论：推测可能配置相关负向词，置信度 0.4 级别，**不写「作者 prompt 写了 xx」**
- 模型版本、随机种子、参考图也可以让破绽消失，不一定是负面 prompt 生效

### 8.6 复现风险清单（输出必带）

显式列出难以逆向复刻的部分：
1. 哪些效果高度依赖模型版本（2.0-mini 做不到，2.5-pro 才支持）
2. 哪些依赖参考图输入，纯文本无法复刻
3. 时序细节，静态关键帧采样会丢失，复现会动作走形

示例：镜头平滑环绕效果，仅靠文本提示在 2.0-mini 很难复现，必须 2.5-pro。

### 8.7 输出格式（四层模板重组）

六维+音频分析后按 seedance 四层模板重组：
1. 导演意图（1-2 句人话）
2. 全局锁定（置信度 > 0.8 的项）
3. 正向补充（置信度 0.5-0.8 的项）
4. 专属负面（现象级证据支撑的负向词候选）

**默认禁止项（不管分析结果如何，以下6项先写入专属负面层）：**
- 人物变脸（跨帧五官不一致）
- 服装漂移（服装颜色/款式/纹理跳变）
- 肢体错误（手指数量/关节方向/肢体比例异常）
- 背景闪烁（背景元素跳变/闪烁）
- 动作断裂（动作不连贯/物理运动逻辑断裂）
- 物理关系失真（重力/碰撞/遮挡关系错误）

并标注：✅ 有证据支撑 / ⚠️ 推测 / ❌ 反推不出（触发词/seed/模型参数——老实说不存在）。

### 8.8 使用边界声明（2026-08-28 补充）

拆解产出的提示词**只学习镜头逻辑和视觉方法，不照抄人物品牌、台词和具体故事**。拆解报告和重组prompt里显式声明此边界，防止执行器直接拿原片内容组装。
