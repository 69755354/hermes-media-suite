## 双号配置：lightclawbot 多UIN

### 原理

lightclawbot 原生支持多UIN（多微信账号）。每个账号绑定一个 UIN，通过环境变量 `LIGHTCLAW_API_KEY_${UIN}` 配API Key。Hermes Gateway 启动时自动加载所有有效Key，为每个UIN建立独立 WebSocket 连接。

### 配置步骤

1. **注册新微信小号**（用于接待客户）
2. **登录腾讯云 lightclaw 控制台** `lightai.cloud.tencent.com`
3. **绑定新号** → 获取该号的 **UIN**（一串数字）和 **API Key**
4. **服务器配置**：在 Hermes 环境变量中加上：
   ```
   LIGHTCLAW_API_KEY_新UIN = 新APIKey
   ```
5. **重启网关** → 两个号同时在线

### 现有配置检查

查看当前已注册的UIN：
```bash
grep LIGHTCLAW_API_KEY /home/ubuntu/.hermes/.env
```

网关状态确认：
```bash
cat /home/ubuntu/.hermes/gateway_state.json
# → "lightclawbot": {"state": "connected"}
```

## 客户接入流程

### 新好友自动引导

客户加机器人微信号后，Hermes 自动识别为新用户，触发引导流程：

```
客户：你好
机器人：🎬 欢迎！我是AI探店视频助手。
        发我「店名+几张实景照片」，我帮你自动生成探店视频。
        示例：店名：熹园知味茶馆
             地址：株洲市珠江北路
             照片：[门头照][店内照]
```

### 需求提交

```
客户：帮我做个视频
客户：[发照片]
机器人 → 自动跑节点0-13流程
       → 出片后回传视频给客户 ✅
```

### 多客户并发

Hermes 的 `group_sessions_per_user: true` 自动按微信用户隔离 session。每个客户的对话、图片、进度互不干扰。

## 主号监控方案

### 方案A：自动推送进度（推荐）

Hermes 在跑每个客户流程时，每完成一个关键节点自动给主号发通知：

| 节点 | 推送内容 |
|:----|:---------|
| 节点1完成 | 🆕 新客户：客户A（店名）开始处理 |
| 节点4完成 | 📝 剧本已出 |
| 节点8完成 | 🎬 分镜+提示词就绪 |
| 节点10完成 | 📹 视频生成中 |
| 节点11完成 | 🎞️ 合成完成 |
| 节点13完成 | ✅ 客户A视频已交付，点此查看 |

### 方案B：主号主动查询

主号给机器人发指令：
```
查订单 → 今日订单3个：
    ① 熹园知味 - 已完成 ✅
    ② 某某火锅 - 生成中 🔄
    ③ 某奶茶店 - 排队中 ⏳

订单1 → 熹园知味详情 + 视频链接
```

### 方案C：双号消息路由

主号给机器人发消息时，不触发全流程处理，走管理指令模式。通过检查消息来源 UIN 来区分主号 vs 客户号。

## 并发与排队

当多个客户同时提交时，简单任务队列策略：

```
客户A提交 → 开始跑（节点0-13）
客户B提交 → 排队中（等A完成）
客户C提交 → 排队中（等A→B完成）
```

由于全流程约 3-5 分钟/客户（主要是 Seedance 6镜各2-4分钟），排队等待时间可控。

**进阶方案：** 升级 Helper API 为异步任务队列（FastAPI + arq/Celery），支持并发处理。

---

## 封号风险

| 风险点 | 规避措施 |
|:------|:---------|
| 个人微信协议非官方 | lightclawbot 已处理此层，但仍存在风险 |
| 频繁加好友被限制 | 初期手动加，量大了换企业微信 |
| 发送频率限制 | 每条客户消息间隔至少 3 秒 |
| 敏感内容触发 | huoshan 节点9合规终检已覆盖违禁词 |

**建议：** 初期用5-10个试用客户验证模式，跑通了再放大。
