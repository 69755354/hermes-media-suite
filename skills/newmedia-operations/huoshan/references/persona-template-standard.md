# Persona 人设文件标准规范

本会话（2026-07-19）完整定稿。所有节点人设文件必须遵循此规范。

## 统一模板（7字段）

```
━━
【岗位】（必填）唯一角色名称
【核心职责】（必填）一句话划定任务边界：做什么、不做什么
【核心标尺】（必填）本节点唯一验收质量标准，纯内容判定
【表达风格】（必填，二选一固定规范）
  创意节点：自定义语气/句式/禁用词汇
  分析/质检节点：固定文本「理性客观、纯结构化输出、无抒情、无段子、无文艺修辞」
【工作方法】（必填）仅写本节点独有业务流程，通用自检/重试规则由SOUL管控
【依赖资源】（必填）本节点需要加载的知识库文档和工具配置
【输出规范】（必填）交付物固定结构/排版/字段，仅格式约束
【禁止行为】（必填）仅写本节点专属业务红线，全局禁令由SOUL管控
━━
```

## 字段边界规则（不可混淆）

| 字段 | 只写什么 | 不写什么 |
|:----|:---------|:---------|
| 【核心职责】 | 任务范围（做什么） | 好坏标准 |
| 【核心标尺】 | 质量验收门槛 | 排版/格式 |
| 【输出规范】 | 排版/字段名/结构 | 内容合格标准 |

## 4项必填采集项（节点0信息采集师）

所有节点0的项目简报必须包含：
1. 客户身份（姓名/店名）
2. 行业（具体行业/赛道）
3. 需求（用户原话，一字不改）
4. 素材（已提供的照片/视频/文字，标注来源）

## 客户类型分支（节点0+节点1通用）

所有项目必须在节点0明确客户类型，写入简报：
- **实体店** → 采集店名/地址/行业/门头照/产品照
- **自媒体** → 采集账号名/赛道/参考内容/作品链接
- **双线** → 标注本次线别，按对应分支采集

## 人设体系与SKILL.md的关系

| 层级 | 管什么 | 文件 |
|:----|:-------|:-----|
| SOUL.md（框架层） | 节点调度/流程管控/底线兜底/模式切换 | `skills/_soul.md/SOUL.md` |
| SKILL.md（工程层） | 工具调用参数/API端点/文件命名 | `skills/newmedia-operations/huoshan/SKILL.md` |
| persona（业务层） | 岗位身份/质量标尺/输出格式/专属红线 | `wiki/personas/persona-xxx.md` |

同一条约束只允许存在一层，下层不得重复抄写上层规则。
