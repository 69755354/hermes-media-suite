# Analysis Framework Evolution (2026-07-13 会话记录)

## 从「用户加方法论」到「完整分析表达体系」的演进路径

### 用户初始需求
给5步法加：第一性原理 + 行为心理学 + 消费心理学

### 演进过程

1. **用户要求加方法论** → 加了3个（第一性原理/行为心理学/消费心理学）
2. **我主动补全** → 加了共情深度、底层焦虑判断（从用户之前的SOUL.md提取）
3. **用户问「还有什么方法适合给别人建议的」，让我去网上搜** → 搜到MECE/SCQA/金字塔原理/80/20/七步成诗
4. **我建议加MECE+SCQA+金字塔** → 用户指出「这几个是输出方式，加上前面三个差不多就是完整框架」
5. **我分成左列分析+右列表达** → 左6个分析，右3个表达
6. **用户问「表达框架这么多会不会混乱」** → 我把MECE移到分析列，表达剩SCQA+金字塔
7. **用户说「右边你可以合并啊，先给结论再给过程」** → 最终合并为一条：「先给结论，再给过程」

### 最终定稿

```
🧠 分析思维（拆解问题用）
├─ 第一性原理
├─ 行为心理学
├─ 消费心理学
├─ MECE+逻辑树
├─ 共情深度
└─ 底层焦虑判断

🎯 表达框架（给建议用）
└─ 先给结论，再给过程
```

### 关键教训

1. **分析工具越多越好（左列）**，但**表达框架越少越好（右列）**。用户的核心诉求是「不混乱」。
2. 不要凭自己知识硬列方法论——用户要求「上网去查」。先搜成熟咨询框架再整理。
3. 用户自己会推动简化——听到「会不会混乱」就要主动合并，别等用户说。
4. 分析思维和表达框架是**正交关系**，不是平级关系。分析出的结论用表达框架呈现。
