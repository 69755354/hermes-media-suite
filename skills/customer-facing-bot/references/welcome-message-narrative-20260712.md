# 欢迎消息叙事设计（2026-07-12 实测经验）

> 客户bot的欢迎第一条消息决定了用户的第一印象。本会话中经历了3版迭代，最终bot自生成的叙事版效果最好。

## 演进过程

| 版本 | 风格 | 评价 |
|:----|:----|:----:|
| V1 正式版 | 「亲爱的朋友，我终于等到你了！我是你最贴心的助手小天…」 | 太正式 |
| V2 俏皮功能列表 | 「哎呦，终于等到你啦！我是你贴心又皮皮的小鹿…🔍搜爆款 ✍️写文案 📊做分析 🎬做视频」 | 功能清晰但缺人味 |
| V3 叙事版（bot自生成） | 「我是小鹿，一个懂内容、懂运营、更懂你的AI助手。我的日常就是泡在小红书、抖音、快手、公众号里…你缺灵感？我帮你搜同行的爆款…」 | 有血有肉，有场景有画面 |

## V3叙事版结构拆解

```
我是[名字]，一个懂[领域]、懂[领域]、更懂你的AI助手。

我的日常就是泡在[平台1]、[平台2]、[平台3]里，[做什么]。
然后把这些变成你的[价值]——

[问题1]？[我能做的1]
[问题2]？[我能做的2]
[问题3]？[我能做的3]
[问题4]？[我能做的4]

我的做事风格很简单：[核心方法论一句话]

所以以后你有需求，直接丢过来就行。
你，什么行业的？ 😎
```

## 设计原则

1. **先立人设，再说功能** — 第一句是「我是谁」（身份认同），不是「我能做啥」
2. **场景化提问** — 「你缺灵感？」比「搜爆款」更有代入感
3. **动词用「搞」类口语** — 「帮你搜」「帮你写」「扒数据」「一条龙搞定」
4. **结尾转化为对话** — 「你，什么行业的？」不是功能列表，是对话邀请
5. **方法论收尾→建立信任** — 「先搜再写，不瞎编」→ 客户知道你不是瞎编的

## ⚠️ 注意

- 这种叙事版适合**有运营能力的bot**（能写出有场景的文案）
- 如果bot能力弱（只有1-2个功能），功能列表版更清晰
- 叙事长度控制：不宜超过200字，用户没耐心读完
