# 人物一致性锁定机制（0826 官方文档研究）

> 来源：help.aliyun.com 官方文档抓取 + 实测
> 研究触发：单张头像照做r2v生成视频不像，用户追问怎么保证真人一致

## 一、核心结论

**阿里真正保证人物一致性的方案是 wan2.7-r2v 传视频，不是传静态图。**

静态图做r2v（HappyHorse/wan3.0）只是"角色参考"，模型参考外观但不锁定，身体/穿着/体型全靠模型脑补。

## 二、三种参考生视频方案对比

| 方案 | 模型 | 参考素材 | 人物锁定力 | 适用场景 |
|:---|:---|:---|:---|:---|
| 静态图r2v | HappyHorse 1.1 r2v | 1-9张静态图 | 弱（角色参考不锁全程） | 简单场景、不要求像 |
| 静态图r2v | wan3.0-video | 最多10图+5视频+5音频 | 中（比HappyHorse略强） | 多素材融合 |
| **视频r2v** | **wan2.7-r2v** | **视频+文本（+音频）** | **强（复刻角色形象+声音）** | **要求真人一致性** |
| 九宫格r2v | wan2.7-r2v | 1张九宫格图 | 中（多角度拼一张图） | 卡通/角色设定 |

## 三、wan2.7-r2v 视频参考（官方推荐锁人方案）

官方原话："复刻视频中的角色的形象和声音表演新剧本。在保持角色一致性的同时，生成多镜头、声画同步的视频。"

- **输入**：视频（角色参考）+ 文本（新剧本）+ 可选音频（音色参考）
- 每个参考素材可配 `reference_voice`（mp3音色文件）
- 支持多主体：多个视频+图片+音频混合
- 提示词用"图n""视频n"指代（wan2.7语法）
- 时长[2s,10s]，720P/1080P，30fps
- 新加坡可调（需SSH到广州）

### wan2.7-r2v API 端点

```
POST https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/video-generation/video-synthesis
```
模型名：`wan2.7-r2v-2026-06-12`（最新版）或 `wan2.7-r2v`

### 参考素材格式

```json
"media": [
    {"type": "reference_image", "url": "...", "reference_voice": "...mp3"},
    {"type": "reference_video", "url": "...mp4", "reference_voice": "...mp3"},
    {"type": "reference_image", "url": "...场景图"}
]
```

- `reference_voice`：可选，为该角色指定音色
- 图片和视频分别计数：图1/图2... 视频1/视频2...

## 四、九宫格参考图（wan2.7-r2v 新功能）

传一张九宫格图（多角度/多场景拼在一张图里），prompt写详细角色设定+分镜脚本。

官方示例是3D卡通角色，真人是否适用待验证。

## 五、静态图r2v的局限（实测+文档确认）

- HappyHorse r2v：图片是"角色参考"，文档说"将图像中的主体角色融合生成视频"——融合≠锁定
- wan3.0：支持图片+视频混合，但文档没提"锁定一致性"的保证
- 单张头像照→锁定力极弱，体型/穿着/发型全靠模型编
- 多张图（三视图）→锁定力提升但仍不保证

## 六、提示词层面没有特殊锁人写法

官方文档研究结论：
- **没有**专门的"人物一致性提示词技巧"
- **没有**特定关键词能增强锁人
- **没有**提到三视图比单图更好的说明
- r2v提示词公式：`参考指代 + 动作 + 场景 + 台词（可选）+ 背景音乐（可选）`
- 参考指代写法："图1在图2里玩耍" 或 "图1的猫在图2的房间里玩耍"
- 提示词不描述人物外观（0826用户三次纠正定案，见 happyhorse-wan3-prompt-errata.md 第十节）

## 七、只有一张照片时的最佳策略（待验证）

1. 用codex/Seedream生成全身三视图 → 传HappyHorse r2v多图参考
2. 用i2v（首帧方式）传全身照 → 模型从首帧演化但不锁定后续
3. 传九宫格（多角度拼图）→ wan2.7-r2v单图参考模式
4. 以上都不保证锁定，真正的锁人方案需要视频素材
