## Mac 反向隧道断了怎么判（2026-10-15 实测）

- 症状：`bash /home/ubuntu/ops/mac.sh '...'` 回 `ssh: connect to host 127.0.0.1 port 46223: Connection refused`。**mac.sh 退出码恒为 0（假成功），只看输出不看 rc。** 无头绪时连试 2–3 次即停，别循环空耗。
- 判据（广州侧一条命令）：`ssh -p 2222 ubuntu@127.0.0.1 'ss -lnt | grep 4622; grep -a 223.157 /var/log/auth.log | tail -3'`。无 4622x 监听 = 隧道断；auth.log 给出 Mac（223.157.38.96）最后一次尝试时间。
- 根因：Mac 两个 launchd 隧道任务（com.xiaolu.tunnel / com.newme.tunnel）抢同一远端端口 46222，`ExitOnForwardFailure=yes` 让整条连接（含管理口 46223）一起失败 → 反复 `bind [127.0.0.1]:46222: Address already in use` 后停止重试。
- 广州侧先自检端口是否真被占：`python3 -c "import socket;s=socket.socket();s.bind(('127.0.0.1',46222))"` 能成功 = 端口空闲，问题 100% 在 Mac 侧，SG/广州怎么修都没用 → 报 BLOCKED 要人工唤醒 Mac / 重启隧道守护并卸载抢口的那个 launchd。
