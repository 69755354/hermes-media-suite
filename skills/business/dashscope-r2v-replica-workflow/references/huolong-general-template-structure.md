### duration反推法（0826实测定案 + 0826三次纠正）

**生成底片前必须先转写原片参考视频，统计实际语速，按字数÷语速算duration，不照搬母版上限。**

原片「刘姐自媒体」实测：5.4字/秒（18句199字/36.7s有效语音）

#### ⚠️ 台词总字数也要对齐原片（0826用户三次纠正定案）

用户原话："它原片总共有多少个台词？然后多少秒？对着它那个节奏来重新写不就行了？"

**铁律：新台词的总字数必须接近原片总字数，不能只调duration不改台词字数。**

翻车过程：
1. 第一版HH-1（7s）：19字台词给7秒 → 2.7字/秒 → 用户说"语速太慢了""一点都不像口播"
2. 第二版HH-1（10s）：还是19字给10秒 → 1.9字/秒 → 更慢了
3. 用户纠正："你要参考原视频啊" → 转写原片发现0-9.8s说了54字（5.5字/秒），而新台词只有19字
4. 用户最终定调："它原片总共有多少个台词？然后多少秒？对着它那个节奏来重新写不就行了？"

**根因**：原片0-9.8秒说了54字（5句话连着说），新台词只有1句19字。字数差三倍，给再多duration也慢——模型把19字均匀拖到整个duration里念。**问题不在duration太长，在台词字数太少填不满时间。**

**正确流程**：
1. 转写原片 → 统计总字数（199字）和总时长（36.7s）→ 算语速（5.4字/秒）
2. **新台词总字数要对齐原片总字数**（±10%），不是只写几句短话然后调duration
3. 每段台词字数对齐原片对应段字数（原片HH-1段54字，新台词HH-1也要~50-55字）
4. duration直接用原片对应段时长（取整）
5. 生成后whisper转写验证实际语速与原片对比，差异>10%重写台词

### 派活纪律（0826实测）

- 每步只传 USER_REQ原话 + DATA_SOURCE + PROJECT_DIR + 产出要求，Hermes不夹带判断
- 每步预检：触发词grep + kb_gate_sg.py + task_brief_gate.py（WARN不阻断，BLOCK才停）
- codex产出必须带attest记录
- 串行依赖：分镜依赖台词本，提示词依赖分镜，合成方案依赖分镜+提示词
- 用户说「赶紧做后面的事」= 串行链中前一步在跑时同步准备下一步任务书，产物落地立刻dispatch

### 预检坑（0826实测）

- `kb_checked.json` 必须有 `ts` 字段（格式 YYYY-MM-DD HH:MM:SS），否则 kb_gate BLOCK
- 分镜类任务 `task_brief_gate` 要求 `READ_SKILL=director-thinking`，缺了报 WARN
- 分镜类任务要求 `ASSET_REF=` 指向参考图文件
- 后期方案类任务正文不能写「已确认」（被判判断词 WARN）
- 正文避免出现出片/Seedance/seedance 等触发词（本任务不用Seedance用快乐马，但讨论后期时仍可能误触发）

## 生成与后期约束

1. 快乐马只生成全屏数字人口播底片；App真实录屏、画中画、Logo、大字、下载卡全部后期完成
2. 不让生成模型伪造App中文UI

5. App动态录屏总计5-10秒，必须包含竖屏上下切换
6. 大字只在钩子/产品名/题材榜单/总结/CTA五个节点出现
7. 产品UI/剧名/集数/榜单/操作响应必须来自当日真实录屏，页面没有的信息不写入台词

## 底片台词版本与合成方案一致性（0826实测翻车）

**铁律：快乐马底片的台词版本（网赚版/通用版）必须与后期合成方案的台词版本严格一致。**

翻车场景：先跑的5段快乐马底片是网赚版台词（"看漫剧也能赚钱""火龙币换成现金提走""全部免费观看"），但后期合成方案配的是通用版台词（"追漫剧最烦的就是刚到关键处又被广告打断""选集页从第1集排到第62集""上下切换我也录下来了"）。两套台词完全对不上——观众听到"火龙币提现"但看到的是选集页/分类页，画面与口播逻辑断裂。

**根因**：底片生成和合成方案分两个独立codex任务产出，各自按不同版本的台词本执行。底片按网赚版提示词生成，合成方案按通用版结构分析报告写时间轴。中间没有版本一致性校验。

**防呆检查**：生成底片前，把底片提示词里的台词与合成方案时间轴里的台词逐句核对，确认是同一版本。不一致则停，先统一版本再跑。

### Seedream 文生图调用方法（0826实测成功）

```bash
# ARK endpoint（广州机直接curl）
ARK_KEY="<ARK_API_KEY>2"
python3 -c "
import json
prompt = '人物描述...'
body = {'model': 'doubao-seedream-5-0-260128', 'prompt': prompt, 'size': '2160x3840'}
with open('/tmp/seedream_payload.json', 'w') as f:
    json.dump(body, f, ensure_ascii=False)
"
scp -P 2222 /tmp/seedream_payload.json ubuntu@127.0.0.1:/tmp/
ssh -p 2222 ubuntu@127.0.0.1 "curl -sS -X POST 'https://ark.cn-beijing.volces.com/api/v3/images/generations' \
  -H 'Authorization: Bearer $ARK_KEY' -H 'Content-Type: application/json' \
  --data-binary @/tmp/seedream_payload.json"
# 返回 data[0].url（TOS签名URL）
# 下载走广州机中转：ssh curl -o /tmp/x.jpeg <TOS_URL> → scp回本机
```

注意：
- ARK文生图用 `prompt` 参数（不是 `messages`），跟视频API不同
- TOS下载URL新加坡直连不通，走广州机中转
- size必须≥368万像素（2160x3840=829万像素✅）

COS免费BGM库路径：`/home/ubuntu/assets/bgm/`（29首mixkit+codex曲目）。选择标准：居家聊天感、无歌词、弱鼓点。合成方案要求sidechain duck（人声优先，BGM不盖口播），BGM轨前置 `volume=3.0` 翻倍（见后期合成四铁律第4条）。
