# 老板表固定格式（2026-10-20 用户拍板）

触发：要做「两个号作品 + 星图」的数据表、老板表、给老板看的数据。

## 铁律：照抄列，不自己发明

**20 列，顺序不能变，表头文字不能改**：

```
号 | 作品名称 | 发布时间 | 审核状态 | 播放量 | 星图有效播放 | 分成(元) | 预估收益(元) |
体裁 | 完播率 | 5s完播率 | 封面点击率 | 2s跳出率 | 平均播放时长 |
点赞量 | 分享量 | 评论量 | 收藏量 | 主页访问量 | 粉丝增量
```

规则：
1. **「号」列写「一号」「二号」**，不写账号名、不写 ID、不加括号。
2. **「预估收益(元)」按参考表口径填 0**（整列 0），不要拿分成去顶。
3. 按**播放量降序**排；单 sheet，不分组、不加 ID 列。
4. 末行合计：第二格写 `共N行（一号X/二号Y）`，播放量/星图有效播放/分成 求和，预估收益 0。
5. 抖音侧 16 列原样取「作品列表导出」的 records（完播率、5s完播率、封面点击率、2s跳出率、平均播放时长、点赞/分享/评论/收藏/主页访问/粉丝增量都在里面）。
6. 星图侧按**标题归一化**匹配 `item_name`（去空白全串匹配，再退前 14 字唯一匹配）；星图有效播放、分成取作品卡的值。
7. **星图里有钱但抖音列表没有的作品**，单独补一行（播放量 0，号按星图账号），否则合计会少钱。
8. 合计必须等于任务头部三个数之和，不等就是没匹配全。

## 一键出表

```bash
python3 /home/ubuntu/workflow/projects/win-agent-package-20261015/scripts/build_two_account_table.py \
  --douyin 一号导出.json 二号导出.json --star 星图数据_YYYY-MM-DD.json --out 表.xlsx
```

脚本按「一号, 二号」的入参顺序打号；输出 rows / play / valid / share 做校验。

## 单个号

只有一个号有数据时用 `--labels 一号`，合计仍写「共N行（一号N/二号0）」；另一个号浏览器没打开（9225 未监听）就不要硬凑，交付时说明哪个号没取到。

## 坑

- 作品列表导出里**没有作品 ID**，只能按标题匹配；标题会被复用（同文案多条视频），匹配时按播放量就近选，且一条星图记录只能被认领一次。
- 某个号当天没导出（环境没登录）就用最近一份，但要在交付说明里讲清是哪天的数据，别当成当天。
- 分成/预估只有作品卡上有；接口作品级金额返回 0，靠 `collect_cards.py` 抓卡补齐，再用 reconcile 把角分误差压到任务总额以内。
