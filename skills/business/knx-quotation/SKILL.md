# KNX / 智能家居报价

## 一、开工前必须问清的事

报价前先锁定范围，别自己假设。至少确认：灯光是**仅开关还是调光**（差价极大）、窗帘套数、空调形式（chiller + FCU 还是分体）、FCU 台数与阀门电压（如 230V 三速风机 + 230V 常闭两通阀）、面板数量与颜色（如香槟金）、温控器数量、主控屏、是否含感应器（PIR / 照度——这项经常客户以为含、其实没报）、是否含编程调试（惯例约 4,500 AED）。

FCU 台数和回路划分**必须回到 RCP / MEP 图确认**，别用客户口述的数字。曾出现材料表 3 台、人工表 20 台，差 17 台。

## 二、线材用量：按拓扑算，不要按"每点几米"

原始报价表最常见的错误是所有系统用同一个"每点多少米"拍板。实际同一栋房子里 Cat6 每点约 21m、DALI 灯回路约 13m、KNX 总线每点约 7.5m，**相差 3 倍**。

按三种拓扑分别算（`√单层面积` 是特征边长，`r_h`/`r_v` 是绕行系数，`k` 是校准系数）：

- **STAR**（Cat6、音箱线，回中央机房）= `k·(r_h·0.5·√单层面积 + r_v·层高·平均跨层数)` + 端头余量
- **RADIAL**（DALI 灯回路、窗帘电机、FCU，从本层配电箱出线，不穿楼板）= `k·(r_h·0.5·√单层面积)` + 端头余量
- **BUS**（KNX/EIB 手拉手）= `k·(r_h·0.7·√(单层面积 / 同线型单层点位数))` + 面板下引 + 端头余量

平均跨层数有闭式解：`((f−1)f + (N−f)(N−f+1)) / (2N)`，其中 f = 机房所在层，N = 总层数。

**关键结论：距离随面积走平方根，不是线性。** 面积翻倍，每点线长只涨 19%（星形）到 33%（辐射）。**点位数量才是成本主导项**，所以报价随项目面积缩放时用 √ 关系，绝不能按面积线性放大。

校准系数 k 默认填 1.0，但应该拿一个已完工项目的实际领料量 ÷ 模型算出的米数，把比值填进去。没校准过就在假设页标出来。

材料量按**整卷**取整（如 305m/卷），不要按裸米数报。

## 三、穿线人工：算工时，不要抄"每点单价"

这一条是 2026-08 重建出来的，**上一版模型在这里错得最狠，误差 3.4 倍**。

⚠️ **最大的坑：客户原表里那些"每点 225 / 187 / 250 AED"是对客售价，不是成本。** 那几个数出自原文件一个叫 "Copy of Cable Costing-**Quotation**" 的页（底下还带 Terms & Conditions）。上一版模型把它当成本，又在上面加了一层 20% 毛利，等于向客户收了两遍利润。**看到任何"每点多少钱"，先问它是成本还是售价**；出自 Quotation / Proposal 页的一律当售价。

正确做法是自下而上：

```
每点工时 = 端接分钟（按设备种类给，10–30 分钟，逐行输入）
         + 拉线分钟（每点线长 × 根/点 × 分钟/米 × 场地系数）
每点成本 = 每点工时 × 每分钟人工成本，其中 每分钟成本 = 小组日薪 ÷ (有效工时 × 60)
建议分包单价 = 每点成本 × (1 + 分包利润率)
```

参考值（迪拜，两人一组）：**小组日薪 400 AED/组·天**（区间 350–450）、**有效工时 7 小时**、**拉线速度 1.0 分钟/米**（管路通畅 0.6–0.8，改造/明显受阻 1.5–2.5）、**场地系数 1.15**、**分包利润率 25%**。端接分钟参考：KNX 面板 20、吸顶感应器 15、墙面屏 20、窗帘电机 20、FCU 25、DALI 灯回路 10、门口机 30、摄像机 20、AP 20、吸顶音箱 25。

人工口径做成一个三档开关（自算成本 / 建议分包单价 / **实付分包包干价**）。分包给电工按点位包干时，把实付价逐行填进去、切到第三档，那时候才是真实成本。

**怎么判断人工算得可信**：不要看钱，看物理量。诊断至少给这几个：总组·天、总人·天、**每组每天完成点位数**（正常一天几个到十几个点，出现三四十个点就是某行分钟数填错了）、人工每米 AED/m（2.3–3.0 合理）、**人工占成本比例**（穿线这类活常见 40%–60%，出现 73% 就是异常信号）。再加一个 **6×6 敏感度表**（日薪 300–600 × 速度 0.6–2.5），让人看两个关键假设变了会怎样。

**闭式核对**：另用一条 SUMPRODUCT 独立算一遍人工总额，跟逐行合计相减，结果必须恒为 0。谁改坏了某一行公式，这里立刻不为 0。这个技巧对任何汇总表都值得抄。

## 四、报价表结构：一份数量源 + 两个开关

必须做到，否则漏项无法被发现：

1. **所有数量只在 Points 页出现一次**，材料表和人工表都用公式从 Points 页取数。绝不允许两张表各自手填一份数量——必然打架。
2. **每个系统一个 `Include` 开关（Y/N）**，同时控制材料与人工。这样结构上就不可能出现"有材料没人工"。比如灯回路若属电工分包，把该行改 N，材料和人工同时剔除。
3. **金额一律是公式，不许硬填数字**。曾出现穿线表金额是硬填的，改了数量金额不动。
4. **报价口径开关**（这是第二个开关，必须显式化）：
   - **A 档** = 材料和人工都按成本加成 —— 这是**成本底线**，是跟分包谈价和客户砍价时自己心里的底牌。
   - **B 档** = 材料按成本加成 + 人工按每点对客单价 —— 这是公司实际收的价，通常明显大于 A。
   - **默认设成 B**，并在说明里写清误用 A 会白送多少钱（Fahad 案例差 4.2 万 AED）。同事拿到表不会去读公式，只会看默认值。
5. **"毛利率"要正名成"成本加成率"**。公式是 `成本 × (1 + m)` 的话，20% 加成只等于 16.7% 毛利。加成率填在输入页，**真实毛利率另算一格显示**（`1 − 成本 ÷ 报价`），否则报的价和以为的利润不是一回事。
6. 单独做一页 **Reconciliation**（逐条记录与客户原表的差异和原因，项目专属）与一页 **Assumptions**（所有未核实的数字用 ★ 标出）。给同事用的空白模板不要放 Reconciliation，那是项目专属机制，换成语义分明的每点输入列 + 口径开关。

内部版建议 9 页：Inputs / Cable Prices / Points / Material / Labour / Summary / Area Scaling / Reconciliation / Assumptions。客户版单独出，英文、Times New Roman + Cambria、未定稿时带 DRAFT 提示行。

**表内自检（每张表都要有，交出去之前看这个）：**

- Points 页最后一列逐行校验，亮 ★ 的情形：拓扑不是 STAR/RADIAL/BUS、线材名在价格页里查不到、Include 不是 Y/N、根/点 < 1、端接分钟为 0、选了实付分包口径但那一行没填价。
- 底部和 Summary 各放一个「**校验未通过行数**」计数（`SUMPRODUCT(--(LEFT(校验列,1)="★"))`）。**不是 0 就别报价**——这类错不会让 Excel 报错，只会让金额悄悄算少或算成 0。
- Summary 底部再放：计入点位总数、每点均价、每平米造价、每组每天完成点位数、人工占成本比例、人工闭式核对。

**交付前的检查清单**（都是真出过的问题）：

- 每一项材料是否都有对应的穿线/安装人工？（曾漏掉 384 路 DALI 灯线的全部人工，约 28,800 AED，而材料占了总材料额的 60%）
- 材料表与人工表的数量是否同源？
- 数量口径是否写明？（窗帘"38 vs 19"不是错误，38 = 19 台 × 2 根；墙面屏在 EIB 和 Cat6 各出现一次也是对的，不是重复计算——但都要在备注里写清，否则看的人会当成错）
- 加成率、报价口径、VAT 是不是示例值忘了改？

## 五、价格必须交代来源

**先建一个单一事实来源文件 `price_sources.json`，再让 build 脚本从它取数。** 每条线材记：单价、整卷长度、**可信度分档**（`supplier_quote` / `back_solved` / `estimate`）、来源单号 + 日期 + **有效期**、铜价底线检验结论。`accept.py` 会核对 build 脚本里的价格与它一致，报价过期就报警（`--client` 档会把这个警告升级成 FAIL）。**改价格永远是先改 price_sources.json、再改脚本**，反过来做迟早两边不一致。

每一条价格都要标明状态，不能含糊成"参考价"：公开零售网价 / 代理项目价 / 供应商正式报价（写单号与日期）/ 反推的隐含值 / 暂定估算，以及是否含当地 VAT 和服务费。单独做一页「价格来源 / Price Basis and Sources」放链接与折算汇率（如欧洲零售价按 EUR/AED 4.23 折算）。

**供应商报价单要盯三件事**：有效期（常见只有 7 天，过期就要重新确认）、整卷规格（实测是 **305m/卷**，不是想当然的 100m）、以及**税**——出口沙特的零税率单改送 UAE 要另加 5% 进项 VAT。

**用铜价做底线检验**能识破 CCA 假铜：算出纯铜净重的底价，实价落在底价的 3–4 倍才是真铜；接近或低于底价的要怀疑是铜包铝。

**明确说出局限**：欧洲公开零售价不等于迪拜项目价，正式报客户前应走代理拿项目价，通常会更低。反推出来的隐含单价要标★并说明这不是核实过的市价。**占金额比重最大的那条线如果还是估价，要单独点出来当风险**（Fahad 项目里 RVV 2x1.5 占材料金额 63% 却仍是估价）。

缺价的线材单独做一份询价单发供应商，**刻意不要写上自己的估价和铜价底线**，免得对方照着我们的数字报。

⚠️ **客户版要删来源**：带 Source URL 列和零售链接的版本转给客户会暴露采购渠道与毛利。对外发之前出一版删掉来源列和来源页的 client-clean 版。

## 六、交付格式与工程纪律

**报价单必须带产品图片**，只有型号和价格不合格。

**给可编辑的源文件，不要只给 PDF**。优先给能直接改的版本（xlsx 源件、HTML 拖拽编辑器、PPTX），并留一条回路：他改完导出 → 由你重出正式文件。

### 表格由脚本生成，不要用手改 xlsx

生成脚本是唯一事实来源，放 `~/NewMe/报价工具/03_源码/`；成品每次重建前自动存档到 `_历史版本/`。四条硬规矩：

1. **行高不许写死。** `ws.row_dimensions[r].height = 26` 这种拍板值会静默切断长注释。**也不要按字符数估行数** —— 实测在真实模板上给了 2 个假阳性（145 字符在 113 宽的合并区里一行放得下，103 字符在 40 宽的列里要 3 行，没有任何单一"装填效率系数"能同时说对）。**必须按真实字体度量算**：`fitscan.py` 按字号量 Liberation Sans / Noto CJK 的像素宽再贪心折行，纯静态、不需要 LibreOffice。build 脚本里 `header_row` 的表头行高、以及合并区和显式设过行高的行都走 `fit_row()`。
2. **改价格先改 `price_sources.json`**（见 §五），再改 build 脚本，`accept.py` 会核对两边一致。
3. **改模型必须两个 build 脚本（中/英）一起改**，否则同事拿到的两个版本会算出不同的数；改完立刻跑 `accept.py`。
4. **换列号之后先 grep 跨页引用。** 比如 Include 从 I 列移到 K 列，要先把全部 `Points!$I` / `Points!$J` 之类的引用找出来一起改，漏一个就会拿错列的数。`twin` 关会逐单元格比中英文公式骨架，这类错跑一次就会被抓到。
5. **版本戳只能由 build 脚本写。** 「模板版本 · 构建日期 · git 校验码 · 生成脚本名」写进 `Inputs!A3`。⚠️ 用 openpyxl 打开成品再补写这一格，**有丢掉内嵌 logo 图片的风险**。

### 验收：先跑 `accept.py`，别自己挨个跑检查脚本

```bash
cd ~/NewMe/报价工具/03_源码
python3 accept.py            # 全量 11 关，需要 LibreOffice
python3 accept.py --fast     # 跳过所有要 LibreOffice 的关（8 GB 的 Mac 上用这个）
python3 accept.py --no-build # 不重建，只验现有成品
python3 accept.py --client   # 发客户前的严格档，把"报价过期"这类 WARN 升级成 FAIL
python3 accept.py --bless    # 把当前结果写成新基准；只在已确认改动正确之后用
```

它写出 `report.json` + `report.md`，**退出码非 0 就是「别发」**。十一关（顺序即依赖）：

`env`（Pillow / 字体 / soffice 齐不齐）→ `build`（两个 build 脚本一起跑）→ `stamp`（版本戳）→ `struct`（空白态 + 关键格必须还是公式）→ `twin`（中英文逐单元格比公式骨架）→ `fit`（静态字体度量查行高装不下）→ `fp`（公式指纹对基准）→ `recalc`（LibreOffice 重算）→ `audit`（零错误值）→ `golden`（填 Fahad 那套点位，数值必须落在基准上）→ `layout`（导 PDF 查 `###` 列宽不够 + 页数对基准）→ `regress`（`test_template3.py` 四段回归）。

- `baseline.json` 是黄金基准（每张表的公式指纹 sha + 条数、golden 数值、PDF 页数）。**只有 `--bless` 会改它**，所以 bless 之前必须先人工确认新数值是对的，否则等于把 bug 固化成基准。
- **实测全绿基准（2026-08-19，11/11 通过）**：两版各 809 条公式、指纹一致；golden = 总工时 16076.3 分钟 / 人工成本 19138.40 / 成本合计 42944.40 / B 档含税 98476.56 / 人工闭式核对 0；填数后两版各 16 页。
- `selfcheck.py` 现在只是**本机不装 LibreOffice 时的轻量子集**（纯 openpyxl：工作表齐全、中英文公式总数相等、模板点位数列是空的、关键单元格还是公式、两个人工假设在合理区间）。它能过不代表能发；能跑全量就跑 `accept.py`。
- `test_template3.py` 仍然是数值回归的实体（A 空白态零错误、B 中英逐项一致含人工 8 个诊断、C 与已完工项目内部版对成本、D 故意填 5 处错看是否全部报警），由 `regress` 关调用。**行号一律用标签查找，不要写死**——旧项目文件的 Summary 布局跟新模板不一样，按位置比会静默错位。

### 排版：一条已被证伪的旧结论

⚠️ **「LibreOffice 不能把合并单元格跨页断开、页尾的多行合并说明块会被直接切掉一半」这条旧说法是错的**，2026-08-19 做阳性对照没能复现（4 行合并块在 6 个不同分页错位处逐一扫过，结束标记词每次都在，一个字都没丢）。**但「把长说明改成一行一句、每行单独 merge」这个做法保留** —— 它对分页友好、行高也更好控，只是当初给的理由是错的；敏感度表和校验块前的 `Break` 强制分页也保留（为了版面整齐）。真正会切字的只有**行高**问题，查法见上面第 1 条和 `excel-recalc-verify` 技能。

### 语言与文档

客户是英文时，正式对外文件出英文版，中文版留内部底稿。英文版的稳妥做法是在中文原件**副本上原地翻译**（重命名工作表 → 改公式里的表名引用 → 查表替换字符串），这样产品图、公式、格式全部保留。跑完必须重算——用 `excel-recalc-verify` 技能里的方法，不要用官方 recalc 脚本。

给同事用的东西额外配一份**一页纸上手指南**（单独 PDF + 可编辑 docx，能直接转发工作群），内容就四块：三步出价、格子的颜色约定、两件最容易出事的事（报价口径 + 校验计数）、发客户前必查四条。表内的「使用说明」页留更细的版本，并放**一行真实项目的示例数据**。

沟通用中文，结论先行，末尾附上必须复核的风险点（FCU 台数、阀门电压、回路划分要按 RCP/MEP 图确认）。

## 七、配套点位图
