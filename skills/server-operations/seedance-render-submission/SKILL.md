# Seedance 出片提交与闸管理

## When to Use

- 提交 Seedance 出片任务（/seedance-exact/job）
- PROMPT_PACKAGE 文档要转成 API 可提交文本
- 出片确认被拦（node12_render / confirm_gate / R7 产物绑定）
- 多镜声音一致性检查
- 用户嫌分镜交付报告太多

## 核心规则

### 1. PROMPT_PACKAGE 是给人看的文档，不能直接提交

分镜阶段的四层结构文档塞给 API 会污染 prompt：
- markdown 标题（`### 第一层`）是噪音
- `@图N=/绝对路径` 会把路径当文字；路径走 `reference_images` 参数
- 校验/注释行（「台词校验：N 个句级口播子镜…」「物理段列示合计…」）进 prompt 干扰台词生成
- 参考图已锁人物/场景/材质，prompt 不重复描写参考图已有内容（简化铁律）

提交前清洗：
1. 去 markdown 标题，保留四层正文
2. `@图N=/路径` 改 `@图N`
3. 去校验/注释行
4. 台词保留英文双引号，去反引号/列表符号
5. 参考图顺序固定：人物在前、场景在后、闪屏/素材最后，与 @图1/@图2/@图3 对应

长度实测：API 无硬性限制（helper 透传不截断），~1300 字符可出片；但第三方实测超 80 字符语义解析准确率断崖下跌（76%→39%），指令密度太高模型抓不住重点，能压短就压短。实测案例（2026-08-23 S01）：四层结构原始 4398 字符 → 清洗（去 @图N=/路径、去「全局锁定/参考绑定」等标注引导词）→ 1556 字符可提交；人物/场景/材质描述被参考图锁定，prompt 内重复描写是主要冗余源。

### 2. 出片提交接口（/seedance-exact/job，SG 1889）

必填字段：
- `prompt`：清洗后的提示词文本
- `duration`：4-15 整数秒（2.033s 之类短镜生成 4s 冗余再裁切）
- `reference_images`：项目内绝对路径列表（projects 目录内，顺序与 @图 对应）
- `output_path`：projects 目录内 .mp4
- `customer_id`：权限闸，unlimited 才放行（basic 拦截）
- `project_dir`：项目目录

### 3. 出片确认闸坑（2026-08-23 R7 单向棘轮）

confirm_gate 的 node12_render 确认点 8/23 R7 起绑定产物哈希：
- **一旦确认记录绑定过产物，check 必须提供同一产物，否则拦截**
- 旧确认（R7 前、无 artifact_sha）被拦：`旧确认未绑定产物；当前已启用产物校验，需重新确认`
- 手动 `confirm_gate.py check <proj> node12_render` 不带产物能过（宽限期），但出片接口 `_gate_chain` 带产物调用 → 被拦。必须重新 confirm 绑定产物：

```
python3 /opt/hermes/gates/confirm_gate.py confirm <项目目录> node12_render "<用户出片原话>" <产物绝对路径>
```

产物候选优先级（execute_api.py `_confirm_artifact`）：
1. `guard/confirm_artifact`（显式指针）
2. `staging/SHOT_REF.yaml`
3. `artifacts/A_STORYBOARD.md`
4. `guard/shot_verify.json`

### 3b. 出片上游门禁链（2026-08-23 实测）

`/seedance-exact/job` 的 `_gate_chain` 会先检查 G_RENDER_READY，而它要求上游 G_CREATIVE_READY 已获批（status=ALLOWED），否则 job **秒回 blocked**：
`BLOCKED:G_RENDER_READY:上游门 G_CREATIVE_READY 未获批（status != ALLOWED）`

- 剧本/分镜内容合规修复后，必须**先跑真实 G_CREATIVE_READY**（会自动 ALLOWED 的门），再重新提交出片
- 真实 G_CREATIVE_READY 会调导演 Judge（deepseek-v4-pro 评审最新 3 份创作文件），单次可能 >180s——**用后台跑 + notify_on_complete，禁止前台等超时**
- 剧本哈希变了 → confirm_gate 旧记录绑旧哈希 → 提交前必须重新 confirm 绑定新产物（见第 3 节命令），否则 `_gate_chain` 带产物调用被拦
- 判定是否需重 confirm：`confirm_gate.py status <proj>` 看 `artifact_sha` 是否等于当前 A_STORYBOARD 的 sha256
- **G_RENDER_READY 人工门（2026-08-23 实测）**：G_CREATIVE_READY ALLOWED 后，check G_RENDER_READY 输出 `MANUAL_REVIEW_REQUIRED:render_readiness`，需 approve 放行：
  ```
  python3 /opt/hermes/gates/workflow_gate.py approve <proj> G_RENDER_READY --by <审批人> --evidence <存在且非空的文件>
  ```
  evidence 写 `guard/attest/G_RENDER_READY_evidence_<日期>.md`，记录用户授权原话（用户说「跑/先跑一镜」= 已授权出片，approve 是执行其意图不是代批）。批准后复检 `check G_RENDER_READY` → ALLOWED，再重新提交 job。

### 3c. 长提示词先试跑偏好（2026-08-23 天行者定案）

用户原话：「你现在这个提示词这么多还不一定SD能理解，先看看效果吧」。**提示词纸面合规 ≠ 模型理解**——四层结构一大坨（S01 清洗后仍 1556 字符）Seedance 不一定抓得住重点。新分镜/新结构首次出片：先抽**最复杂一镜**（覆盖运镜+口播+素材直出）试跑，重点检查人物还原/运镜方向/手机屏直出/口型四件事，效果确认后再批量。出歪了正好暴露是提示词太长该精简还是结构问题，拿效果说话再改。

### 3d. 出片质量实测教训（2026-08-23 S01 试跑，天行者逐项反馈）

Seedance 对长 prompt 的「文字意图」执行有偏差，试跑后逐项核（用户会看：语速/运镜/念错字/手机屏）：

| 问题 | 现象 | 修法 |
|---|---|---|
| 语速偏快 | 写「语速适中、吐字清晰」，10s 塞 9 句台词实际读得明显快（用户：「语速太快了把」） | 改「语速从容偏慢、吐字清晰，短句之间留出自然停顿、从容不赶节奏」；「兴奋」基调也诱发加速，收敛它。先改一镜验证，确认有效再同步其余镜的「语速适中」 |
| 运镜不对（含反向/僵硬） | 写「0—5秒画面明显拉远」「绝对不是推近」，实际反向推近或观感僵硬（用户：「运镜还是有问题」） | **根因第一优先查动作缺失**（2026-08-23 用户点破：「运镜差别就是因为参考视频是走动的」）——原片人物边走边讲撑起运镜感，成片人站原地+镜头干拉=又近又僵。修法=补走动轨迹（按原片实测：几秒开始走/往哪走/幅度/停哪）进 prompt 动作层，运镜措辞配合改（直白相机语言「摄影机从近处向后拉开距离，人物在画面中逐渐变小」），不要只改运镜字眼治标 |
| 走动/动作缺失 | 原片有走动过程，成片站原地不动（用户：「很僵硬」） | 复刻源头检查（见 3f）：SHOT_REF 可能漏动作，先查 SHOT_REF 动作 sequence，再逐帧对比原片实测补轨迹 |
| 念错字 | 多句台词场景有念错/吞字（用户：「还念错字」） | 试跑后转写成片音频（本地 faster-whisper，禁付费云转写）对照台词表逐句核，定位具体句和字 |
| 起幅景别偏近 | 原片 0s 中景（大腿可见），成片裁到胸部=近景，人物显近显满（用户：「开始坐的太近了」） | 起幅景别按原片实测对齐：抽原片 0s 帧 vision 确认裁切位置，把景别描述写准（能见大腿的中景 vs 只到胸的近景） |
| 参考图内容被重绘 | @图3 素材可能被模型重绘成近似字样/图案，非原素材像素还原 | 试跑后 vision 核屏幕内容与原素材差异 |
| 声音不自然 | AI 味/表演感重（用户：「声音也不好听」） | 声音描述往「自然聊天感」调，去生硬表演词；音色/语气基调收敛 |

台词原文、时码、硬切点是不可改基线；只调动作轨迹/声音描述/运镜表述/景别。改 prompt 后哈希变 → 重新 confirm + 两道门禁重跑。

### 3f. 复刻源头缺陷检查（2026-08-23 火龙 S01 定案）复刻链路：codex 逐帧实测原片 → SHOT_REF.yaml（唯一画面依据）→ 分镜回指 → prompt 回指。**每一环都忠实回指 ≠ 复刻到位——SHOT_REF 本身是 codex 实测产物，可能漏动作**（实测案例：原片 S01 有走动过程，SHOT_REF 动作 sequence 只写了「身体后移并由坐姿过渡到站立」，无「走动」二字 → 分镜、prompt 照搬 → 成片站原地僵硬。用户批评：「你这个复刻怎么这些东西都没复刻到呢」）。

规则：
1. 复刻类任务出片后**必须抽帧 vs 原片对比验证**（见 3e），不能信任「分镜回指了 SHOT_REF」就认为复刻到位
2. 发现一镜有问题（走动/运镜/景别），**全片 8 镜逐镜过一遍**（用户原话：「把整个视频都过一遍，这个问题其他镜号肯定都有」）——不是修补丁式只修出问题的镜
3. 核对动作时看 SHOT_REF 的 `动作.sequence` 是否漏了移动类动作（走动/位移/转身/换位），对照原片逐时点帧确认
4. 全片重新实测任务派 codex：任务书给原片路径+SHOT_REF+A_STORYBOARD，要求逐镜抽帧（每镜起/中/落多时点）vision 分析实际运镜/动作/景别/走动轨迹，输出全片差异清单 → 再按差异清单重新出分镜（8 镜全修，不只 S01）

### 3g. Seedance 能力边界与验收硬门（2026-08-23 S01 对比报告确认）

以下四条是模型能力边界，prompt 再堆同义词无效，验收时按此设目标：

1. **手机屏 reference_image 是参考重绘，不是像素贴图**。状态栏/标题/图标/主体会被重绘成替代页面（S01 实测 4/6/8/10s 同错跨帧稳定，排除运动模糊）。prompt 写「完整保留原素材图形和文字」无效。验收目标二选一：接受近似品牌页，或后期四点透视跟踪贴图（prompt 让屏幕区纯黑无字作可跟踪平面）。**⚠️ 方案选择权在用户历史裁定，不在执行器/最新报告（2026-08-23 实测）**：codex 按 S01 对比报告建议把手机屏改成「底层深灰暗屏+后期贴 @图3」，但火龙历史裁定是「手机屏品牌页=@图3 三图直出（生成时放屏内，禁后期贴禁重绘）」，用户此前也明确「重绘勉强可以接受」= 保留直出方案——执行器按最新分析报告改方案 = 偏离裁定。防再犯：重出分镜任务书**显式携带用户历史裁定**（@图3 直出 vs 后期贴按项目定案写死）；复核 codex 产出时对照裁定逐项核（本类改动最容易在执行器「合理化」下悄悄换方案），发现偏离立即向用户确认，不默认执行器方案。
2. **台词时码不能执行 50ms 级裁切**。跨镜句「只留 0.050s 起声」会被整句提前说完（S01 实测 #09 提前 1.86s 全落入本镜）；长台词+密集时码+多层视觉约束同 prompt 时模型把精确台词当软约束（错读漏字实测 #02/#03/#07/#08）。修法：音频链路分离——单独生成 ≥11.8s 连续音频逐句对齐、0.000—0.500 静默，Seedance 只做无声画面/参考音频口型，最终覆盖音轨。ASR 验收：同音正字差异（赚/转、币/壁）需听感复核，不单凭 ASR 判错。
3. **@图1 背景污染**：人物参考图自带室内背景（电视/柜/椅）会被模型继承进生成画面，挤掉 @图2 场景布局。输入侧修复：@图1 用纯白底三视图或抠背景人物图；prompt 追加「@图1 只提取人物的脸、发型、体型和服装，完全忽略并禁止继承其背景，@图2 是唯一场景依据」。
   **⚠️ 三视图副作用（2026-08-23 rev3 实测）**：三视图人物是**空手**的，模型会继承「空手」→ 不画手机/道具（对比：上一版带手持物的半身像参考图有手机）。换三视图后必须在**每一层** prompt 强化持机（第一层「男主全程手持同一部手机，约3秒后举至画面右侧亮屏朝镜头，全镜不放手、不消失」+ 负面加「手机消失」），否则核心道具直接消失。
4. **拉远落幅验收以「见脚见地」为硬门**：原片落幅完整见鞋和脚下地面，生成只到大腿=拉远幅度不够（约少 25-30%），不能把「方向正确」当合格。prompt 写「完整拍到头顶、双侧裤脚、两只黑色皮鞋和鞋下地面，脚下保留 4%—6% 地面」；验收抽 6s 帧，头部高度应接近原片（S01 目标 17%H vs 实际 22%H）。
5. **动作节拍**：多动作并发（站起+拉远+举机+手势+口播）模型会抢跑/延迟（S01：站起提前 1s+、2s 招呼手势丢失、讲解手势晚 2s）。「稳定」要写成「摄影机稳定、演员继续讲解」，避免模型把后半段当全身静止。

### 3h. 负面区与正面指令一致性（2026-08-23 rev3 实测，手机消失根因）

Seedance 对负面约束的权重可能高于正面指令。实测案例：正面要求「@图3 三图融合直出（生成时放屏内）」，负面却写了「禁止模型生成……@图3内容」——模型直接不画手机屏、甚至不画手机（0s/5s/7.5s/10s 全帧无手机）。**禁止列表里绝不能出现正面要求生成的内容。**

规则：
1. 负面区只禁与正面不冲突的东西；「禁止生成 X」里的 X 必须是正面完全不想出现的内容
2. 正面要求直出的 @图N，负面写法是「除 @图N 既有内容外，不得生成任何其他可读中文/Logo/金额/UI」，不是「禁止生成 @图N」
3. 核心道具（手机/持物）从参考图换掉后（如换三视图），prompt 每层都要出现「手持同一部手机/全镜不放手」；负面加「手机消失」
4. 即使如此，模型仍可能中途丢道具（rev3：4s 有手机、8s 手机消失）——prompt 无法 100% 锁死道具持续在场，**出片后先抽帧自查「道具是否全程在场、有无中途消失」再发用户**，不要等用户看完打回

### 3e. 原片 vs 成片对比方法（试跑质检）

1. 抽帧对齐时点：原片（60fps）与成片（24fps）同取 t=0/2/4/6/8/10s 帧：
   ```bash
   ffmpeg -y -ss $t -i 原片.mp4 -frames:v 1 -q:v 2 ref_${t}s.jpg
   ffmpeg -y -ss $t -i 成片.mp4 -frames:v 1 -q:v 2 gen_${t}s.jpg
   ```
2. vision 逐时点对比：景别、人物占画面高度比例、姿势手势、手机状态、服装场景还原度。**运镜方向判定优先用头部尺度（拉远=头部变小），不能用「可见人物框比例」**——人物站起/下沿裁切会让可见框比例回升，看着像推近（2026-08-23 实测曾据此误判「拉远做成推近」，codex 用头部高度 39%H→24%H 证明实际是先拉远后稳定，真正问题是拉远幅度不够）。
3. 台词：`ffmpeg -i 成片.mp4 -vn -acodec pcm_s16le -ar 16000 -ac 1 out.wav` → 本地 faster-whisper 转写 → 对照台词表逐句找念错/多字/少字
4. 产出逐时点对照表 + 差异清单 + 根因推测（对应 prompt 哪句）+ 修改建议；这类分析任务派 codex（有 vision）执行，任务书给帧图目录+SHOT_REF+台词表

### 4. 多镜声音一致性锁（2026-08-23 天行者纠正）

8 镜分开生成，同一角色声音最易漂。锁定方法：
- 同一角色各镜声音描述段**逐字一致**（复制粘贴式锁定：年龄/音色/语速/吐字）
- 只允许表达基调按本镜内容微调（分享感/讲解/收口）
- 检查：grep 各镜「同步生成中文男/女声」段对比；男主五镜同一段、女主两镜同一段
- 台词靠时码+原文锁定，语气描述不能各镜冲突

### 5. 交付纪律（2026-08-23 天行者纠正）

分镜交付只出**主文件**（分镜脚本），素材映射合并进脚本素材引用段；自审/实施报告等流程文件归档不端给用户。用户原话：「你出个脚本分镜还要写这么多报告的吗」。
- **出片验证阶段用户说「发出来看看」指视频本体（MEDIA: 路径直接发），不是提示词文本/分析报告（2026-08-23 实测被纠正：「我是说视频」）**。提示词可以顺带给，但主交付物永远是视频；先把视频发出去，文字说明跟在后面。

## 调试坑

- `/job/status` 轮询长脚本易误报 404；直接 `curl -s -X POST http://127.0.0.1:1889/job/status -d '{"job_id":"..."}'` 看真实状态
- job 可能秒回 blocked（gate 拦），轮询看不到就误以为在生成——先查 job 真实 status 再判断
- 已提交任务绝不杀进程：钱已花，等跑完收结果
- **部署后回归脚本先核对函数签名（2026-08-23 实测踩坑）**：`workflow_gate.py` 的 `locate_creative_prompt_files(proj, reg=None)`——**第二个参数是 registry（注册表），不是 scope**；scope 在函数内部自己从 `creative_scope_config()` 读。回归脚本若按旧版写 `locate_creative_prompt_files(proj, scope)` 会把 tuple 当 reg 传 → `AttributeError: 'tuple' object has no attribute 'get'`。部署脚本的验证段先 `grep -n "def locate_creative_prompt_files"` 确认签名再写调用。
- **director_review_scorer 模型配置读 `auxiliary.model.default`，不是顶层 `model.default`（2026-08-23 部署时发现并修正）**：codex 按「从 config 读 model.default」实现 `load_model()`，但本机顶层 `model.default` = 主对话模型（deepseek-v4-flash），辅助任务（评审/质检）专用模型在 `auxiliary.model.default`（deepseek-v4-pro）。不修正会把导演评审降级成 flash。修正逻辑：优先 `cfg["auxiliary"]["model"]["default"]`，缺失回退顶层，再缺失回退 hardcode 兜底。
