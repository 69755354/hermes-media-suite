## Docker Compose vs Direct Run

Two options found:

### Option A: Docker Compose (from repo's compose.yml)
```yaml
services:
  astrbot:
    image: soulter/astrbot:latest
    container_name: astrbot
    restart: always
    ports:
      - "6185:6185"
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - ./data:/AstrBot/data
      - /etc/localtime:/etc/localtime:ro
```

### Option B: Direct Docker Run (used in this session)
```bash
sudo docker run -d \
  --name astrbot \
  --restart always \
  -p 6185:6185 \
  -e TZ=Asia/Shanghai \
  -v /home/ubuntu/AstrBot/data:/AstrBot/data \
  -v /etc/localtime:/etc/localtime:ro \
  soulter/astrbot:latest
```

## Disk Cleanup Required Before Pull

AstrBot Docker image is 2.66GB (659MB compressed). On a full 40GB disk:

```bash
# Before: 99% full (551MB free)
sudo docker system prune -af                    # Freed 2GB

```

## Config file location (inside container)

`/AstrBot/data/cmd_config.json` — the `platform` array holds bot configs. On first run this is auto-generated with empty platform array.

## QR Code Login

Adapter URL: `ilinkai.weixin.qq.com` (Tencent official)
- Endpoint: `POST /ilink/bot/get_bot_qrcode` with `?bot_type=3`
- QR valid: 5 minutes, auto-refresh on expiry
- Login state persisted in `cmd_config.json` (token field auto-populated)
- Supports concurrent mobile + server login (phone stays online)

## Notes

- The AstrBot dashboard index.html is served as SPA from `/AstrBot/astrbot/dashboard/dist/`
- Initial credentials (`astrbot`/<random>) are generated by the container's first-run init script
- Password change (`password_change_required: true`) is enforced via dashboard redirect, not API block
- Provider config must be added separately for the bot to actually reply to messages
