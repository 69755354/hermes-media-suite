# 视频模板对比分析方法（2026-08-27 实测）

> 触发：用户分析完一条视频后说「跟我们XX模板对比」「跟网赚模板比一下」「拿XX和YY对比」。
> 前置：已完成视频提取（下载+转写+抽帧+vision分析），拿到口播逐字稿和逐帧画面描述。

## 工作流

### 步骤1：确认对比双方文件都在本地

**🚨 最重要：先确认两个视频文件都存在于本地，缺的先下载。**

用户说「拿XX和YY对比」时：
1. 用 `search_files` 或 `find` 确认两个mp4文件都在本地
2. 如果其中一个只有抖音链接没有本地文件，**先下载再对比**——用 `scripts/douyin_download.py <video_id>` 下载
3. 如果下载失败（抖音反爬/cookie过期），如实告诉用户「这个视频我没下载到本地，你再发我一次」，**不要拿别的文件顶替**
4. 特别注意：抖音链接 `https://www.douyin.com/video/<id>` 的 video_id 直接对应本地命名 `<id>.mp4`，搜索时用这个ID

**教训（2026-08-27）**：用户说「拿小刘吃瓜子那个和夜店那个对比」，我直接发了V7刘姐版到群里——拿错了对比对象。用户要的是「吃瓜小刘子」那条抖音链接的视频（7667831952510045491），不是V7。那条视频只在之前的会话里分析过（vision看过画面），但从未下载到本地——会话断了之后上下文丢失，凭模糊记忆拿了V7顶替。

### 步骤2：定位内部模板定义

搜索项目目录里的模板定义文件：

```
search_files(path="<项目目录>", pattern="网赚|通用|模板|核心承诺|痛点|CTA", target="content")
```

关键文件通常包括：
- `生产方案.md` — 模板定义、结构骨架、分镜表、SOP
- `拆解报告.md` — 原片结构分析
- `_知识库引用.md` — 合规边界和模板判定规则

### 步骤3：提取对比维度

从模板定义文件中提取以下维度（以生产方案 A2 边界表为基准）：

| 维度 | 说明 |
|:---|:---|
| 核心承诺 | 模板卖什么（追剧体验 vs 赚钱 vs 免费看） |
| 主要痛点 | 钩子切入点（广告打断 vs 奖励门槛 vs 逐集解锁） |
| 必备证据 | UI展示方式（真实录屏 vs 贴图 vs 无） |
| 人设 | 数字人特征（年龄/性别/穿着/场景） |
| 机位/画面结构 | 固定中近景 vs 人物→剧情→界面循环 |
| 底部声明 | 有无提现/合规小字（判定模板归属的关键） |
| CTA | 下载链接 vs 账号关注 vs 其他 |
| 时长/分辨率 | 模板标准 vs 实际视频 |
| 字幕 | 跟随方式和样式 |

### 步骤4：模板归属判定

按生产方案边界规则判定：
- **只要「金币/红包/激励/提现」出现在核心钩子、主要证据或CTA → 网赚口播**
- **口播不提赚钱但底部有提现声明 → 软网赚（口播走产品推广路线，合规声明带出激励属性）**
- **口播只讲追剧体验，无激励信息 → 通用口播**

### 步骤5：输出对比表+差异分析

结构：
1. 逐维度对比表（视频 vs 我们的模板A vs 模板B）
2. 关键差异点（3-5条，每条说明差异+影响）
3. 对我们模板的启示（可借鉴什么/要规避什么）

### 步骤6：发飞书群（如用户要求「发群里」「发对比到群里」）

1. **压缩**：成片>8MB 飞书内联发送可能失败，用 ffmpeg 压到8MB以下：
   ```bash
   ffmpeg -y -i <输入.mp4> -c:v libx264 -crf 28 -preset fast -c:a aac -b:a 128k /tmp/<输出>.mp4
   ```
2. **发视频**：用 `feishu_send_video.py`（路径在 `server-operations/cos-object-storage/scripts/`）：
   ```bash
   python3 ~/.hermes/skills/server-operations/cos-object-storage/scripts/feishu_send_video.py <视频路径> <chat_id> "<文件名>"
   ```
   - chat_id 素材群 = `<MATERIAL_GROUP_CHAT_ID>`
   - 每次换带时间戳的新文件名，否则飞书缓存成旧消息
3. **发对比文字**：用飞书API发text消息（token获取同 feishu_send_video.py 的凭证）
4. **三个消息可以并行发**：两个视频+一个文字，放在同一turn的两个terminal调用并行执行

## 群聊待办任务检查（2026-08-27 实测）

用户说"群里的任务做了没"时，用 `feishu_pull_group.py` 拉群消息检查待办：

```bash
python3 ~/.hermes/skills/content-extraction/video-content-extraction/scripts/feishu_pull_group.py <MATERIAL_GROUP_CHAT_ID> 30
```

从消息列表里识别：
- `from=ou_81da2...`（方沐阳）的指令消息 = 待办任务
- `from=cli_aaf4...`（bot自己）的消息 = 已完成的回复
- 对照时间线，bot还没回的就是待办

**常见待办信号**：
- "字幕/音量太小了" → 需要调ASS参数+重新合成。**⚠️ 先核实"这个"指哪个视频**（见下方"群聊任务核实铁律"），不要猜
- "再调整一版看看效果" → 需要出修正版
- "分析下这个视频" → 需要下载+拆解
- "跟我们XX对比" → 需要对比分析

**⚠️ 关联铁律**：拉到待办任务后，动手前必须确认任务指向哪个文件——见上方"群聊任务'这个'指向哪个视频"章节。

## 🚨 群聊任务"这个"指向哪个视频——先核实再动手（2026-08-27 老板三次纠正）

**血泪教训**：方漠阳在群里说"这个字幕和音量都太小了"，我**没核实"这个"是哪条视频**就动手改了V15夜店版，被问"她让你改的是这个视频么"时猜了V15，被质疑后改口说"可能是吃瓜小刘子"，再被追问"你改半天连改哪个视频都没搞清"。**老板不得不自己翻群消息截图、指引我看 gateway 日志确认。**

**核实三步（全部靠工具查证，不靠猜）：**

1. **拉群消息** `feishu_pull_group.py` 按时间顺序看——"这个"前面最近一条视频/media 消息就是所指对象
2. **nonsupport 消息查 gateway 日志**：群消息显示 `nonsupport` 的视频消息，用时间戳去 gateway.log 交叉定位。时间戳转北京时间：
   ```bash
   python3 -c "import datetime; print(datetime.datetime.fromtimestamp(<ts>/1000, tz=datetime.timezone(datetime.timedelta(hours=8))).strftime('%m-%d %H:%M:%S'))"
   grep 'MM-DD HH:MM' ~/.hermes/logs/gateway.log
   ```
   日志会记录当时收到什么消息、私聊里用户说了什么（如"你发的是网赚版"），直接确认内容
3. **手机截图**：如果用户给了手机截图，看消息时间戳和发送者，比文字推断更可靠

**绝对禁止**：
- 不核实就猜"这个"指哪个文件，然后动手改
- 被质疑时立刻改口（说明本来就没底，属于盲猜）
- 拿"可能"当确定结论去执行

**特别提醒**：群消息里 `nonsupport` 类型的消息（video/media）在飞书 API 也返回 `nonsupport` 查不了详情，但 gateway 日志有完整记录（谁发的、什么类型、私聊里用户怎么说的）。gateway.log 是真相来源。

**⚠️ gateway日志查证具体方法（2026-08-27 实测定案）**：
1. 群消息时间戳转北京时间：`python3 -c "import datetime; print(datetime.datetime.fromtimestamp(<ts>/1000, tz=datetime.timezone(datetime.timedelta(hours=8))).strftime('%m-%d %H:%M:%S'))"`
2. `grep 'MM-DD HH:MM' ~/.hermes/logs/gateway.log` — 看那个时间点发了什么
3. 关键线索类型：
   - `reply_to_id=om_xxx` — 方漠阳回复的是哪条消息（message_id），就是"这个"所指的视频
   - 私聊里用户说的话（如"你发的是网赚版"）— 直接确认视频内容
   - `Sending video attachment (.mp4) to oc_52b229` — bot发了视频到群里
4. 如果群里发的视频是bot自己发的（不是用户发的），查当天的session_search看发了什么文件

**⚠️ 用户发视频附件时的处理（2026-08-27 实测）**：
用户直接发视频文件到私聊（如 `18446744072187255816.mp4`）时，这就是"11:05发的视频"的实物证据。必须：
1. `ffprobe` 查元数据（时长/分辨率/编码）
2. `ffmpeg -af volumedetect` 查音量
3. `fps=1` 抽帧 + `vision_analyze` 看内容
4. `faster_whisper` 转写台词
5. 对比项目目录里的已有版本，确认这是哪条视频
不要只看文件名（文件名是消息ID不是内容标识），要看视频内容本身。

## 实测案例（2026-08-27 火龙漫剧）

对比对象：抖音视频 7667831952510045491（账号「吃瓜小刘子」）
对比模板：通用口播模板（huolong_general_template_v1）+ 网赚口播模板（V15夜店高颜值版）

**关键发现：**
- 该视频口播全程不提「赚钱/提现/金币」，只讲「免费/不用会员/不卡顿」
- 网赚属性完全靠底部合规声明暗示 → 「软网赚」策略
- UI是贴图不是真实录屏 → 低成本批量出片路线
- CTA是账号关注不是下载 → 种草导粉而非直接转化
- 30s比我们40s模板短10s，少了榜单页和播放操作页证据

**V15夜店高颜值版结构（40.5秒）：**
- 0-10s：女口播（酒吧场景，黑丝绒裙，举手机展示）
- 10-12s：男口播（电梯走廊，蓝缎面衬衫）
- 12-18s：App福利中心+金币弹窗+提现演示
- 18-22s：App首页（全本免费/题材分类）
- 22-28s：App选集界面+找片瀑布流
- 28-35s：App短剧播放页（大圣金身特效/1820金币）
- 35-40s：片尾引导卡（红色箭头→左下角下载）

**对我们模板的启示：**
1. 「软网赚」策略可参考——口播不提赚钱降低审核风险，但客户指定要讲赚钱时不能擅自改方向
2. 贴图替代录屏是低成本但高风险路线，我们坚持真实录屏是对的
3. 品类列举一口气打包6个 vs 我们逐页举证——前者省时但证据力度弱

## 两条视频端到端对比流水线（2026-08-27 实测，GLM 全量内联方案）

> 触发：用户给一条外部抖音链接 + 一条内部成片，要求对比分析。
> 前置：两条视频文件都在本地（缺的先下载）。

### 执行步骤

1. **并行 ffprobe**：两个视频同时拿时长/分辨率/编码（一个 terminal 调用，两条 ffprobe 串行写在同一命令里）
2. **并行 whisper + 抽帧**：两个视频同时提音频转写 + fps=1 抽帧（两个 terminal 调用并行，各跑各的）
3. **并行 vision 逐帧**：两个视频的关键帧分批送 vision_analyze（每轮7帧并行），每帧问：人物特征/场景/画面风格/构图/文字UI/手机界面
4. **补字幕文件**：如果某条视频是内部成片，搜项目目录里的 `.ass`/`.srt` 字幕文件作为权威台词来源（whisper 可能有长段缺失，见 SKILL.md 的「whisper 长段缺失」坑）
5. **打包 GLM 对比分析**：把两条视频的完整数据（元数据+逐帧画面分析+口播台词+画面结构时间轴）全部内联塞进任务书 USER_REQ 里，让 GLM 一次出报告。**关键：数据内联不让 GLM 自己读文件**——5700字任务书2轮完成，让 GLM 自己读4个文件要25轮耗尽
6. **GLM 任务书对比维度模板**（10维）：钩子策略/目标用户/人设策略/场景策略/卖点结构/App界面展示/台词话术/节奏结构/合规标注/优劣势与适用场景。每个维度先出对比表(A vs B)再出1-2句关键差异解读，最后出总体结论和投放建议

### 关键坑
- **whisper 长段缺失**：v15 的 40.5s 音频 whisper 只转出 0-10.5s 和 31-40s，中间 20 秒空白。从 `.ass` 字幕文件拿到完整 28 句台词补上。**先搜字幕文件再判断 whisper 是否完整**
- **GLM 数据内联**：把所有数据（逐帧画面分析+台词+元数据）直接塞任务书 USER_REQ，不让 GLM 读文件。对比分析类的 10 维框架任务书约 7000 字，GLM 2 轮完成
- **GLM gate token**：用 `python3 -c` 一行脚本生成 token JSON（含 sha256），不用 heredoc（变量不展开会失败）
- **抖音 video_id 提取**：`https://www.douyin.com/video/<id>` 直接取 URL 末段数字部分即可，不需要短链重定向
