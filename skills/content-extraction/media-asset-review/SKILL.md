# 素材审核与交付纪律

用户要审查提取的素材（截图/帧/logo/界面图）判断哪些能用时的交互纪律，以及飞书收不到图片/视频的排查。

## When to Use
- 用户发「logo」「素材发给我看看」「哪些可以用」→ 逐张审核流程
- 用户发了图/视频但 Hermes 收不到（「我给你图了啊」）→ 入站接收排查
- 用户要看我截图的素材 → 单张交付

## 一、逐张审核交互纪律（2026-08-18 用户两次纠正）

- **一次只发一张**：用户说「一张张发」= 严格单张，一次 MEDIA: 一条。批量刷图（一次发 12 张）会被骂「你听不懂我说话吗」。宁可多轮往返，不批量。
- **等确认再发下一张**：用户说「等我确定完再发下一张」→ 发完当前这张就停，不主动推下一张；用户说「下一张/发」才继续。
- 用户对每张给结论：留 / 删 / 修。
  - 删：先 `search_files` 全项目 grep 文件名查引用，无引用再 `rm`，删完报剩余数量
  - 修：先备份 `.bak` 再覆盖（铁律）
  - 留：口头确认即可，继续下一张
- **发图前先确认文件存在**：`ls -la` 验证路径，避免 MEDIA 404。
- **视频交付：用户说「发出来看看」= 发视频文件本体，不是文字描述**（2026-08-23 实测教训）。视频生成完成后（如 `staging/test-shots/*.mp4`），用户催「把刚刚生成的发出来看看」「我是说视频」「快点」——根因是 bot 只回了文字/说明没发 mp4。规则：**视频生成任务结束即发视频文件（MEDIA: 或飞书 file 消息），先发视频再补文字**；若视频还在生成中，明说「正在生成预计 X 分钟」，不要只回文字让用户误以为卡了。检查清单：`ls -la` 确认 mp4 存在 → **`ffmpeg -v error -i file.mp4 -f null -` 验证可解码** → 发文件 → 一句话说明这是什么版本。
- **视频文件完整性验证（2026-08-26 实测教训）**：SCP 传输中途被 kill 或传输未完成时，文件可能：(a) ffprobe 元数据显示完整时长/规格但实际 H264 NAL unit 损坏；(b) 实际可解码帧数远小于元数据声称的帧数（如声称 20 秒 600 帧，实际仅 110 帧 3.7 秒）。**发视频给用户前必须跑 `ffmpeg -v error -i file.mp4 -f null - 2>&1 | wc -l`**，error 行数>0 = 文件损坏，不能发。被用户说「打不开」再查已经晚了。另外：raw decode 字节计算法（`ffmpeg -i file -map 0:v -f rawvideo - | wc -c` 除以 `W*H*3`）可快速估算实际可解码秒数，对比元数据时长判断是否完整。
- **「你自己看」≠「发给我看」（2026-08-26）**：用户说「你自己看」= 让 Hermes 用 vision_analyze 抽帧自检，不是把视频/图片发给用户。用户说「发出来看看」「发出来」= 发文件给用户。两者完全不同，搞混了会浪费一轮往返。正确流程：生成完→先抽 6-8 帧 vision_analyze 自检人物/场景/画面质量→自检没问题再发文件给用户看。
- **成片交付前质检（2026-08-24 火龙 v12 实测，合成后必做）**：①ffprobe 核规格（时长/分辨率/30fps/h264+aac）；②`volumedetect` 验音频：`ffmpeg -hide_banner -i 成片.mp4 -af volumedetect -f null - 2>&1 | grep -E "mean_volume|max_volume"`——mean -14~-20dB 有声正常、`-inf` 静音轨、max 贴近 0dB 是 limiter 顶住可接受；③**抽 7-9 帧（如 1/5/10/15/20/25/30/35/38s）xstack 拼 3x3 接触表一次 vision 检查**，替代逐张 vision：`for t in 1 5 10 15 20 25 30 35 38; do ffmpeg -y -ss $t -i in.mp4 -frames:v 1 -q:v 2 /tmp/qc/f_${t}s.jpg; done` 再 xstack 拼图，vision 提问模板「逐格检查黑屏/花屏、贴片出画或裁切、字幕完整性、风格一致性、画面错乱」。全过才交付。

### 改一个点不要动其他元素（0906 用户两次纠正）

用户说「箭头放上点」→ 只移箭头 y 坐标，不要顺便改素材尺寸、logo 显示时段、其他参数。自作主张改其他元素 = 破坏已调好的状态，用户要重来一遍。

**铁律**：用户指出问题时只改那一个点，改完确认其他元素参数原封不动，再抽帧验证发用户。即使用户的改动暴露了其他问题，也等用户自己说。

### Vision 自检不能走过场（0906 用户质疑「你是不是不能识图了」）

抽帧做了 vision_analyze，vision 明确返回「素材占 65% 画面」「人物脸部全部被遮挡」，但没认真读返回内容就报「质检通过了」。

**铁律**：vision_analyze 返回后必须逐句读完，重点看：①素材尺寸占比（>50% = 太大）②是否提到「遮挡」「覆盖」③logo 是否存在 ④人物脸部是否完整露出。任何一项不达标 = 不通过。不能只看 vision 给了描述就当通过。

### 发群里指定对象（0906）

用户说「发到群里给方漠阳」→ 用 `hermes send --list feishu` 查群列表，找到目标群的 chat_id，`hermes send --to feishu:<chat_id> "MEDIA:/path"` 发送。不要问用户群 ID 是多少，自己查。

## 二、复刻类素材可用性判定

- **原片人物特写帧 = 废素材直接删**：复刻要换人，原片人脸/身体局部画面不能用作贴图素材（实例：界面_13s/17s/21s_crop 都是女性特写，全删）
- 只有 App 界面/无人物画面才保留（实例：选剧筛选页 19s/23s/25s 留）
- 用户提供的素材（logo/闪屏页/品牌页）落盘 `assets/materials/` 并登记 `素材位置记录.md`，只记位置不参与生成

## 三、图片修边对齐（PIL）

截图顶部黑边/右侧白边等多余区域：

```python
from PIL import Image
img = Image.open('x.png')
w, h = img.size
cropped = img.crop((0, top_cut, w, h))  # top_cut 像素数先用 vision zoom 确认
cropped.save('x.png')  # 先 cp x.png x.png.bak
```

- 修前 vision zoom 确认黑边边界（整体偏暗时亮度阈值检测不可靠，直接 zoom 看）
- 裁完发回给用户确认效果

## 四、飞书入站图片/视频收不到排查

**根因：** `~/.hermes/hermes-agent/plugins/platforms/feishu/adapter.py` 的 `_IGNORED_INBOUND_MESSAGE_TYPES`（约 L290）在入口直接 return 非文本消息。08-17 防 emoji/sticker 打爆请求上限时黑名单一刀切，把 `image`/`video` 也拦了。

**修复（2026-08-18 已落地）：** 从集合移除 `"image"` 和 `"video"`（保留 sticker/post/media/audio/file）→ 备份 → 语法检查 → 重启 gateway（kill PID 姿势，见 hermes-gateway-ops）→ 让用户重发验证。放行后图片落 `~/.hermes/cache/images/`，vision 可分析。

**教训：** 黑名单激进误伤致正常功能丢失 → 优先白名单/宁可放过。防 emoji 的闸只该拦 sticker，不该连 image/video 一起拦。

## 视觉模型识图不可单独作结论（2026-09-19 实测翻车）

对界面/页面截图做评审时，**单次 vision 结果不能当事实**，必须回源码或实际请求交叉验证：

- 实测：对某后台登录页截图让 vision 分析，它报“logo 是加载失败的裂图，旁边文字写小唐”——实际源码里 logo 元素正常存在（`<img src="/xiaolu_logo_v8.png">`），全页 **0 处“小唐”**。裂图是真的（图片路径 404），但“小唐”是**模型幻觉**，被当成事实写进了评审结论。
- 正确做法：① 截图前确认资源能加载（headless 截图里相对路径资源常 404，不代表线上也是）② 视觉结论（尤其是文字内容、品牌名、数字）必须回源码 grep 交叉验证 ③ 页面内文字以源码为准，画面以截图为准，不一致时以源码为事实
- 同源风险：模型会把占位/裂图/低清图标脑补成具体内容，把没有的元素说成有、把有说成没有——凡是要写进交付结论的细节，都要有第二个来源。

## 五、验证

- 逐张审核：用户每张都有明确结论，未确认的没往下推
- 素材判定：原片人物帧已删，无人物界面帧保留
- 修边：裁后发回用户确认，原文件有 .bak
- 入站修复：用户重发图片能收到（cache/images 出现新文件）
