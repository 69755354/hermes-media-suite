# 成片贴图位置与死帧排查（2026-08-24 火龙 v19 实测）

适用：复刻成片被用户报「中间卡了」「LOGO 放错地方」「乱贴东西」时。
**先对照原片核「放法」，别只查 ffprobe/字幕技术参数**——用户骂「你特么怎么质检的」的根因就是贴图/位置没对照原片。

## 一、Seedance 素材「静止死帧」识别（用户报「中间卡了」）

### 症状
成片某段「镜头走一半突然卡住不动」。分镜要求硬切 10.050s，素材却生成 11.104s，死帧裸进成片。

### 关键坑：别把动态误判成坏帧
- 纯颜色/PSSNR/帧差分在**动态镜头会全程差异 75-98%**（人物走动、镜头移动本就每帧大变）→ 一路标「闪烁」是**误报**，不能当坏帧。
- 唯一真异常信号：**前一帧段还高差异、突然掉到 <5% 且持续** = 死帧起点。

### 判别脚本（PIL 像素差，diff 采样 64x64 灰度哈希）
```python
import subprocess, os
def frame_raw(path, t):
    out = f"/tmp/pg_{int(t*10)}.pgm"
    subprocess.run(["ffmpeg","-y","-v","error","-i",path,"-ss",str(t),"-frames:v","1",
                    "-vf","scale=64:64,format=gray",out],check=True)
    data = open(out,'rb').read()
    return data[data.find(b'\n255\n')+5 : data.find(b'\n255\n')+5+64*64]

def diff(a,b):
    return sum(1 for i in range(len(a)) if a[i]!=b[i]) / len(a)

# 扫 8.0→11.1 每 0.2s：>25% 动态正常；<5% 且持续 = 死帧起点
for t0,t1 in [(round(8.0+i*0.2,1), round(8.0+(i+1)*0.2,1)) for i in range(16)]:
    d = diff(frame_raw(素材,t0), frame_raw(素材,t1))
    tag = "动态" if d>0.25 else ("微变" if d>0.05 else "静止!")
    print(f"{t0}→{t1}s: {d*100:.1f}% [{tag}]")
```

### 修法
- 该镜 `trim=end=<死帧起点>`（如 10.05）硬切，别 `trim=end=11.104` 把死帧带进。
- 后续镜音频 `adelay` 整体前移：镜2 `10869→10050`、镜3 `21973→21073`、镜4 `33077→32077`（前移镜1省下的 ~0.8s）。
- 只有镜1尾部有死帧、镜2/3/4 全程正常时，只修镜1，别动其他镜。
- **⚠️ 改镜长必须同步改 4 个地方**（火龙 v19 实测，漏一个就音画对不齐）：① 该镜 `trim=end`；② 后续每镜音频 `adelay` 减去缩短量（毫秒）；③ 总时长 `DUR`；④ **镜1 自己的音频若未 atrim 会带满原时长**——镜1 视频裁短但音频仍满，尾部留 1s+「只见其声不见画」空洞。镜1 台词若含跨镜句（第 9 句起声在 10.0s），裁到 10.05 保住了起声、主体已跨镜，正确。

## 二、贴图（LOGO/角标）位置跨版本漂移

### 症状
成片镜1 浮个位置不对的 LOGO。用户报「LOGO 放错地方」「老是犯同样的错误」。

### 根因（火龙 v12→v19 六版带错）
- 某版大改贴片时把 Logo overlay 连带挪位（v14：`x=500,y=190`→`x=430,y=880`），之后各版基于上一版**复制**没对照原片复核 → 错误连续继承。
- QC 只查 ffprobe（分辨率/时长/编码）+字幕+画面，**没对照原片核每个贴图区域** → 一直漏。

### 🚨 先判断「该删 vs 该挪到统一位」，别一律删（2026-08-24 火龙定案）

用户报 LOGO 放错位置时，**先看这个元素是不是「重复出现元素」**（LOGO/角标常在全片多镜出现）：

- **如果它是重复元素的错位实例**（如火龙 LOGO 在镜4 左下、镜1 也该有但被放到右下）→ **修法是挪回统一位置，不是删**。用户定案「放到左下角」——统一到全片 LOGO 的标准位置。
- **统一位置从同脚本其他实例反查**：找该元素其他正确的 overlay 坐标，照抄（火龙：镜4 LOGO 已在左下 `x=40,y=920`，镜1 这个也挪过去即全片统一）。
- **对照原片实证**：原片同帧该区干净（<15%）但成片该区高（>50%）只证明「成片多贴了」，**不决定删 or 挪**——"该不该有"看用户/原片，"放哪"照重复元素其他实例。
- 只有元素确实是原片没有的（画蛇添足）且用户确认才删。

### 判定（PIL 分区域彩色占比 vs 原片同帧）
```python
from PIL import Image
def region_color(path, x1,y1,x2,y2):
    img = Image.open(path).convert("RGB"); w,h = img.size
    crop = img.crop(tuple(int(v) for v in (x1*w/720, y1*h/1280, x2*w/720, y2*h/1280)))
    px = crop.load(); n = 0
    for x in range(crop.width):
        for y in range(crop.height):
            r,g,b = px[x,y]
            if max(r,g,b)-min(r,g,b) > 40: n += 1   # 彩色像素
    return n/(crop.width*crop.height)*100

# 原片某区 13% vs 成片同区 60% = 成片多贴了原片没有的东西
```
- 区域定义按 720×1280 基准：右下(430,880)-(580,1030)、右上(190,120)-(450,350)、左下(120,1050)-(400,1230)。
- **可信判据**：原片某区干净（<15%）vs 成片同区高（>50%），才判「成片多贴了东西」。原片人物/手机本身在动时该区占比也高，不能单看一帧。

### 修法（挪位 or 删，合成脚本 filter_complex 链式 overlay）
- 定位那行 `[oXX][app]overlay=x=?:y=?:enable='between(t,?,?)'[...]`。
- **挪位**：改坐标即可，`x=430:y=880` → `x=40:y=920`（照同元素其他实例统一位置）。
- **删**：链式 overlay 删节点必须同步改引用——`[o01][app]...>[o02]` 删后把 `[o01]` 直接接到下一个存在的节点（`[o01][play_g1]...>[o03]`），并改 split 分支（见下）。
- **split 分支清理**：删掉 `[app]` 时若源是 `[8:v]scale=150:150,format=rgba,split=2[app][app_small]`，改成不 split → `[8:v]scale=150:150,format=rgba[app_small]`，避免未消费分支。
- **验证**：grep 确认无孤儿（删时 `[app]`=0、`[o02]`=0；挪位时 `[app]`/`[o02]` 在、坐标对），再用脚本抽 filter_complex 检查 basev/vout 存在、o 链路连续（见下）。

### filter_complex 修改后验证脚本
```python
import re, sys
t = open('compose_xxx.sh',encoding='utf-8').read()
m = re.search(r'-filter_complex "(.*?)" \\', t, re.S)
fc = m.group(1)
all_tags = set(re.findall(r'\[([a-z0-9_]+)\]', fc))
o_tags = sorted([x for x in all_tags if x.startswith('o')], key=lambda s:int(s[1:]))
print("链上o标签:", o_tags)   # 应连续无跳（或跳的已被直连）
for must in ['basev','vout','o01','o14']:
    assert must in all_tags, f"缺 {must}"
# 确认被删的孤儿不存在（挪位场景则不必查 app/o02）
print("OK")
```
